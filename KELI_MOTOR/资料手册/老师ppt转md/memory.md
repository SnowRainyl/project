## 2. 引言 (Introduction)

### 2.1 嵌入式系统的典型架构
*   **流程：** 环境 -> 传感器 -> 信号调理 -> A/D 转换 -> **数字处理（计算、通信、存储）** -> D/A 转换 -> 信号调理 -> 执行器 -> 环境。
*   **存储 (Storage)：** 是数字处理核心的三大支柱之一。

### 2.2 什么是存储器？
*   **定义：** 一种能够保持信息一定时间的设备。
*   **种类：**
    *   生物类：大脑（非常高效）。
    *   纸质类：书籍（持久性长达数千年）。
    *   电子设备：电容器（模拟存储）、硬盘/磁带（磁存储）、CD/DVD/蓝光（光存储）、**固态电路（嵌入式系统主要使用）**。

### 2.3 数字存储器的基本组织
*   **数据单位：** 存储器由“字”(Words) 组成，字由“位”(Bits) 组成。
*   **编址：** 每个字由索引（地址/Address）标识。地址从 0 开始，最后一个地址 $A_{last} = N_{words} - 1$。
*   **关键参数：**
    *   **数量：** 字的数量总是 2 的幂（$N_{words} = 2^k$），地址位数 $k = \log_2(N_{words})$。
    *   **容量 (SIZE)：** 总位数 = $N_{words} \times n_{bits}$。
    *   **示例：**
        *   256 x 8 = 2048 bits (256 bytes)
        *   16K x 16 = 262,144 bits (32 Kbytes)

### 2.4 存储器结构 (Logical vs. Real Structure)
*   **逻辑结构：** 位单元阵列。一行代表一个字，一列代表位。使用地址译码器选择单行。
*   **实际结构：** 
    *   为了优化长宽比 (Aspect ratio) 并减小地址译码器体积，通常使用**正方形阵列**。
    *   **行译码器 (Row Decoder)：** 选择一行（包含多个字）。
    *   **列译码器 (Column Decoder)：** 从选中的行中通过多路复用器 (Multiplexer) 选择目标字。
*   **读取关键部件：** 感测放大器 (Sense Amplifier)。用于检测位线上的微小电压差异（几百毫伏），通过强正反馈实现快速判定。

### 2.5 存储器操作
*   **Read (读)：** 给定地址，返回存储的数据。
*   **Write (写)：** 给定地址和字，存入数据。
*   **Match (匹配)：** 给定字，搜索地址（特指内容寻址存储器 CAM）。
*   **Erase (擦除)：** 将存储器初始化为预定义内容（如全 1）。

### 2.6 存储器接口与组成
*   **接口：** 地址总线 ($k$ 根)、数据总线 ($n_{bits}$ 根)、控制总线 (Clock, Reset, CS, OE, WE, R/W)。
*   **芯片级联：**
    *   **增加字数：** 使用地址译码器驱动各芯片的片选信号 (CS)。
    *   **增加字宽：** 多个芯片共享相同的地址和片选，数据线并联形成更宽的地址总线。

---

## 3. 存储器参数 (Memory Parameters)
1.  **Size (容量)：** 对成本影响巨大。
2.  **Speed (速度)：** 
    *   **访问时间 (Access time)：** 地址稳定到输出数据稳定的时间。
    *   **写入时间 (Writing time)：** 数据存入所需时间。
    *   **吞吐量 (Throughput)：** 每秒最大操作次数。
3.  **Area (面积)：** 位单元的大小（$\mu m^2$）。存储器通常采用最先进的制造工艺（最小栅极长度）。
4.  **Cost (成本)：** 分为单位成本和 NRE (非经常性工程) 成本。
5.  **Write ability (写入能力)：** 
    *   高端：随机快速写入，无限次循环。
    *   中端：写入较慢，万次循环。
    *   低端：仅在制造时写入（如 Mask ROM）。
6.  **Storage permanence (存储持久性/挥发性)：** 
    *   高：掉电不丢失（非易失性）。
    *   低：掉电丢失或需定时刷新。

## 4. 只读存储器 (Read Only Memory - ROM)

### 4.1 掩膜可编程 ROM (Mask Programmable ROM)
*   **特性：** 在制造阶段写入，无法更改。写入能力最低（仅一次），持久性最高。
*   **成本：** NRE 成本高（需专用掩膜板），单位成本极低，适合大规模生产。
*   **结构：** 
    *   **NOR 结构：** 位线默认上拉至 $V_{dd}$。如果位单元中存在晶体管且被选中，则位线下拉至 0，反相后输出 1。
    *   **NAND 结构：** 晶体管串联。结构更致密、更便宜，但寄生电阻大，速度慢（延迟随晶体管数量呈二次方增长：$\tau \propto n_{tr}^2$）。

### 4.2 一次性可编程 ROM (OTP-ROM)
*   **原理：** 基于熔丝 (Fuses) 或反熔丝 (Anti-fuses)。
*   **操作：** 出厂时所有熔丝导通（全 1）。通过高电压烧断熔丝变为 0。
*   **性能：** 编程电压 $V_p \gg V_{dd}$。编程周期（$t_{PW} \approx 10 \mu s$）比读取周期（$t_{ACC} \approx 150 ns$）慢两个数量级。
*   **缺点：** 烧断后不可恢复；无法在封装后进行完整的功能测试（Yield 产量受晶圆缺陷影响）。

---

## 5. 可擦写可编程 ROM

### 5.1 EPROM (电可编程 ROM)
*   **核心：FAMOS 晶体管** (Floating gate Avalanche effect MOS)。
*   **原理：** 在栅极下增加一个完全绝缘的**浮栅 (Floating Gate)**。
*   **编程（热电子注入）：** 栅极加高压（+20V），漏极加高压（+25V）。高能电子穿越 $SiO_2$ 壁垒被困在浮栅中。浮栅带负电，使晶体管阈值电压 $V_{th}$ 升高（$V_{th} > V_{dd}$），导致晶体管在正常电压下始终截止（逻辑 0）。
*   **擦除：** 使用 **UV（紫外线）灯**照射。高能光子使电子跳出浮栅。
*   **局限：** 必须从电路中取出才能擦除；必须整片擦除；擦除过程需数分钟。

### 5.2 E2PROM (电可擦除可编程 ROM)
*   **核心：FLOTOX 晶体管** (Floating gate Tunneling Oxide)。
*   **原理：基于隧道效应 (Tunneling effect)**。漏极一侧的 $SiO_2$ 层极薄。
*   **编程/擦除：** 通过 Fowler-Nordheim 效应。电场使电子穿过薄氧化层。
*   **结构改进：** 为每个位单元增加一个**存取晶体管 (Access Transistor)**，以实现单个字的独立读写，避免编程时误擦除相邻单元。
*   **性能：** 读周期 $150 ns$，写周期 $5 ms$（写之前需先擦除）。
*   **优点：** 可在电路中操作，支持单比特访问。
*   **缺点：** 位单元比 EPROM 大，成本较高。

---

## 6. Flash 存储器 (Flash Memory)

### 6.1 NOR Flash
*   **背景：** 解决 E2PROM 成本高和写入慢的问题。
*   **特性：** 
    *   所有晶体管源极相连并接地（或接 $V_s$）。
    *   **写入（编程）：** 使用热电子注入（同 EPROM），速度快。
    *   **擦除：** 使用隧道效应。
*   **块擦除 (Block level erase)：** 存储器划分为块（几 KB 到几百 KB）。擦除以块为单位，而不是整片或单个字节。
*   **性能：** 读取同 ROM。写入 1K 字示例：E2PROM 约 5.12s，NOR Flash 仅需 5.24ms（得益于块擦除和快速编程）。
*   **CFI 接口：** 通用 Flash 存储器接口，基于命令集（如 AA @ 555, 55 @ 2AA, A0 @ 555 等序列）执行写入。

## 7. NAND Flash 存储器 (NAND Flash Memory)

### 7.1 结构与特性
*   **核心：** 基于 FLOTOX 晶体管，漏极（Drain）端氧化层较薄。
*   **拓扑结构：** NAND 拓扑（位单元串联），比 NOR 结构更致密、成本更低，但速度较慢（寄生电容和电阻更高）。
*   **控制信号：** 包含 BST（位线选择晶体管）和 SST（源极选择晶体管），用于激活整串存储单元。

### 7.2 关键电压定义
*   $V_{th}$：未编程晶体管的正常阈值电压。
*   $V_{thprog}$：已编程晶体管的阈值电压。
*   $V_{pass}$：使所有晶体管导通的栅极电压（无论其编程状态如何），$V_{pass} > V_{thprog}$。
*   $V_{read}$：仅使未编程晶体管导通的电压，$V_{th} < V_{read} < V_{thprog}$。
*   $V_{OFF}$：使所有晶体管截止的电压，$V_{OFF} < V_{th}$。

### 7.3 操作逻辑
*   **读操作（Page Read）：**
    1.  选中行设为 $V_{read}$，其余行设为 $V_{pass}$。
    2.  如果选中单元未编程（导通），位线下拉，输出逻辑 1。
    3.  如果选中单元已编程（截止），位线保持高电平，输出逻辑 0。
*   **编程/擦除：** 均通过隧道效应实现。擦除在块（Block）级别进行，通过给衬底（Substrate）加高压实现。
*   **缺点：** 访问速度慢，**不能直接执行代码**（需要先加载到 RAM），通常作为硬盘替代品，支持页（Page）读取。

## 8. 随机存取存储器 (Random Access Memory - RAM)

### 8.1 概述
*   **特点：** 写入速度快（$100ns$ vs Flash 的 $1ms$），支持字和位级别的读写，编程与擦除无区别（$0 \rightarrow 1$ 与 $1 \rightarrow 0$ 对称）。
*   **分类：** 静态 RAM (SRAM) 和 动态 RAM (DRAM)。

### 8.2 静态 RAM (SRAM)
*   **位单元：** 6 晶体管（6T）结构。由两个反相器组成的双稳态电路和两个存取晶体管（Pass Transistors）组成。
*   **读操作：**
    1.  预充两条位线（$BL$ 和 $\overline{BL}$）至 $V_{dd}$。
    2.  激活字线（WL），单元内部通过存取晶体管向位线放电。
    3.  感测放大器检测 $\Delta V$（正或负）来判定逻辑 0 或 1。
*   **晶体管尺寸约束：**
    *   **读稳定性：** 下拉晶体管 $M_1$ 必须大于存取晶体管 $M_3$，防止读取时电平翻转。
    *   **写能力：** 存取晶体管 $M_3$ 必须大于上拉晶体管 $P_1$，以强行改变锁存器状态。
*   **特性：** 速度极快（几纳秒），功耗较高，位单元面积大（6个晶体管），断电数据丢失。

### 8.3 动态 RAM (DRAM)
*   **位单元：** 1 晶体管 1 电容（1T1C）。利用电容器电荷存储信息。
*   **原理：**
    *   逻辑 1：电荷存在；逻辑 0：无电荷。
    *   **破坏性读取：** 读取过程会消耗电荷，因此读取后必须**自动重写（Rewrite）**。
*   **电荷分享计算：**
    *   $\Delta V = \frac{V_{dd}}{2} \cdot \frac{C_{bit}}{C_L + C_{bit}}$ （假设预充电压为 $V_{dd}/2$）。
*   **刷新（Refresh）：** 由于泄漏电流，信息只能保持几毫秒，必须定期刷新。常用方法：CBR（CAS before RAS）。
*   **特性：** 密度极高，成本低，但速度比 SRAM 慢一个数量级，需要复杂的控制器。

### 8.4 DRAM 变体
*   **Fast Page Mode (FPM)：** 保持行地址（RAS）活跃，仅改变列地址（CAS），加速同页数据的访问。
*   **EDO (Extended Data Out)：** 在输出端增加寄存器，实现类似流水线的效果，进一步提升性能。
*   **SDRAM (Synchronous DRAM)：** 所有操作与时钟边缘同步，支持指令化操作（如 ACTIVE, READ, PRECHARGE）。
*   **DDR (Double Data Rate)：** 在时钟的上升沿和下降沿均传输数据。

## 9. 存储控制器 (Memory Controllers)
*   **功能：** 将标准的内存请求转化为 DRAM 特有的命令序列（Row, Column, Bank 选择）。
*   **调度策略：**
    *   FCFS (先来先服务)。
    *   FR-FCFS (就绪优先)：优先处理已打开行的数据请求，以提高吞吐量。
*   **保障：** 确保满足所有时序约束（Timing Constraints）和定期刷新。

## 10. 内容寻址存储器 (Content Addressable Memories - CAM)

### 10.1 基本概念
*   **又称关联存储器（Associative Memories）：** 不是通过地址读数据，而是通过**给定数据找地址**（匹配操作）。
*   **结果：** 匹配成功（HIT）返回地址，匹配失败（MISS）。

### 10.2 关联 SRAM 结构
*   在普通 SRAM 基础上增加 3 个晶体管用于比较逻辑。
*   **匹配线（Match Line, ML）：** 预充至高电平。如果位单元内容与搜索数据不匹配，$ML$ 会被放电至地。
*   **并行性：** 所有的字同时进行比较，结果非常快（几十纳秒），但功耗极高（需要对大量 ML 进行预充/放电）。

#### Associative SRAM 图解

普通 SRAM 是：

```text
给地址 -> 读出该地址的数据
```

Associative SRAM / CAM 是反过来的：

```text
给 keyword -> 同时比较所有 word -> 返回匹配 word 的地址
```

图中的每一行是一个 word，每一行都有一根 Match Line：

```text
ML0 -> word 0 是否匹配
ML1 -> word 1 是否匹配
ML2 -> word 2 是否匹配
```

匹配过程：

```text
1. 所有 Match Line 先被预充到高电平
2. 输入 keyword 放到 BL / ~BL 上
3. 每一行的所有 bit 同时比较
4. 如果某一行所有 bit 都匹配，该行 ML 保持高电平
5. 如果某一行至少一个 bit 不匹配，该行 ML 被拉低
6. Priority Encoder 检查所有 ML
7. 至少一个 ML 为高 -> HIT，并输出匹配地址
8. 所有 ML 都为低 -> MISS
```

所以 CAM 的速度快，是因为它不是一行一行查，而是所有行并行比较。

代价是：

- 每个 bit cell 比普通 SRAM 更复杂
- Match Line 预充和放电功耗较高
- 面积和功耗都明显大于普通 SRAM

### 10.3 三态 CAM (Ternary CAM / TCAM)
*   **功能：** 支持“0”、“1”和“**Don't Care (X)**”匹配。
*   **位单元：** 每个位需要 2 个位单元（$D$ 和 $D'$）来存储状态。
*   **逻辑组合：**
    *   $DD' = 01$：内容为 0。
    *   $DD' = 10$：内容为 1。
    *   $DD' = 11$：内容为 Don't Care（永远匹配）。
    *   $DD' = 00$：未使用。
*   **应用：** 常用于网络路由表（子网掩码匹配）。

#### TCAM 图解

TCAM 比普通 CAM 多了第三种匹配状态：

```text
0
1
X = don't care
```

`X` 的意思是：这一位不管输入是 0 还是 1，都算匹配。

例如 TCAM 中存储：

```text
10110XXX
```

它可以匹配：

```text
10110000
10110001
10110111
10110任意三位
```

这就是图中绿色框为什么可以匹配较短前缀的原因。

TCAM 常用于网络路由表，因为路由匹配经常不是完整地址匹配，而是前缀匹配：

```text
192.168.1.X
10.0.X.X
```

在硬件中，TCAM 每个位通常用两个存储节点表示：

```text
D / D'
```

用两个 bit 编码三种状态：

```text
01 -> 存 0
10 -> 存 1
11 -> X / don't care
00 -> 通常不用
```

右侧晶体管图表达的是：如果输入 keyword 与存储 bit 不匹配，比较电路会把 Match Line 拉低；如果匹配，Match Line 保持高电平。对于 `X`，无论输入是什么，都不会拉低 Match Line。

## 11. 存储器核心理解

### 11.1 存储器在嵌入式系统中的位置

嵌入式系统里的存储器用于保存程序、数据、参数和运行时状态。CPU 不能只靠寄存器工作，绝大多数程序指令和变量都需要放在存储器中。

常见分类：

- Flash / ROM：非易失性，掉电后内容仍保留
- SRAM：易失性，掉电后内容丢失，但读写速度快
- EEPROM：非易失性，可按较小粒度擦写，常用于保存参数
- External Flash：外部非易失存储，可用于日志、参数、字库、文件等
- Cache：缓存，用于提高 CPU 访问存储器的速度

### 11.2 Word、Address 和 Size

数字存储器由很多个 word 组成，每个 word 由若干 bit 组成。CPU 通过 address 选择要访问哪个 word。

基本关系：

```text
N_words = 2^k
k = 地址线位数
Size = N_words x word_width
```

例子：

```text
256 x 8  = 256 个 8-bit word = 256 byte
16K x 16 = 16K 个 16-bit word = 32 Kbyte
```

在 MCU 中更常用 byte address，也就是每个地址对应 1 byte。

### 11.3 Read、Write 和 Erase

不同存储器支持的操作不同：

- Read：读出某个地址的内容
- Write：写入某个地址
- Erase：擦除一片区域，常见于 Flash
- Match：按内容查找地址，常见于 CAM

RAM 的写入通常可以直接把 0 改成 1，也可以把 1 改成 0。

Flash 不一样。Flash 写入和擦除是非对称的：

```text
擦除：通常把一整个 page/sector/block 变成全 1
编程：通常只能把某些 bit 从 1 写成 0
```

所以 Flash 写数据前经常需要先擦除。

### 11.4 ROM、EEPROM、Flash、SRAM 的区别

| 类型 | 掉电保存 | 写入速度 | 擦写粒度 | 典型用途 |
|---|---|---|---|---|
| Mask ROM | 是 | 制造时写入 | 不可改 | 大批量固定程序 |
| OTP-ROM | 是 | 只能写一次 | 不可擦 | 一次性配置 |
| EEPROM | 是 | 慢 | byte/word 级 | 参数保存 |
| NOR Flash | 是 | 慢于 RAM | sector/block 级 | 程序代码、参数 |
| NAND Flash | 是 | 适合大容量 | page/block 级 | 大容量数据存储 |
| SRAM | 否 | 快 | byte/word 级 | 运行时变量、栈、堆 |

### 11.5 NOR Flash 和 NAND Flash

NOR Flash 的特点：

- 支持随机读取
- 读取速度较快
- 可以用于 execute-in-place（XIP），即 CPU 直接从 Flash 取指执行
- 容量通常不如 NAND 大
- 常用于 MCU 程序存储器

NAND Flash 的特点：

- 容量大、成本低
- 适合连续页读写
- 通常不能直接执行代码，需要先加载到 RAM
- 常用于 SD 卡、U 盘、SSD、文件系统存储

### 11.6 Flash 的擦除与写入

Flash 和 RAM 最大的区别之一是：Flash 不能像普通变量一样随便覆盖写。

Flash 的基本规则通常是：

```text
Erase 擦除：把一整块区域变成全 1
Program 编程：只能把 bit 从 1 改成 0
```

也就是说，如果某个 bit 已经是 0，普通 program 操作不能直接把它改回 1。要把 0 改回 1，必须先擦除它所在的 sector/block。

例子：

```text
擦除后：1111 1111
写入 A：1010 1100   可以，1 -> 0
再写 B：1111 0000   不可以，因为有些 0 需要变回 1
```

正确做法是：

```text
先擦除 sector
↓
再重新 program 新数据
```

Flash 常见擦写粒度：

- Read：通常可以按 byte/word/page 读取
- Program：常按 byte 或 page 编程
- Erase：通常按 sector/block 擦除

所以 Flash 写参数时不能只考虑“写几个字节”，还要考虑这些字节所在的整个 sector。

典型 Flash 写入流程：

```text
1. 读出旧 sector 内容到 RAM 缓冲区
2. 在 RAM 缓冲区中修改目标参数
3. 发送 Write Enable
4. 擦除目标 sector
5. 等待 Flash busy 位清零
6. 分页 program 修改后的数据
7. 每页 program 后等待 busy 位清零
8. 读回校验
```

为什么需要 RAM 缓冲区？因为 sector erase 会把整个 sector 都擦掉。如果只想修改其中几个字节，必须先保留同一 sector 里的其他内容。

Flash 的几个重要限制：

- 写入速度远慢于 SRAM
- 擦除速度比写入更慢
- 擦写次数有限，例如几万到十万次量级
- 掉电中断写入可能导致数据损坏
- 写入前需要确认目标区域是否已经擦除

因此 Flash 更适合保存配置参数、校准值、日志等低频更新数据，不适合高频实时变量。

### 11.7 SRAM 和 DRAM

SRAM：

- 使用锁存结构保存 bit
- 不需要刷新
- 速度快
- 面积大、成本高
- 常用于 MCU 内部 RAM 和 cache

DRAM：

- 用电容保存 bit
- 需要周期性刷新
- 密度高、容量大
- 控制器复杂
- 常用于外部大容量内存

### 11.8 Cache 的意义

Cache 是 CPU 和较慢存储器之间的一层高速缓存。它保存最近访问过的数据或指令，提高平均访问速度。

但外设寄存器不能像普通内存一样随意 cache，因为外设寄存器可能被硬件自动修改。

例如：

```c
while (!(SPI2->SR & SPI_SR_TXE)) {
}
```

`SPI2->SR` 的状态位由 SPI 硬件更新。如果 CPU 一直读 cache 中的旧值，而不真正访问 SPI 外设，程序就可能卡住。

因此 memory-mapped 外设区域通常要设置为 non-cacheable，并且 C 语言访问外设寄存器时要保持 `volatile` 语义。

## 12. 和本项目相关的内容

本项目使用 STM32F407 与 FPGA 实现直流电机串级 PID 控制，和 memory 相关的重点如下。

### 12.1 STM32F407 内部 Flash 保存程序代码

STM32F407 内部 Flash 是非易失性存储器，用来保存编译后的固件程序。上电或复位后，CPU 从 Flash 中取指执行。

和课程内容对应：

```text
内部 Flash
-> 非易失
-> 可擦写
-> 适合保存程序
-> 读取速度比 RAM 慢，但 MCU 可直接从中执行代码
```

### 12.2 STM32F407 内部 SRAM 保存运行时数据

程序运行时的变量、栈、缓冲区、PID 状态量等通常位于 SRAM。

本项目中典型运行时数据包括：

- PID 控制变量
- 当前目标转速
- 编码器计数差值
- ADC 采样值
- 电流计算结果
- SPI 发送数据
- UART 打印缓冲区

SRAM 掉电后内容丢失，所以不能用来长期保存 PID 参数或历史记录。

### 12.3 W25Q64 SPI Flash 属于外部非易失存储

项目中设计了 W25Q64 SPI Flash，用于 PID 参数非易失性存储。

它和 STM32 内部 Flash 的区别：

- 位于芯片外部
- 通过 SPI1 通信
- 不能像普通 SRAM 那样直接用指针读写
- 需要发送 Flash 命令，例如读、写使能、页编程、扇区擦除等
- 写入前通常需要擦除 sector

典型操作顺序：

```text
读出目标 sector 原内容到 RAM
↓
在 RAM 中修改 PID 参数字段
↓
写使能
↓
扇区擦除
↓
等待 busy 位清零
↓
按 page 分批编程
↓
等待 busy 位清零
↓
读回验证
```

这和课程中的 Flash 特点对应：Flash 是非易失的，但写入慢，并且擦除粒度大于普通变量写入。

对 PID 参数保存来说，推荐把参数组织成一个小结构体，并加入 magic number、version 和 checksum，避免读到未初始化或写坏的数据。

示例结构：

```c
typedef struct {
    uint32_t magic;
    uint16_t version;
    float speed_kp;
    float speed_ki;
    float speed_kd;
    float current_kp;
    float current_ki;
    float current_kd;
    uint32_t checksum;
} pid_param_flash_t;
```

上电读取时：

```text
读取 W25Q64 参数区
↓
检查 magic/version/checksum
↓
有效：使用 Flash 中参数
无效：使用默认 PID 参数
```

写入时不要在 1 kHz 控制中断里直接擦写 Flash。Flash 擦除和写入太慢，应该放在低优先级任务或用户确认保存参数时执行。

### 12.4 SPI Flash 和 memory-mapped 外设不是一回事

需要区分两个概念：

```text
SPI1->DR
```

这是 STM32 内部 SPI1 外设的数据寄存器，属于 memory-mapped I/O。

```text
W25Q64 里的某个地址
```

这是外部 Flash 芯片内部的存储地址，需要通过 SPI 命令访问。

也就是说：

```text
CPU 不能直接 *(uint32_t *)0x00010000 访问 W25Q64
```

除非系统有专门的 memory-mapped external flash 控制器或 QSPI memory-mapped 模式。本项目使用普通 SPI，因此 W25Q64 是通过命令读写的外部设备。

### 12.5 FPGA 内部也可能使用存储结构

FPGA 中实现 PWM 发生器时，主要用的是寄存器和计数器：

- duty register：保存 STM32 发送来的占空比
- counter：PWM 计数器
- shift register：SPI 接收过程中的移位寄存器

这些都是硬件寄存器，不是大容量 memory，但本质上也属于保存状态的存储单元。

如果 FPGA 中使用 ROM/RAM IP，则可以用于查表、缓存或波形存储。但当前项目的 PWM 模块通常不需要复杂存储器。

### 12.6 ADC、UART、SPI、TIM 的寄存器不是普通 RAM

本项目大量使用外设寄存器：

```c
ADC1->DR
USART2->DR
SPI2->DR
TIM3->CNT
```

这些地址位于 memory address space，但它们不是 SRAM。读写它们会触发外设硬件行为。

例如：

- 读 `ADC1->DR`：得到 ADC 转换结果
- 写 `USART2->DR`：触发串口发送
- 写 `SPI2->DR`：触发 SPI 传输
- 读 `TIM3->CNT`：得到编码器计数器当前值

### 12.7 本项目为什么要注意非易失存储

PID 参数、校准参数、零电流基准值等如果希望断电后保留，就不能只放在 SRAM 中。

可选方案：

- 保存到 STM32 内部 Flash
- 保存到外部 W25Q64 SPI Flash
- 如果芯片有 EEPROM，也可以保存到 EEPROM

本项目选择或预留 W25Q64，更适合保存可修改参数，避免频繁擦写内部程序 Flash。

### 12.8 本项目中 Flash 擦写需要注意什么

如果本项目实际启用 W25Q64 保存 PID 参数，需要注意：

- 不能像 SRAM 变量一样原地覆盖写
- 修改参数前要考虑 sector erase 会清空整块区域
- 擦写期间不要阻塞 1 kHz PID 控制中断
- 写入前后应检查 W25Q64 的 busy 位
- 写入后最好读回校验
- 避免频繁保存参数，减少擦写次数消耗
- 可以使用双备份区，防止掉电时只写坏唯一一份参数

双备份区思路：

```text
参数区 A：上一份有效参数
参数区 B：新参数写入位置
↓
新参数写完并校验成功后，标记 B 有效
↓
下次更新再切回 A
```

这样即使写入过程中掉电，也更容易恢复到上一份有效参数。

### 12.9 CAM/TCAM 与本项目的关系

课程中 CAM/TCAM 的图很重要，但它和本项目的电机控制主链路关系不大。

CAM/TCAM 适合：

- 路由表查找
- Cache tag 匹配
- 快速模式匹配
- 硬件查表

本项目主要任务是：

```text
ADC 采样
↓
PID 计算
↓
SPI 发送占空比
↓
FPGA 输出 PWM
↓
TIM3 编码器反馈
```

这个链路不需要“按内容查地址”的并行搜索，所以不会直接用到 CAM/TCAM。

不过 CAM 的思想可以帮助理解 cache：cache 判断某个内存地址是否已经在缓存中时，需要比较 tag，这类“快速匹配”就和 associative memory 的思想有关。

### 12.10 本项目基本不涉及 DRAM、SDRAM、Cache、CAM

本项目的 STM32F407 裸机控制系统主要使用：

- 内部 Flash
- 内部 SRAM
- 外部 SPI Flash W25Q64
- 外设寄存器
- FPGA 寄存器/计数器

课程中的 DRAM、SDRAM、DDR、CAM/TCAM 更多用于复杂 SoC、操作系统、大容量存储或网络查表场景，不是本项目的核心。

Cache 在更高性能 MCU/MPU 中很重要，但本项目的重点仍是寄存器级外设配置、实时控制和 SPI/ADC/TIM/USART 数据流。

## 13. 一句话总结

存储器负责保存程序、数据和状态。STM32F407 项目中，内部 Flash 保存固件，内部 SRAM 保存运行时变量，外部 W25Q64 SPI Flash 可保存断电不丢失的 PID 参数；而 `SPI2->DR`、`ADC1->DR`、`TIM3->CNT` 等虽然位于内存地址空间，但它们是外设寄存器，不是普通 RAM。Flash 适合长期保存但写入慢且需要擦除，SRAM 适合快速运行但掉电丢失。
