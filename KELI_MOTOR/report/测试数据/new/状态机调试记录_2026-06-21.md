# 电机状态机调试记录 2026-06-21

## 目标

今天主要围绕 `MOTOR_TEST` 的电机状态机做测试，目标是确认三件事：

1. 保留状态机后，启动、运行、停止是否可控。
2. 串级 PID（速度环输出电流目标，电流环输出 duty）在低速和中速是否稳定。
3. `setpoint ramp` 是否真的能减少超调，还是会让启动阶段的问题更明显。

## 当前保留的代码逻辑

最终代码保留状态机和串级 PID，去掉可切换 ramp 的串口命令，固定为无 ramp：

- `set`：电位器换算出来的目标转速。
- `setR`：送入速度 PID 的目标转速。当前无 ramp，所以 START/RUN 时基本等于 `set`。
- `RPM`：编码器测速结果。
- `iset`：速度 PID 输出的电流目标，单位 mA。
- `curr`：电流采样换算后的实际电流，单位 mA。
- `duty`：电流 PID 输出到 PWM 的占空比计数。
- `adc`：电位器 ADC。
- `curr_raw`：电流检测通道 ADC 原始值。

主循环精简成三个小函数：

- `PollPidCommand()`：负责 200ms 串口轮询，处理 PID 参数命令。
- `PrintMotorStatus()`：负责串口打印状态、RPM、duty、电流等。
- `UpdateOled()`：负责 OLED 三行刷新。

OLED 已接入并继续使用，过时的 OLED 未连接注释已删除。

## 状态机做了什么

当前状态机仍是：

```text
IDLE -> START -> RUN -> STOP -> IDLE
```

- `IDLE`：电位器低于启动阈值，清零 set、setR、PID 积分和 duty。
- `START`：目标有效，但电机还没真正转起来。此阶段用较保守的启动电流上限，避免速度环因为 RPM=0 长时间积分过大。
- `RUN`：电机已达到启动完成转速后进入正常串级 PID。
- `STOP`：电位器回零后快速降 duty，最后回到 IDLE。

START 的作用不是追求稳态精度，而是帮助电机跨过静摩擦，同时限制启动阶段积累的能量。今天的多组数据也说明：很多超调不是 RUN 阶段单独造成的，而是 START 阶段为了把电机拉起来积累了电流和 duty，电机一旦挣脱静摩擦，就会冲出去。

## 今天尝试过的方案

### 1. 字段和打印整理

把原来的 `raw` 改成 `curr_raw`，避免和电位器 ADC 混淆：

- `adc` 是电位器通道，用来算目标转速。
- `curr_raw` 是电流检测通道原始 ADC。

同时解释并保留了 `set / setR / RPM / duty / iset / curr` 这些字段，方便后续串口数据分析。

### 2. 尝试去掉状态机

测试思路是让代码直接 RUN，用普通闭环处理所有情况。结论是不推荐：

- 低速启动时 RPM 长时间为 0，速度环会持续加大 `iset`。
- 电机一旦克服静摩擦，容易突然冲高。
- STOP 阶段也容易出现 set 已经为 0，但内部目标或输出还没完全退干净的误导状态。

所以最后回到状态机。

### 3. 调整启动和停止阈值

中间试过把启动/停止阈值改低，例如 `20 / 10`，这样旋钮稍微一动就能进 RUN/START，响应更“跟手”。

但阈值只决定什么时候进入状态机，不解决启动超调本身。最终更重要的问题还是 START 阶段的电流、积分和 handoff。

### 4. 尝试低速专门处理

曾尝试 10~30 RPM 低速区间使用 duty 前馈或小 PI 修正，让低速更容易稳定。

测试后发现：

- 固定 duty 起步能改善低速卡住，但容易出现“冲高再回落”。
- duty 给小了起不来，给大了又过冲。
- 前馈表需要大量标定，且负载变化后仍然需要 PID 修正。

由于用户明确希望速度和电流都保留 PID，最后没有保留低速开环/前馈方案。

### 5. 尝试 ramp on/off

曾加入串口命令切换 ramp：

- ramp on：上升方向 setR 慢慢追 set，下降方向直接跟随。
- ramp off：setR 直接等于 set。

测试文件：

- `ramp_0-100-0.MD`
- `无ramp.MD`
- `ramp_ON_OR_OFF.MD`
- `onoroff.MD`

结论：

- ramp 的理论作用是避免目标转速突然跳变，减少大阶跃命令造成的速度环冲击。
- 但本电机的主要问题在 START 阶段：静摩擦 + 启动电流积累。
- ramp 会让 setR 慢慢爬升，但如果电机仍然不动，START 阶段仍会积累 `iset/duty`。
- 电机一旦转起来，积累的能量释放，仍然会超调，有时 ramp 反而把 START 时间拉长。

因此最后删除了 ramp 串口命令，固定无 ramp，先把状态机和 PID 调稳。

## 关键测试现象

### ramp UP 仍有明显超调

在 `onoroff.MD` 中，ramp UP 接近 49 RPM 时仍出现明显超调：

```text
set≈49.1 setR≈49.2 ramp=UP RPM=62.2 duty=1598 iset=43.8mA
```

这说明 ramp 没有根治中速启动超调。

### 删除 ramp 命令后的无 ramp 测试

在 `删除ramp命令测试.MD` 中，固定 50 RPM 左右时，稳定段表现较好：

```text
set≈50.5 setR≈50.5 RPM≈49.1~51.6 duty≈1331~1383 iset≈43~45mA
```

这个结果说明：对稳态精度来说，无 ramp 并不是问题；只要 PID 进入稳定运行，误差可以比较小。

### RPM 精度大约是 0.5 RPM

编码器测速本身有量化：

```text
11 PPR * 4倍频 * 34减速比 = 1496 counts/rev
```

速度计算窗口约 10ms，单个计数对应约 4 RPM；再经过 8 点滑动平均后，显示出来的分辨率大约是 0.5 RPM。因此串口里 RPM 以 0.5 左右跳动是正常现象，不代表 PID 一定抖动。

## 最终结论

今天测试后，最合适的结论是：

1. 状态机需要保留，因为它负责 IDLE/START/RUN/STOP 的边界处理。
2. 串级 PID 需要保留，因为速度和电流都要闭环。
3. 当前先不追求旋钮变化时完全平滑，优先保证最终能到目标速度并稳定。
4. `setpoint ramp` 暂时不保留，因为实测对主要超调问题帮助有限，还增加调试复杂度。
5. 后续如果继续优化，应优先调 START 阶段参数，而不是继续加 ramp：
   - `SPEED_START_ISET_MAX`
   - `SPEED_START_INTEGRAL_MAX`
   - `SPEED_HANDOFF_KEEP`
   - `CURRENT_HANDOFF_KEEP`
   - `DUTY_HANDOFF_KEEP`
