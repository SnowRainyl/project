# 本项目互连接口知识点梳理

> 一句话定位：本项目的互连接口负责把 STM32、FPGA、OLED、PC 调试串口、电机反馈信号连接起来。重点不是泛泛背协议，而是弄清楚每条线传什么、怎么同步、用什么编码方式、为什么这样设计。

## 本项目实际用到的接口

| 接口/信号 | 连接对象 | 作用 | 同步方式 | 编码/信号方式 |
|---|---|---|---|---|
| UART2 | STM32 ↔ CH340G ↔ PC | 串口调试、打印 PID/ADC/RPM 信息 | 无时钟线，靠 start bit 每帧重新同步 | NRZ + start bit / stop bit |
| SPI2 | STM32 → FPGA | STM32 把 12-bit PWM 占空比发给 FPGA | STM32 提供 SCK 时钟线 | NRZ，靠 SCK 边沿采样 |
| I2C1 | STM32 ↔ OLED | 向 SSD1306 OLED 写显示数据 | STM32 提供 SCL 时钟线 | NRZ + 开漏输出 |
| 编码器 A/B 相 | 电机编码器 → STM32 TIM3 | 测量电机转速和方向 | TIM3 捕获 A/B 相边沿 | 正交编码，不是通信线路编码 |
| PWM | FPGA → TB6612 | 控制电机驱动器占空比 | 固定 PWM 周期 | 脉冲宽度表示占空比，不是通信线路编码 |

## 本项目关键引脚

| 功能 | STM32 引脚 | 对端 | 说明 |
|---|---|---|---|
| UART2_TX | PA2 | CH340G RXD | STM32 向电脑发送调试信息 |
| UART2_RX | PA3 | CH340G TXD | 电脑向 STM32 发送调试命令 |
| I2C1_SCL | PB6 | OLED SCL | I2C 时钟线，开漏 + 上拉 |
| I2C1_SDA | PB7 | OLED SDA | I2C 数据线，开漏 + 上拉 |
| SPI2_CS | PB12 | FPGA cs_n | 软件片选，低有效 |
| SPI2_SCK | PB13 | FPGA sck | SPI 时钟 |
| SPI2_MISO | PB14 | FPGA miso | 本项目不需要 FPGA 回传，可不接 |
| SPI2_MOSI | PB15 | FPGA mosi | STM32 发送 12-bit duty |
| TIM3_CH1 | PC6 | 编码器 A 相 | 转速/方向反馈 |
| TIM3_CH2 | PC7 | 编码器 B 相 | 转速/方向反馈 |
| PWM 输出 | FPGA F16 / J3-31 | TB6612 PWMA | FPGA 输出约 12.2 kHz PWM |

## 为什么这样选择接口

本项目不是随便选 UART、SPI、I2C，而是根据每个外设的需求来选：

| 设备/功能 | 选择的接口 | 选择原因 |
|---|---|---|
| PC 调试 | UART2 + CH340G | 调试信息是低速文本数据，UART 简单、通用，电脑端可以直接用串口助手查看 |
| STM32 → FPGA | SPI2 | PWM duty 需要稳定、较快地写入 FPGA；SPI 有独立时钟线、速度高、时序清楚，适合点对点传输 |
| OLED 显示 | I2C1 | OLED 数据量不大，刷新速度要求不高；I2C 只需要 SCL/SDA 两根线，节省 STM32 引脚 |
| 电机转速反馈 | TIM3 编码器模式 | 编码器输出 A/B 两相脉冲，不是字节通信；直接用定时器硬件计数最可靠 |
| 电机功率控制 | FPGA PWM | TB6612 需要 PWM 占空比控制平均电压；FPGA 用硬件逻辑产生稳定 PWM，减轻 STM32 实时负担 |

简单说：

- **UART 给人看**：适合电脑调试和文本输出。
- **SPI 给 FPGA**：适合高速、明确、点对点的数据写入。
- **I2C 给 OLED**：适合低速、多设备、少引脚的外设。
- **TIM3 给编码器**：适合硬件计数 A/B 相边沿。
- **PWM 给电机驱动**：适合用占空比控制电机平均电压。

## 核心概念

### 1. UART、SPI、I2C 的数据位本质上都是 NRZ

NRZ 的意思是：每个 bit 用当前电平表示。

```text
1 → 高电平
0 → 低电平
```

NRZ 不是“用跳变表示数据”。如果连续发送很多个 `1`，线上就是一段长高电平；如果连续发送很多个 `0`，线上就是一段长低电平。接收端知道当前电平是 0/1，但如果没有额外同步信息，就很难判断这一段里到底有几个 bit。

本项目里三个协议用不同方式解决同步问题：

- **UART**：没有时钟线，用 start bit 的下降沿让接收端在每一帧开始时重新对齐。
- **SPI**：有 SCK 时钟线，FPGA 按 SCK 边沿采样 MOSI。
- **I2C**：有 SCL 时钟线，OLED 按 SCL 的有效时刻读取 SDA。

### 2. SPI 为什么适合 STM32 到 FPGA

SPI 是同步串行接口，STM32 是 Master，FPGA 是 Slave。本项目只需要 STM32 把占空比写给 FPGA，不需要 FPGA 回传数据。

- `MOSI`：STM32 发 12-bit duty 数据。
- `SCK`：STM32 提供采样节拍。
- `CS_N`：拉低表示一帧开始，拉高表示一帧结束。
- `MISO`：本项目可不接，因为 FPGA 不需要回传。

SPI 不需要地址，也不需要仲裁。Master 通过片选线 `CS_N` 直接选择目标设备，所以结构简单、速度高，适合 STM32 到 FPGA 这种点对点控制链路。

### 3. I2C 的开漏和“线与”

I2C 的 SDA/SCL 是开漏（Open-Drain）输出：

```text
输出 0：设备主动把线拉到 GND
输出 1：设备不主动推高，只是释放总线
```

总线上有上拉电阻。所有设备都释放时，上拉电阻把线拉成 `1`；只要有任何一个设备拉低，总线就是 `0`。

```text
任何设备拉低 → 总线 = 0
所有设备释放 → 总线 = 1
```

这样做是为了让多个设备共用同一根线时不会互相硬顶。普通推挽输出如果一个设备强推高、另一个设备强拉低，可能等于把 VCC 和 GND 短接；开漏只能拉低或释放，所以不会出现这种冲突。

I2C 开漏主要用于：

- 多个从设备共享 SDA/SCL。
- 从设备在 ACK 位拉低 SDA 表示应答。
- 从设备通过拉低 SCL 做 clock stretching，让主机等待。
- 多主机同时发送时进行仲裁。

多主机仲裁是逐 bit 仲裁：两个主机可以同时开始发送；只要前面的 bit 一样，就暂时没冲突；一旦某一位不同，发 `0` 的赢，发 `1` 的输。

```text
A 想发: 1 0 1 1
B 想发: 1 0 1 0
总线:   1 0 1 0
```

第 4 位时，A 想发 `1`，所以释放总线；B 想发 `0`，所以拉低总线。总线实际为 `0`。A 读回 SDA 后发现“我想发 1，但总线是 0”，就知道自己输了仲裁，停止发送并释放总线。

记法：**谁想发 1 却读到 0，谁就输；发 0 的继续。**

开漏的代价是上升沿慢，因为高电平靠上拉电阻充电，不是芯片主动推高。所以 I2C 适合低速、多设备共享总线，不适合像 SPI 那样的高速点对点传输。

### 4. 编码器 A/B 相不是普通通信协议

电机编码器输出 A/B 两相信号，STM32 的 TIM3 编码器模式读取两路边沿。A/B 相的相位关系用于判断方向，边沿数量用于计算速度。

这属于正交编码，不是 UART/SPI/I2C 这种通信线路编码。它不传输“字节”或“帧”，而是把机械转动转换成两路相位错开的数字脉冲。

### 5. PWM 不是通信线路编码

FPGA 输出给 TB6612 的 PWM 信号不是在传 bit 流，而是在固定周期内改变高电平持续时间：

```text
占空比越大 → 高电平时间越长 → 电机平均电压越大
占空比越小 → 高电平时间越短 → 电机平均电压越小
```

所以 PWM 是控制信号，不是数据通信编码。

## 必要补充原理

### 时钟与同步

接收端要正确读数据，必须知道“什么时候采样”。本项目里有两类同步方式：

| 类型 | 项目例子 | 方法 |
|---|---|---|
| 异步 | UART | 双方约定波特率，用 start bit 每帧重新同步 |
| 同步 | SPI、I2C | 发送方提供时钟线，接收方按时钟采样 |

SPI 和 I2C 有时钟线，所以连续多个 0/1 不会让接收端数不清 bit；UART 没有时钟线，所以每帧不能太长，并且需要 start bit/stop bit。

### 线路编码

本项目重点只需要理解 NRZ。Manchester、nB/yB、bit stuffing 可以作为对比，不是本项目实际使用的方案。

| 编码方式 | 核心思想 | 本项目是否使用 |
|---|---|---|
| NRZ | 高/低电平直接表示 1/0 | UART、SPI、I2C 都用这个基本思想 |
| Manchester | 每个 bit 中间强制跳变，跳变也表示数据 | 未使用 |
| nB/yB | 把 n 位数据查表换成 y 位码字，避免太长连续 0/1 | 未使用 |
| Bit Stuffing | 连续 n 个相同 bit 后插入一个相反 bit | 未使用，CAN 常用 |

NRZ 例子：

```text
数据:  1   0   1   1   0   0   0
电平:  高  低  高  高  低  低  低
跳变:  ↑   ↓   ↑   -   ↓   -   -
```

第 4 位还是数据 `1`，只是因为第 3 位也是 `1`，所以电平保持高，不发生跳变。

### UART 要点

UART 没有时钟线，靠帧结构同步：

```text
空闲高 → start bit 低 → 数据位 → stop bit 高
```

本项目使用 USART2，PA2/PA3，通过 CH340G 接电脑，配置为 `115200 8N1`。

### SPI 要点

SPI 由 Master 提供时钟和片选：

```text
CS_N 拉低 → 开始一帧
SCK 跳变 → FPGA 采样 MOSI
CS_N 拉高 → 一帧结束
```

本项目 SPI2 使用 Mode 0：SCK 空闲低，数据在上升沿采样。发送内容是 12-bit PWM duty，FPGA 收到后更新 PWM 占空比。

### I2C 要点

I2C 只有两根线：

```text
SCL：时钟线
SDA：数据线
```

基本帧结构：

```text
START → 7位地址 + R/W → ACK → 数据 → ACK → STOP
```

本项目 I2C1 使用 PB6/PB7 驱动 SSD1306 OLED，常见地址为 `0x3C`。I2C 适合多个低速设备共享总线，但因为开漏上升沿慢，不适合替代 SPI 做高速传输。
