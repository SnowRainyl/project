# 模块 3：转速测量 — 编码器

> 对应代码：`MOTOR_TEST/MDK-ARM/Src/encoder_reg.c`
> 硬件：JGA25-370 内置光电编码器，TIM3 编码器模式，PC6（A相）/ PC7（B相）

---

## 3.1 为什么需要测 RPM

**一句话：PID 想控制转速，必须先知道电机现在到底转多快。**

控制循环每 1ms 执行一次。它一直重复同一件事：

```
目标 RPM = 50
实际 RPM = 43
误差 = 50 - 43 = 7

PID 看到误差为正：电机慢了
        ↓
把 duty 调大一点
        ↓
PWM 占空比变大，电机加速
        ↓
1ms 后再测一次 RPM
```

所以编码器的作用就是：

```
把“电机转了多少”变成数字
```

这个数字最后会变成 RPM，PID 才能比较：

```
目标 RPM - 实际 RPM = 误差
```

公式里的 `1496` 是关键：

```
输出轴转 1 圈 = 1496 个计数
```

有了这个等式，计数就能换成圈数，圈数再换成 RPM。

问题变成：1496 怎么来的？

---

## 3.2 内部轴和外部轴

JGA25-370 不是单纯一个电机，而是：

```
小电机 + 齿轮箱
```

结构可以这样看：

```
[小电机] ── [齿轮组] ── [输出轴]
 转很快         减速        转慢但有力
```

- **内部轴**：小电机自己的轴，转得很快
- **输出轴**：齿轮箱出来的轴，接负载，转得慢但力气大

编码器装在**内部轴**上，不在输出轴上。

原因很简单：

```
内部轴转得快 -> 脉冲更多 -> 低速时也能测得细
```

但我们真正关心的是**输出轴 RPM**，因为输出轴才是接负载、真正做功的轴。

所以软件要做一次换算：

```
内部轴编码器计数 -> 输出轴转速
```

---

## 3.3 两个参数：PPR 和减速比

换算需要两个数，都来自电机手册。

**PPR = 每转脉冲数**

本项目：

```
内部轴转 1 圈 -> 编码器产生 11 个脉冲
```

所以：

```
PPR = 11
```

你可以把它理解成编码器码盘上的“刻度数量”。

**减速比 = 34**

意思是：

```
内部轴转 34 圈 -> 输出轴转 1 圈
```

齿轮箱做的事就是：

```
牺牲速度，换更大的扭矩
```

手册里的验证关系：

```
11 × 34 = 374
```

也就是输出轴转 1 圈时，内部轴编码器会产生 374 个原始脉冲。

---

## 3.4 计算输出轴一圈的计数

目标：**输出轴转 1 圈，TIM3 的 CNT 变化多少？**

```
输出轴转 1 圈
  → 内部轴转 34 圈          （减速比）
  → 产生 11 × 34 = 374 个脉冲  （PPR）
  → TIM3 模式 3 双边沿计数 ×4
  → 374 × 4 = 1496 个计数
```

**为什么要 ×4：**

编码器有 A、B 两路信号。一个完整脉冲周期里，硬件可以数 4 个边沿：

```
A 上升沿
B 上升沿
A 下降沿
B 下降沿
```

TIM3 编码器模式 3 会把这些边沿都拿来计数，所以是 `x4`。

最终：

```
输出轴 1 圈 = 11 × 34 × 4 = 1496 个 CNT 计数
```

```c
#define ENCODER_COUNTS_PER_REV  (11 × 4 × 34)  // = 1496
```

---

## 3.5 RPM 计算公式

有了 1496，就能从计数算 RPM：

```
delta ÷ 1496     → 这 1ms 内输出轴转了多少圈
× 60000          → 1分钟 = 60000ms，换算到每分钟
= RPM
```

对应代码（[encoder_reg.c:225](../../MOTOR_TEST/MDK-ARM/Src/encoder_reg.c#L225)）：

```c
raw_rpm = (float)g_encoder_delta * 60000.0f / (float)ENCODER_COUNTS_PER_REV;
```

其中：

```
g_encoder_delta = 这 1ms 内 CNT 变化了多少
1496            = 输出轴 1 圈对应多少计数
60000           = 1 分钟有 60000 ms
```

例子：

```
1ms 内 delta = 3
RPM = 3 × 60000 / 1496 ≈ 120 RPM
```

**溢出回绕的处理：**

```c
g_encoder_delta = (int16_t)(current_cnt - s_last_cnt);
```

CNT 是 16 位，只能数到 `65535`，再往后会回到 `0`。

所以代码不是直接看 `current_cnt`，而是看：

```
这次 CNT - 上次 CNT = 这 1ms 走了多少计数
```

强转成 `int16_t` 后，可以同时表示正转和反转：

```
正转越界：last=0xFFF0, now=0x0010 → (int16_t)(0x0020) = +32 ✓
反转越界：last=0x0010, now=0xFFF0 → (int16_t)(0xFFE0) = -32 ✓
```

前提是：

```
限制的是两次读取之间的真实变化量，不是 CNT 的绝对数值。
```

也就是说：

```
now/last 跨不跨 65535 -> 0 的回绕点不重要
重要的是这 1ms 内真实走过多少计数
```

因为 `int16_t` 只能安全表示：

```
-32768 ~ +32767
```

所以只要 1ms 内真实变化量小于 `32768` 个计数，方向和大小就不会被误解。

本项目：

```
输出轴 1 圈 = 1496 counts
32768 / 1496 ≈ 21.9 圈
```

也就是说，除非输出轴在 1ms 内转 21 圈以上，否则这个差值算法都安全。实际电机远远达不到这个速度，所以这样写够用。

**面试怎么说：**
> "编码器装在内部轴，PPR=11，减速比=34，x4 解码后输出轴每转 1496 个计数。每 1ms 读一次 CNT，delta 除以 1496 得圈数，再乘 60000 换算到 RPM。CNT 回绕用 int16_t 差值自动处理。"

## 3.6 TIM3 编码器模式配置

**一句话：TIM3 编码器模式让硬件自己看 A/B 相，然后自动改 CNT。**

普通思路是：

```
A/B 来一个边沿 -> 进中断 -> CPU 判断方向 -> CPU 加减计数
```

但这样 CPU 太忙。

TIM3 编码器模式做的是：

```
A/B 相输入
   ↓
TIM3 硬件判断方向
   ↓
CNT 自动 +1 或 -1
```

CPU 只需要每 1ms 读一次 `TIM3->CNT`。

三个关键寄存器：

**SMCR — 选解码模式**
```c
TIM3->SMCR = (3UL << 0U);  // SMS=011：模式 3，TI1+TI2 双边沿，x4 倍频
```

作用：

```
告诉 TIM3：你现在不是普通定时器，你要进入编码器模式
```

`SMS=011` 表示模式 3：

```
A 相和 B 相都参与计数
上升沿和下降沿都参与计数
所以是 x4
```

**CCMR1 — 配置输入捕获**
```c
TIM3->CCMR1 = (1UL << 0U)    // CC1S=01：CH1 作输入（PC6 = A相）
            | (1UL << 4U)    // IC1F=0001：2点数字滤波去毛刺
            | (1UL << 8U)    // CC2S=01：CH2 作输入（PC7 = B相）
            | (1UL << 12U);  // IC2F=0001：同上
```

作用：

```
告诉 TIM3：
CH1 是输入，接 A 相
CH2 是输入，接 B 相
顺便加一点数字滤波，过滤很窄的毛刺
```

**CCER — 极性控制**
```c
TIM3->CCER = 0U;  // 正向，若转向相反把 CC1P 或 CC2P 置 1 即可翻转
```

作用：

```
决定 A/B 相边沿是否反向
```

如果发现转向符号反了，可以：

```
改 CCER 里的极性位
```

不用立刻改硬件接线。

**为什么选 TIM3：**

```
TIM6 是基本定时器，没有编码器模式
TIM6 也已经用于 1kHz 控制循环
PC6/PC7 的复用功能正好是 TIM3_CH1/CH2（AF2）
```

所以这个项目选 TIM3。

## 3.7 项目坑：编码器不供电

**现象：** 编码器全接好，电机在转，RPM 始终是 0。

**原因：** 编码器不是一根“被动信号线”，它里面有光电传感器，需要单独供电。

12V 只让电机线圈转，不会给编码器电路供电。

| 供电 | 目的 |
|------|------|
| 12V → TB6612 → 电机 | 电机转动 |
| 5V → 编码器蓝线（VCC） | 光电传感器工作 |

没有 5V 时：

```
A/B 没有脉冲
   ↓
TIM3->CNT 不动
   ↓
delta = 0
   ↓
RPM = 0
```

后果：

```
PID 一直以为电机没转
误差一直很大
积分项持续累积
duty 可能被拉满
```

**排查：** 先查编码器 VCC（蓝线）是否接 5V。

## 3.8 和老师 PPT 的对应关系

这一节可以直接放到报告里，用来把编码器代码和 peripheral、memory 里的知识连起来。

### Timer 和 Counter 的区别

老师 peripheral 里区分了 Timer 和 Counter：

| 名称 | 数什么 | 例子 |
|------|--------|------|
| Timer | 数内部时钟 tick | TIM6 每 1ms 触发控制循环 |
| Counter | 数外部事件边沿 | TIM3 数编码器 A/B 相边沿 |

所以 TIM3 在这里虽然名字叫 Timer，但实际用途更像 Counter：

```
PC6/PC7 出现边沿
    ↓
TIM3 硬件判断方向
    ↓
TIM3->CNT 自动 +1 或 -1
```

CPU 不需要每个边沿都进中断，只需要 1ms 读一次 `TIM3->CNT`。

### 编码器模式 = 硬件状态机

普通 GPIO 读 A/B 相，需要软件自己判断：

```
A/B 当前状态
    ↓
和上次状态比较
    ↓
判断正转/反转
    ↓
软件加减计数
```

TIM3 编码器模式把这件事放进硬件：

```
A/B 相输入 → TIM3 编码器接口 → DIR/CNT 自动更新
```

这对应老师课里“外设负责特定硬件功能”的思想：CPU 不必亲自处理每个脉冲，外设硬件持续工作，CPU 只读结果。

### TIM3->CNT 是 memory-mapped 外设寄存器

老师 peripheral/memory 里说，STM32 外设寄存器是 memory-mapped I/O。代码里的：

```c
TIM3->CNT
TIM3->SMCR
TIM3->CCMR1
TIM3->CCER
```

不是普通 RAM 变量，而是 TIM3 硬件寄存器。

区别是：

| 普通变量 | `TIM3->CNT` |
|----------|-------------|
| 只有 CPU 写它才会变 | 编码器边沿来了，硬件自己会改 |
| 存在 SRAM | 位于外设地址空间 |
| 读写没有额外硬件动作 | 读写会影响/读取定时器硬件状态 |

所以 `current_cnt = TIM3->CNT` 的意思是：

```
读取 TIM3 硬件当前累计到的编码器计数
```

不是读取一个软件数组或缓存。

### 复用功能和 RCC 对应关系

编码器输入不是普通 GPIO 输入，而是 TIM3 的 CH1/CH2 复用功能：

| 引脚 | 功能 |
|------|------|
| PC6 | TIM3_CH1，编码器 A 相 |
| PC7 | TIM3_CH2，编码器 B 相 |

因此需要两类配置：

```
GPIOC 时钟打开
PC6/PC7 配置成 AF2
TIM3 时钟打开
TIM3 配置成编码器模式
```

这对应老师 peripheral 里讲的规律：

```
外设挂在哪条总线上，就打开对应 RCC 时钟
引脚要给外设用，就配置 GPIO MODER + AFR
```

如果只开 TIM3 时钟但没配 AF2，A/B 相进不了 TIM3；如果只配 AF2 但没开 TIM3 时钟，TIM3 内部逻辑不工作。

### 为什么不用 GPIO 中断数脉冲

从第一性原理看，编码器的每个边沿都是一个外部事件。如果用 GPIO EXTI 中断：

```
每个边沿 → 进一次中断 → 软件判断方向 → 软件计数
```

问题是转速一高，中断频率会很大，CPU 会被脉冲打断很多次。

TIM3 编码器模式更适合：

```
边沿很多 → TIM3 硬件自己数
CPU 固定 1ms 读一次
```

这样控制循环的时间更稳定，不会因为编码器脉冲变多而让 CPU 忙乱。

**面试怎么说：**
> "从课程角度看，TIM6 是 timer，用内部时钟产生 1ms 节拍；TIM3 在编码器模式下更像 counter，用来数外部 A/B 相边沿。PC6/PC7 配成 AF2 后进入 TIM3_CH1/CH2，TIM3 硬件状态机自动判断方向并更新 CNT。TIM3->CNT 是 memory-mapped 外设寄存器，不是普通变量，编码器边沿来了硬件自己会改。这样比 GPIO 中断数脉冲稳定，因为 CPU 不需要处理每一个边沿，只要每 1ms 读一次差值。"
