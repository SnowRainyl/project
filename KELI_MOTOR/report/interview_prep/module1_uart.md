# 模块 1：UART 串口调试

> 对应代码：`MOTOR_TEST/MDK-ARM/Src/uart.c`
> 硬件：USART2，PA2(TX) / PA3(RX)，CH340G USB-TTL 模块，115200 8N1

---

## 1.1 UART 在项目里的角色

**一句话：UART 是你和 STM32 之间的"对话窗口"。**

STM32 运行时内部发生的一切你看不到——ADC 读到多少、PID 输出多少、电机转速对不对，没有 UART 这些数据全部在芯片里。

有了 UART，STM32 可以实时把数据发到电脑，串口助手里显示：
```
RPM: 87  Target: 100  Duty: 2340  Current: 28mA
```

| 用途 | 说明 |
|------|------|
| 打印调试信息 | 看 ADC 值、RPM、PID 输出是否正常 |
| 排查 bug | 哪一步数据不对，说明哪一步有问题 |
| 观察 PID 调参过程 | kp 调大之后转速响应怎么变 |

OLED 能显示但信息量少、更新慢；UART 可以高速连续打印，适合调试阶段。

**面试怎么说：**
> "UART 我主要用来做串口调试，实时打印 RPM、电流、PID 输出，调参的时候能直观看到系统响应。"

## 1.2 时钟使能

**一句话：STM32 的外设默认不通电，用之前必须先开时钟。**

STM32 为了省电，所有外设上电后时钟默认是关的。没有时钟，寄存器写了也没用，外设不工作。

```c
RCC->AHB1ENR |= (1 << 0);    // GPIOA 时钟
RCC->APB1ENR |= (1 << 17);   // USART2 时钟
```

为什么要开两个——UART 涉及两个独立的硬件：

| 硬件 | 挂在哪条总线 | 开哪个寄存器 |
|------|------------|------------|
| GPIOA（引脚） | AHB1 | `AHB1ENR` bit0 |
| USART2（串口控制器） | APB1 | `APB1ENR` bit17 |

STM32 内部总线分工：
```
AHB1  → GPIO、DMA（高速，直连CPU）
APB1  → USART2/3、SPI2、I2C（低速，经过分频）
APB2  → USART1、SPI1、ADC（中速）
```

USART2 挂在 APB1，所以它的时钟频率是 APB1 频率，波特率计算时用这个值。

**面试怎么说：**
> "STM32 外设默认时钟关闭，使用前要通过 RCC 寄存器使能。UART 涉及 GPIO 和 USART 两个模块，分别挂在 AHB1 和 APB1 总线上，所以要开两个时钟。"

## 1.3 引脚复用配置（MODER + AFR）

**一句话：告诉引脚"你现在不是普通 GPIO，你要给 USART2 用"。**

PA2 和 PA3 默认是通用引脚，做 UART 的 TX/RX 必须显式配置，分两步：

**第一步：MODER — 设置引脚模式**

每个引脚 2 个 bit：
```
00 = 输入
01 = 输出
10 = 复用功能  ← UART 用这个
11 = 模拟
```

```c
GPIOA->MODER &= ~((3 << 4) | (3 << 6));  // 清除 PA2、PA3 原来的值
GPIOA->MODER |=  ((2 << 4) | (2 << 6));  // 设为 10（复用功能）
```

PA2 占 bit[5:4]，PA3 占 bit[7:6]，所以移位 4 和 6。

**第二步：AFR — 选择复用给哪个外设**

设成复用功能后，还需要指定给哪个外设：
```
AF7 = USART2  ← 用这个
AF5 = SPI
AF4 = I2C
```

```c
GPIOA->AFR[0] &= ~((0xFU << 8) | (0xFU << 12));  // 清除
GPIOA->AFR[0] |=  ((7U   << 8) | (7U   << 12));  // AF7 = USART2
```

两步缺一不可：
```
只设 MODER=10，不设 AFR  →  引脚不知道给谁用，行为未定义
只设 AFR，不设 MODER=10  →  引脚还是 GPIO 模式，复用不生效
```

**面试怎么说：**
> "引脚复用分两步：MODER 设为 10 表示复用功能模式，AFR 选择 AF7 表示分配给 USART2。两个寄存器都要配，缺一个引脚就不工作。"

## 1.4 波特率计算（BRR）

**一句话：BRR 告诉 USART2 每隔多久发一个 bit，双方必须一致才能通信。**

波特率 = 每秒传输多少个 bit。115200 baud = 每秒 115200 个 bit。发送方和接收方必须用同一速率，否则采样时机对不上，数据全乱。

**计算公式：**
```
USARTDIV = f_APB1 / (16 × BaudRate)
```

系统时钟 168MHz，APB1 四分频后 = 42MHz：
```
USARTDIV = 42,000,000 / (16 × 115200) = 22.786...

整数部分 = 22        → BRR[15:4] = 22
小数部分 = 0.786 × 16 = 12.5 → 取整 13 → BRR[3:0] = 13

BRR = (22 << 4) | 13 = 0x16D
```

为什么是 42MHz 不是 168MHz：USART2 挂在 APB1，APB1 经过 /4 分频，所以是 42MHz。

> 注意：若时钟配置改变（如退回 HSI 16MHz，APB1=16MHz），BRR 要重新算，此时 BRR = 0x8B。

**面试怎么说：**
> "BRR 由 APB1 时钟频率除以波特率计算得出。系统时钟 168MHz，APB1 四分频后 42MHz，按公式算出 BRR = 0x16D 对应 115200 baud。时钟配置变了 BRR 必须重新算。"

## 1.5 USART 使能顺序（CR1）

**一句话：TE / RE / UE 三个开关，UE 必须最后开。**

```c
USART2->CR1 = (1 << 3) | (1 << 2) | (1 << 13);
```

| bit | 名称 | 作用 |
|-----|------|------|
| bit2 | RE | 接收使能（Receiver Enable） |
| bit3 | TE | 发送使能（Transmitter Enable） |
| bit13 | UE | USART 总使能（USART Enable） |

UE 是整个 USART 模块的电源开关。若先开 UE 再配 TE/RE，中间有窗口期：USART 已工作但发送/接收未使能，可能产生乱码。

正确顺序：先配好 BRR 和 TE/RE，最后才开 UE。代码里一次性写入三个 bit，是同一个写操作，等效安全。

只开 TE 不开 RE 也可以——只需发送时 RE 可以不开。本项目两个都开，保留了接收能力（`UART_RecvChar`），支持将来从电脑发命令给 STM32。

**面试怎么说：**
> "CR1 里 TE 使能发送，RE 使能接收，UE 是总开关。配置顺序是先设好波特率和 TE/RE，最后开 UE，避免 USART 在未就绪状态下工作。"

## 1.6 发送：TXE 标志位

**一句话：USART 发送有一个缓冲区，没空之前不能塞新数据。**

```c
void UART_SendChar(char c) {
    while (!(USART2->SR & (1 << 7)));  // 等待 TXE=1
    USART2->DR = (unsigned char)c;
}
```

发送硬件结构：
```
你写入 DR  →  发送数据寄存器（TDR）  →  移位寄存器  →  TX 引脚逐位输出
```

DR 和移位寄存器是两个独立存储位置。**TXE=1** 表示 DR 已空，移位寄存器已取走上一个字节，可以写入下一个。

不等 TXE 直接写：新数据覆盖旧数据，上一个字节丢失。

这叫**阻塞发送**：`while` 循环卡住直到 TXE=1。
- 优点：简单可靠
- 缺点：等待期间 CPU 什么都不能做

对调试用途够用，但在实时控制系统里发大量数据会影响控制循环，生产代码应考虑 DMA 或中断方式。

**面试怎么说：**
> "发送前等待 TXE=1，确认发送寄存器为空再写入，否则会覆盖上一个字节。这是阻塞发送，简单但 CPU 会等待。如果发送数据量大，应考虑用 DMA 或中断方式避免占用 CPU。"

## 1.7 接收：非阻塞 RXNE + ORE 错误处理

**一句话：接收不等待，有数据就取，没有就直接返回。**

```c
uint8_t UART_RecvChar(char *c) {
    uint32_t sr = USART2->SR;
    if (sr & (1 << 3)) {        // ORE：溢出错误
        (void)USART2->DR;
        return 0;
    }
    if (sr & (1 << 5)) {        // RXNE：有数据
        *c = (char)(USART2->DR & 0xFF);
        return 1;
    }
    return 0;
}
```

**为什么是非阻塞？**

不知道电脑什么时候会发数据。如果用 `while` 等，程序永远卡在这里，电机控制全部停止。正确做法：主循环每次经过都问一句"有没有数据"，有就取走，没有继续干别的。

**RXNE**（Receive data register Not Empty）：接收移位寄存器收完一个完整字节后，数据放入 DR，RXNE 置 1。读取 DR 后自动清零。

**ORE**（Overrun Error，溢出错误）：上一个字节还在 DR 里没被读走，新字节又收完了，硬件没地方放，产生 ORE。新数据丢失，RXNE 被 ORE 盖住，正常读取失效。

清除方法：先读 SR，再读 DR，错误自动清除：
```c
if (sr & (1 << 3)) {
    (void)USART2->DR;   // 读 DR 清除 ORE
    return 0;
}
```

`(void)` 表示"我知道在读这个值，但不用它"，防止编译器优化掉这行。

**面试怎么说：**
> "接收用非阻塞方式，轮询 RXNE 标志位，有数据才读取，没有直接返回，不影响主循环。同时处理了 ORE 溢出错误——读取速度跟不上接收速度时产生，通过先读 SR 再读 DR 的顺序清除。"

## 1.8 项目坑：ST-Link VCP 失效 → 改 CH340G

**这是项目里真实发生的问题，面试里最有价值的部分。**

**背景：**

STM32F407G-DISC1 板载 ST-Link 芯片内置虚拟串口（VCP），理论上一根 USB 线就能收 UART 数据。

**遇到的问题：**

配置完全正确，但电脑端串口助手死活收不到任何数据。

排查过程：
1. 换 HAL 库写法重写 → 还是不行
2. 换串口助手软件 → 不行
3. **用示波器探 PA2** → 确认有正确 UART 波形输出
4. 结论：STM32 这侧完全正常，问题在 ST-Link 芯片内部，硬件损坏

**示波器定位问题的逻辑：**

```
STM32 PA2 → 导线 → ST-Link 芯片 → USB → 电脑 COM 口
```

示波器在 PA2 上看到正确波形 → PA2 之前的部分全部正常 → 问题在 PA2 之后，即 ST-Link 芯片侧。

这是示波器的核心用法：**在信号链路上找到"最后一个正常点"，问题就在那个点之后。**

**解决方案：换外部 CH340G 模块**

```
CH340G TXD → STM32 PA3 (USART2_RX)
CH340G RXD → STM32 PA2 (USART2_TX)   ← TX/RX 必须交叉
CH340G GND → STM32 GND               ← 必须共地
CH340G VCC → 不接                    ← STM32 自有供电
```

**为什么这个经历有面试价值：**

1. 硬件也会坏，不能假设开发板所有功能都正常
2. 用示波器定位问题边界，而不是盲猜
3. 知道绕过问题的方法，不卡死在原方案

**面试怎么说：**
> "调试串口时遇到一个问题：代码配置正确，示波器也能看到 PA2 有正常波形，但电脑端就是收不到数据。排查后发现是板载 ST-Link 的 VCP 硬件异常，不是软件问题。最后改用外部 CH340G 模块解决，同时也学到了用示波器定位问题在哪一侧。"
