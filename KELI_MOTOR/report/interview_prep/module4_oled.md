# 模块 4：显示 — OLED（I2C）

> 对应代码：`MOTOR_TEST/MDK-ARM/Src/custom_i2c.c` + `OLED_SSD1306.c`
> 硬件：SSD1306 0.96" OLED，I2C 地址 0x3C，PB6(SCL) / PB7(SDA)

---

## 4.1 I2C 协议基础：完整写操作流程

**一句话：I2C 是主机用两根线，按“开始、地址、数据、结束”的顺序和从机说话。**

两根线：

```
SCL = 时钟，由主机 STM32 产生
SDA = 数据，主机和从机都可以拉低
```

OLED 是从机，STM32 是主机。一次写操作分 4 步：

```
1. START   — SCL 高时 SDA 拉低，表示一次通信开始
2. 地址帧  — 7bit 从机地址 + 1bit 读写位
3. ACK     — 从机拉低 SDA，表示“我收到了”
4. STOP    — SCL 高时 SDA 拉高，表示通信结束
```

如果 OLED 没有 ACK，说明这次通信失败，比如地址错、没供电、线没接好、总线卡住。

代码里等 ACK 的体现：
```c
// custom_i2c.c:68 — 等地址帧的 ACK
while (!(I2C1->SR1 & I2C_SR1_ADDR) && --t);
if (!t) {
    I2C1->SR1 &= ~I2C_SR1_AF;   // 没 ACK → 清 AF 错误标志
    I2C1->CR1 |= I2C_CR1_STOP;
    return;
}
```

## 4.2 I2C 引脚：为什么必须开漏 + 上拉

**一句话：I2C 总线很多设备共用，所以大家只能“拉低”，不能主动“推高”。**

### 推挽和开漏

**推挽（Push-Pull）**：内部两个晶体管，能主动输出高也能主动输出低。

**开漏（Open-Drain）**：只有下管（N型），只能主动拉低；输出高时下管断开，线靠外部上拉电阻爬回 VCC。

### 为什么 I2C 用开漏

多设备共享同一根线。若用推挽：
```
设备A 推高（接 VCC） + 设备B 拉低（接 GND） → 短路 → 烧芯片
```

用开漏：
```
任何设备拉低 → 线为低（主动）
所有设备松手 → 上拉电阻把线拉到 VCC（被动）
```

所以 I2C 的规则是：

```
低电平 = 有人拉低
高电平 = 所有人都松手，上拉电阻拉高
```

这就是为什么 SDA/SCL 要配置成开漏。

### 上拉电阻怎么选

上拉电阻负责把线从低电平拉回高电平。

它不能太大，也不能太小：

| 情况 | 问题 |
|------|------|
| R 太大 | τ 大，上升太慢，高速时信号来不及爬到 VCC，读到错误的 0 |
| R 太小 | 线被拉低时电流 = VCC/R 过大，功耗高，低电平电压升高超出 VOL |

这里的 `τ = R × C`，`C` 是总线寄生电容。线越长、模块越多，电容越大，上升越慢。

| SCL 速率 | 推荐 R |
|---------|--------|
| 100kHz 标准模式 | 4.7kΩ |
| 400kHz 快速模式 | 2.2kΩ |
| STM32 内部上拉 | ~40kΩ（单设备短线凑合用） |

代码配置：
```c
GPIOB->OTYPER |= (GPIO_OTYPER_OT6 | GPIO_OTYPER_OT7);     // 开漏
GPIOB->PUPDR  |= (GPIO_PUPDR_PUPD6_0 | GPIO_PUPDR_PUPD7_0); // 内部上拉
```

### SCL 频率从哪来

I2C 的 SCL 频率不是随便来的，它来自 APB1 时钟再分频：

```
HSI/PLL → SYSCLK → APB1(PCLK1) → I2C CCR 分频 → SCL
```

```c
I2C1->CR2 = 36;   // APB1 = 36MHz
I2C1->CCR = 180;  // SCL = 36MHz / (2×180) = 100kHz
I2C1->TRISE = 37; // 最大上升时间 = 1000ns × 36MHz + 1 = 37
```

这里要特别注意：`CR2` 必须写真实的 `PCLK1` 频率，单位是 MHz。

如果当前工程的 `SystemClock_Config()` 配置为：

```
SYSCLK = 168MHz
APB1 = HCLK / 4 = 42MHz
```

那 100kHz 标准模式更一致的配置应是：

```c
I2C1->CR2 = 42;
I2C1->CCR = 210;   // 42MHz / (2×210) = 100kHz
I2C1->TRISE = 43;  // 1000ns × 42MHz + 1
```

所以面试里不要只背 `36/180/37`，要说清楚：

```
CR2/CCR/TRISE 要跟 APB1 实际频率一致
```

## 4.3 SSD1306 地址 0x3C 怎么确定

**一句话：0x3C 是 OLED 的 7 位从机地址，0x78 是把 0x3C 左移一位后的写地址字节。**

### 7 位地址和 8 位地址字节

I2C 第一个字节 = 7位地址 + 1位读写：
```
bit7  bit6  bit5  bit4  bit3  bit2  bit1 | bit0
──────────────────────────────────────────┼──────
         7位从机地址                      │ R/W
         0  0  1  1  1  1  0            │  0(写)/1(读)
```

- **0x3C** = 7位地址本身
- **0x78** = 0x3C 左移1位（最低位 R/W=0），是实际发到总线的字节

### SA0 引脚决定地址

SSD1306 高6位固定 `011110`，最低1位由 SA0 引脚决定：
```
SA0 = GND → 地址 0x3C（淘宝模块默认，出厂焊死）
SA0 = VCC → 地址 0x3D
```

同一总线可挂两个 SSD1306，SA0 分别接 GND/VCC 即可区分。

### 代码里的两种写法

```c
#define OLED_Addr  0x78   // 存的是"写地址"（含R/W=0）

// 传给函数时右移还原为7位地址
i2c_write_memory(OLED_Addr >> 1, ...)  // 0x78 >> 1 = 0x3C
```

右移只是两种地址约定之间的转换：

```
0x78 >> 1 = 0x3C
```

本项目的 `i2c_write_memory()` 需要传 7 位地址，所以调用时右移。

## 4.4 项目坑：OLED 卡死

### 卡死原因

**一句话：I2C 如果一直等硬件标志位，但标志位永远不来，程序就会卡死。**

驱动里有多处“等标志位”循环：
```c
while (!(I2C1->SR1 & I2C_SR1_SB));   // 等 START
while (!(I2C1->SR1 & I2C_SR1_ADDR)); // 等地址 ACK
while (!(I2C1->SR1 & I2C_SR1_TXE));  // 等发送缓冲空
```

正常流程：

```
硬件完成动作 -> 置标志位 -> while 退出
```

卡死流程：

```
上一次 I2C 异常
   ↓
STOP 没正常发出 / BUSY 仍为 1
   ↓
下一次 START 发不出去
   ↓
SB/ADDR/TXE 等标志位不来
   ↓
while 永远不退出
```

如果 OLED 刷新卡死在 while 里，主循环也会被拖住，电机控制就可能受影响。

### 修复方案

**1. 等待都加超时**

让程序最多等一段时间，等不到就放弃本次 OLED 写入：

```c
t = I2C_TIMEOUT;
while (!(I2C1->SR1 & I2C_SR1_SB) && --t);
if (!t) { I2C1->CR1 |= I2C_CR1_STOP; return; }
```

**2. 每次事务开始前清残留错误标志**

如果上次留下 AF/BERR/ARLO/OVR，这次要先清掉：

```c
I2C1->SR1 &= ~(I2C_SR1_AF | I2C_SR1_ARLO | I2C_SR1_BERR | I2C_SR1_OVR);
```

否则硬件还记着旧错误，新事务可能一开始就失败。

### `--t` 的含义

`--t` 是前缀自减，先减再判断：

```c
t = 10000;
while (!(flag) && --t);
// 每次循环：t先减1，减完的值参与&&判断
// t减到0 → 0为假 → 退出（超时）
// flag来了 → 第一个条件为假 → 退出（正常）
```

退出后用 `if (!t)` 区分是哪种退出：t==0 说明超时，flag来了说明正常。

用 `--t` 不用 `t--`：t=1时前缀先减成0立刻退出，后缀会多跑一次。

### 为什么等不到标志位

标志位本质上是硬件的回执：

```
我完成了 -> 我把某个 bit 置 1
```

等不到通常有两类原因：

**① 代码写错**（可修复）：时钟未使能、引脚未配AF、CCR算错等，改代码解决。

**② 硬件/环境问题**（不可避免）：OLED供电抖动、导线过长信号变形、电机启动干扰等。代码完全正确也会发生。

所以超时保护不是掩盖bug，而是对抗不可预测的硬件环境——和TCP重传是同一个逻辑。

### 早期 bug：错误关闭 PE

早期代码参考了"出错就复位外设"的写法：
```c
I2C1->CR1 &= ~I2C_CR1_PE;  // 关掉
I2C1->CR1 |= I2C_CR1_PE;   // 再开
```

STM32 的坑：**关 PE 时硬件强制释放总线，时机不对会让 SDA/SCL 出现异常电平，反而让总线卡在 BUSY**，比不关更糟。修复方法是永远不关 PE，改用清错误标志代替。

### 出错后的完整恢复流程

```
超时退出
   ↓
发 STOP（释放总线）→ return（放弃本帧）
   ↓
1ms 后下一控制周期进来
   ↓
先清错误标志（AF/BERR/ARLO/OVR）← 必须在重试前做
   ↓
重新开始整个事务
```

不先清标志直接重来：硬件看到 SR1 里还有 AF=1，认为总线仍在错误状态，新事务直接失败。

## 4.5 和老师 PPT 的对应关系

这一节可以直接放到报告里，用来把 OLED 代码和 interconnections、peripheral、power management 里的知识连起来。

### I2C 是“地址选设备”，不是“片选选设备”

老师 interconnections 里讲 I2C 是多主多从、两根线共享的同步总线：

```
SCL = clock
SDA = data
```

本项目只用了最简单的场景：

| 角色 | 器件 | 作用 |
|------|------|------|
| Master | STM32 I2C1 | 产生 SCL，发 START/地址/数据/STOP |
| Slave | SSD1306 OLED | 地址匹配 0x3C 后 ACK，并接收命令/数据 |

I2C 和 SPI 最大的区别：

| 协议 | 怎么选中设备 |
|------|--------------|
| SPI | 拉低某个 CS/NSS 引脚 |
| I2C | 在总线上发送 7bit 地址 |

所以 OLED 不需要单独 CS 引脚。只要总线上设备地址不同，多个 I2C 设备就可以共用 PB6/PB7。

### 开漏 = 多设备共享总线的物理基础

老师 PPT 里说 I2C 的逻辑是：

```
输出 0：设备主动拉低到 GND
输出 1：设备松手，由上拉电阻拉高
```

这会形成“线与”效果：

```
任何设备拉低 → 总线 = 0
所有设备松手 → 总线 = 1
```

这就是 I2C 可以仲裁和 ACK 的原因。比如 ACK 时，STM32 发完 8bit 后释放 SDA，OLED 如果收到了，就在第 9 个时钟把 SDA 拉低。STM32 读到低电平，就知道 OLED 收到了。

本项目虽然只有一个 master，不需要真的处理多主仲裁，但 GPIO 仍然必须按 I2C 规则配置成 AF4 开漏上拉。

### OLED 写入不只是“发一个字节”

SSD1306 每次 I2C 写入通常有两类字节：

| 字节 | 含义 |
|------|------|
| 地址字节 | `0x3C + W`，选中 OLED |
| 控制字节 | `0x00` 表示后面是命令，`0x40` 表示后面是显示数据 |
| 数据字节 | 真正的命令参数或像素数据 |

所以一次典型 OLED 写命令是：

```
START
地址 0x3C + 写位
ACK
控制字节 0x00
ACK
命令字节
ACK
STOP
```

一次典型 OLED 写像素数据是：

```
START
地址 0x3C + 写位
ACK
控制字节 0x40
ACK
显示数据...
ACK
STOP
```

这对应老师 PPT 里的帧结构：

```
START → Address → R/W → ACK → Data → ACK → STOP
```

### CPU 到 OLED 的外设链路

老师 peripheral 里讲 memory-mapped I/O：CPU 读写某个地址，不一定是在读写 SRAM，也可能是在操作外设寄存器。

本项目 OLED 的链路是：

```
CPU 写 I2C1->DR
    ↓
I2C1 外设硬件移位发送
    ↓
PB6/PB7 输出 SCL/SDA 波形
    ↓
SSD1306 收到地址、控制字节和数据
    ↓
OLED 内部显存/控制器更新显示
```

这里 `I2C1->DR` 是 STM32 内部外设寄存器，不是 OLED 的显存。OLED 的显存不在 STM32 地址空间里，只能通过 I2C 命令间接写进去。

### OLED 供电和线性稳压

老师 power management 里讲线性稳压器：输出干净，但多余电压会变成热。

本项目中 OLED 和 STM32 逻辑侧工作在 3.3V，通常来自板载 LDO 或面包板电源模块的 3.3V 输出：

```
外部电源 / USB → 稳压器 → 3.3V → STM32 + OLED
```

OLED 电流不大，所以线性稳压的效率不是主要矛盾；但电机启动会带来电源噪声，所以 OLED 卡死问题有时不只是代码，也可能来自供电抖动、地线压降或 I2C 线太长。

**面试怎么说：**
> "OLED 通过 I2C1 通信，PB6/PB7 配成 AF4 开漏上拉。I2C 和 SPI 不同，它靠 7 位地址选设备，不靠 CS；OLED 地址 0x3C 是 7 位地址，代码里的 0x78 是左移后的写地址。一次写操作是 START、地址+写位、ACK、控制字节、数据、STOP，其中 0x00 表示命令，0x40 表示显示数据。
>
> 从课程角度看，开漏上拉是 I2C 多设备共享总线的物理基础：任何设备都只能拉低，不能主动推高，所以 ACK 就是 OLED 在第 9 个时钟把 SDA 拉低。代码层面 CPU 写 I2C1->DR，I2C 外设硬件产生 SCL/SDA 波形，OLED 收到后更新内部控制器/显存。
>
> 项目里踩过的坑是 I2C 等标志位可能卡死，所以每个等待都加 timeout，出错发 STOP 并清 AF/BERR/ARLO/OVR，避免 OLED 问题拖死主控制循环。"
