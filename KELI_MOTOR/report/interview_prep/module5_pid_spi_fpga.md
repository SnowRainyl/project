## 5.1 为什么用串级 PID，单环有什么问题

**一句话：速度环管“转多快”，电流环管“用多大力”。串级 PID 是先算需要多大电流，再算需要多少 PWM。**

### 单环的问题

速度 PID 直接输出 PWM 占空比：

```
目标RPM → [速度PID] → PWM → 电机
              ↑
           编码器（慢）
```

两个缺陷：

1. **速度反馈比较慢**：转速要靠编码器在一个采样周期内的计数差算出来。PWM 已经打到电机上了，速度变化要过一会儿才看得出来。

2. **无法直接限流**：速度 PID 如果直接输出 PWM，启动或负载突变时可能一下子给很大 duty，电流峰值不好控制。

### 串级的解法

在速度环和 PWM 之间加一个电流环：

```
目标RPM → [速度外环] → 目标电流(mA) → [电流内环] → PWM → 电机
              ↑                              ↑
           编码器                          INA240
```

- 速度外环输出：为了达到目标 RPM，我希望电流是多少
- 电流内环输出：为了达到目标电流，我应该给多少 duty
- 外环 `out_max = 400mA`，所以目标电流不会无限变大，这就是限流

## 5.2 位置式离散 PID 公式

**一句话：output = P项（当下）+ I项（历史）+ D项（趋势）。**

公式：

```
output = kp × err  +  ki × integral  +  kd × (err - err_prev)
```

代码对应（[pid.c:30-42](../../MOTOR_TEST/MDK-ARM/Src/pid.c)）：

```c
float err = setpoint - feedback;
pid->integral += err;
float deriv = pid->kd * (err - pid->err_prev);
pid->err_prev = err;
float output = pid->kp * err + pid->ki * pid->integral + deriv;
```

三项含义：

| 项 | 公式 | 物理含义 |
|----|------|---------|
| **P 比例** | `kp × err` | 现在差多少，差越大打越猛。快，但有稳态误差 |
| **I 积分** | `ki × Σerr` | 历史误差累加。消除稳态误差——哪怕当前误差很小，只要一直差，积分会一直推 |
| **D 微分** | `kd × Δerr` | 误差变化速度。误差快速缩小时提前收力，防止超调 |

口诀：**P 管当下、I 管历史、D 管趋势。**

### 积分项是否必须有

不是必须的。判断依据：**能不能接受稳态误差。**

- 纯 P 控制：系统最终可能稳定在目标值附近但差一点点（靠误差维持输出，误差越小推力越小）
- 加 I 项：不断累加小误差直到推到 0，消除稳态误差；代价是可能超调、windup

| 情况 | 是否需要积分 |
|------|------------|
| 允许有一点稳态误差 | 可以不要 |
| 有前馈控制/模型补偿 | 积分可以很小甚至不要 |
| 必须长期精准到目标值 | 通常需要 |
| 有持续扰动（负载变化、摩擦） | 通常需要 |

本项目必须精确控速，所以保留 I 项，同时加 Anti-windup 对冲它的副作用。

### 本项目为什么 kd = 0

编码器 RPM 是离散量化测量，真实转速稳定时 RPM 数值也会在几个整数间跳动（量化噪声）。D 项会把这种"假变化"放大成很大的输出，导致 PWM 以 1kHz 来回抖，电机发出嗡嗡声。保留 D 项的净收益是负的，所以两个环都用 PI。

## 5.3 积分限幅与 Anti-windup

**一句话：输出已经到上限时，积分再继续增加也没用，只会让之后超调更严重；Anti-windup 就是阻止这种无用积分。**

### Windup 的发生过程

以电机从 0 启动，目标 100 RPM 为例：

1. 启动时误差 = 100，积分每 1ms 累加 100
2. 经过若干 ms，`output` 超过 `out_max=4095`，被截断
3. **关键**：output 已经被截断，但积分还在继续累加
4. 电机加速到 100 RPM，误差变 0，P项=0，但 **I项仍是一个很大的正数**
5. 输出继续猛推 → 电机冲过 100 RPM → 大幅超调
6. 误差变负，积分才慢慢往回减，但要消化之前多余的"积分债"，需要很多周期
7. 结果：转速震荡很久才稳定

### 代码的两层保护（[pid.c:34-59](../../MOTOR_TEST/MDK-ARM/Src/pid.c)）

**第一层：`integral_max` 硬限幅**

```c
if      (pid->integral >  pid->integral_max) pid->integral =  pid->integral_max;
else if (pid->integral < -pid->integral_max) pid->integral = -pid->integral_max;
```

积分绝对值不超过上限，防止无限膨胀。

**第二层：输出饱和时回退积分**

```c
if (output > pid->out_max) {
    output = pid->out_max;
    if (err > 0.0f) pid->integral -= err;   // 撤销本次累加
} else if (output < pid->out_min) {
    output = pid->out_min;
    if (err < 0.0f) pid->integral -= err;
}
```

输出饱和 AND 误差方向会让饱和更严重时，撤销本次 `integral += err`，让积分停在"刚好让输出 = out_max"的值上。

一句话：**输出已经顶到上限时，继续积分只会欠债；Anti-windup 是及时停止欠债。**

## 5.4 内外环参数：kp/ki 怎么定的

### 两个 kp 做的是不同单位换算

| 环 | 输入误差 | 输出 | kp 的含义 |
|----|---------|------|----------|
| 速度外环 kp=1.5 | RPM（0~100） | mA（0~400） | 每差 1 RPM，多要 1.5 mA 电流 |
| 电流内环 kp=5.0 | mA（0~400） | duty（0~4095） | 每差 1 mA，PWM duty 推 5 个单位 |

kp 数值不可直接比大小，因为单位不同。粗略估算合理量级：`out_range / in_range` = 400/100=4（速度外环），4095/400≈10（电流内环）。

### 内环要比外环更“硬”

这里的“更快”不是说代码里有两个不同频率的中断。

本项目里速度环和电流环都在 TIM6 的 1kHz 中断里计算。区别是：

```
速度环看编码器 RPM，机械响应慢
电流环看 INA240 电流，电气响应快
```

所以电流环参数要调得更直接、更快，让它尽量像一个“电流执行器”。

如果电流环太软，会出现：

```
外环：我要 300mA → 内环：还没到
外环：我要 350mA → 内环：还没到
→ 速度环看到的是一个失控的执行器，整体振荡
```

所以电流内环 `kp` 通常会比外环更激进一些，让实际电流尽快跟上目标电流。

### 整定过程

1. **先断开外环**，手动给固定目标电流（如 200mA），调内环 kp/ki 直到电流快速稳定无超调
2. **再闭合外环**，kp 从小往大调，观察串口打印 RPM 曲线
3. 本项目实测：速度外环 kp=20 时 RPM 振荡 → 逐步降到 1.5 稳定

### 当前参数

| 环 | kp | ki | kd | out_max | integral_max |
|----|----|----|-----|---------|-------------|
| 速度外环 | 1.5 | 0.1 | 0.0 | 400 mA | 2000 |
| 电流内环 | 5.0 | 0.2 | 0.0 | 4095 | 8000 |

## 5.5 SPI 帧格式：12bit duty 怎么发

**一句话：duty 是 12bit，SPI 一次只能发 8bit，所以拆成高 4bit 和低 8bit，分两次发。**

### 这条 SPI 总线是谁和谁通信

本项目里 SPI2 的角色很简单：

| 角色 | 器件 | 作用 |
|------|------|------|
| Master | STM32 | 主动拉低 CS，主动产生 SCK，主动发送 duty |
| Slave | FPGA | 被 CS 选中后，跟着 SCK 接收 MOSI 数据 |

这对应老师 interconnections 课里的 SPI 第一性原理：

```
SPI 不靠地址找设备
SPI 靠 CS / NSS 选中设备
Master 负责产生时钟 SCK
MOSI 是 Master → Slave
MISO 是 Slave → Master
```

所以这里不是像 I2C 那样发送设备地址。STM32 拉低 `PB12` 这个 GPIO CS，就等于告诉 FPGA：“接下来 SPI2 上的数据是给你的”。

本项目只需要 STM32 把 duty 发给 FPGA，不需要 FPGA 回传数据，所以 MISO 即使存在，也可以不用读；SPI 硬件仍然是全双工，只是返回的数据被丢弃。

### 为什么用 12bit 不用 8bit

- 8bit = 256 级，控制 0~100 RPM 每级 ≈ 0.39 RPM，低速抖动明显
- 12bit = 4096 级，每级 ≈ 0.024 RPM，平滑 16 倍
- FPGA PWM 计数器本身就是 12bit，精度天然匹配

### 拆包代码（[stm32f4xx_it.c](../../MOTOR_TEST/Core/Src/stm32f4xx_it.c)）

```c
uint8_t hi = (duty >> 8U) & 0x0FU;   // 取 bit11~bit8（高4位）
uint8_t lo =  duty        & 0xFFU;   // 取 bit7~bit0（低8位）

FPGA_CS_LOW();
SPI2_ReadWriteByte(hi);
SPI2_ReadWriteByte(lo);
FPGA_CS_HIGH();
```

举例：duty = `0x8A3`

```
duty >> 8      = 0x008
& 0x0F         = 0x08  → hi（防止 duty 越界时高位脏数据混入）

duty & 0xFF    = 0xA3  → lo

FPGA 收到：hi=0x08, lo=0xA3
拼回：(0x08 << 8) | 0xA3 = 0x8A3 ✓
```

`& 0x0F` 是防御性写法：duty 最大 4095=`0x0FFF`，正常不需要这个 mask，但万一传入了超出范围的值，能保证只发 4bit。

## 5.6 FPGA PWM 频率计算

**一句话：50MHz 晶振，12bit 计数器（0~4095），每个周期 4096 个时钟，所以 PWM 频率 = 50MHz / 4096 ≈ 12.207kHz。**

### 推导

```
T_clock  = 1 / 50MHz = 20ns
T_PWM    = 4096 × 20ns = 81.92μs
f_PWM    = 1 / 81.92μs ≈ 12,207 Hz = 12.207kHz
```

逻辑分析仪实测 12.207kHz，与计算完全吻合。

### 为什么是 50MHz

AX309 开发板上焊了一颗 50MHz 有源晶振，直接连到 FPGA 时钟引脚。这是板子硬件设计的选择，不来自任何规范。换一块 100MHz 晶振的板子，同样的计数器 PWM 频率就是 `100MHz / 4096 ≈ 24.4kHz`。

### 为什么选 12bit 计数器

- 12bit 分辨率对应 4096 级 PWM，与 STM32 ADC 12bit 量程匹配
- 可以换成 8bit（256 级，195kHz），但分辨率变粗，低速控制精度下降

## 5.7 和老师 PPT 的对应关系

这一节可以直接放进报告，用来说明这个项目不是孤立代码，而是把 power management、interconnections、peripheral 里的概念串起来。

### 闭环控制框架

老师 power management 里讲的闭环稳压，本质是：

```
目标值 → 比较误差 → 控制器 → PWM / 功率级 → 被控对象 → 传感器反馈
```

本项目只是把“稳压”换成了“稳速 + 限流”：

| 课程闭环稳压 | 本项目速度外环 | 本项目电流内环 |
|--------------|----------------|----------------|
| 参考值 | 电位器给目标 RPM | 速度 PID 给目标电流 |
| 反馈值 | 输出电压采样 | 编码器 RPM / INA240 电流 |
| 误差放大器 | 控制器 | PID |
| PWM 调制 | 改变占空比 | FPGA 输出 12bit PWM |
| 功率级 | DC-DC 开关管 | TB6612 H 桥 |
| 被控对象 | 输出电压 | 直流电机转速 / 电流 |

所以串级 PID 不是两个随便叠起来的 PID，而是两个闭环：

```
外环：转速不够 → 多要一点电流
内环：电流不够 → 多给一点 duty
```

### PWM 电机调速 ≈ 简化 Buck

老师 peripheral 里说 PWM 的平均电压：

```
Vavg = duty_ratio × VH
```

对应到本项目：

```
D = duty / 4095
Vmotor_avg ≈ D × 12V
```

这和 Buck Converter 的核心公式 `Vout = D × Vin` 是同一个思想：

| Buck Converter | 本项目 |
|----------------|--------|
| 输入电压 Vin | 12V 电源 |
| 开关管 | TB6612 内部 MOSFET |
| 占空比 D | FPGA 输出的 duty / 4095 |
| 电感 | 电机线圈本身 |
| 续流二极管 | TB6612 内部续流路径 |
| 输出平均电压 | 电机两端平均电压 |

所以 PWM 控速不是“玄学地一闪一闪”，而是利用电机线圈电感和机械惯量，把高速开关平均成一个等效驱动电压。

### PWM 和 DAC 的区别

ADA full notes 里讲 DAC transfer function：数字码 `D` 经过 DAC 后，直接变成一个阶梯状模拟电压。

理想 DAC 可以理解成：

```
数字 D → 模拟电压 A
A = D × LSB
```

如果本项目真的用 DAC 控电机，链路会像这样：

```
PID duty 数字量 → DAC 输出模拟电压 → 线性功率放大 → 电机
```

但项目没有这么做，而是：

```
PID duty 数字量 → FPGA PWM → TB6612 H 桥开关 → 电机平均电压
```

两者目标相似，都是让数字控制量影响电机电压；但实现完全不同：

| 方案 | 输出形态 | 功率效率 | 是否适合电机 |
|------|----------|----------|--------------|
| DAC + 线性功放 | 连续模拟电压 | 低，多余电压变热 | 不适合大功率电机 |
| PWM + H 桥 | 高速开关波形，靠电感/惯量平均 | 高，MOSFET 主要工作在开/关 | 适合电机 |

所以可以把 PWM 理解成“用于功率控制的等效 DAC”：它不是在引脚上输出真正连续的模拟电压，而是用占空比控制平均能量。

### TB6612 H 桥和续流

老师 power management 里讲 Full H-bridge：四个开关管决定电机两端电压方向。本项目没有自己搭四个 MOSFET，而是用 TB6612 集成 H 桥。

| 信号 | 作用 |
|------|------|
| `AIN1/AIN2` | 决定正转、反转、刹车或停止 |
| `PWMA` | 接收 FPGA PWM，决定平均电压大小 |
| `STBY` | 总使能，低电平时驱动关闭 |

电机是电感负载，PWM 关断瞬间电流不能立刻变成 0，必须有续流路径。TB6612 内部的 MOSFET/二极管提供这条路径，避免电机线圈产生很高的反向电压打坏驱动器。

因为 TB6612 是集成驱动芯片，同一桥臂上下管的 shoot-through 防护由芯片内部处理，本项目代码只需要给方向信号和 PWM，不需要自己写 dead time。

### SPI2 到 FPGA 是外设链路

老师 peripheral 课里说 CPU 通过 memory-mapped 外设寄存器控制外设。本项目发送 duty 的链路就是：

```
CPU 写 SPI2->DR
    ↓
SPI2 硬件产生 SCK/MOSI
    ↓
FPGA 的 SPI slave 接收两个字节
    ↓
FPGA duty 寄存器保存 12bit duty
    ↓
FPGA 计数器 0~4095 循环计数
    ↓
比较器：counter < duty 时输出高电平
```

这里 `SPI2->DR` 是 STM32 片上外设寄存器；FPGA 里的 duty register、PWM counter、comparator 是硬件逻辑，不是 C 语言变量。

## 5.8 TIM6 1kHz 控制循环

**一句话：TIM6 每 1ms 叫醒一次控制代码，让系统按固定节奏“测量 → 计算 → 输出”。**

### 时钟参数推导

TIM6 输出频率 = TIM6_CLK / (PSC+1) / (ARR+1)

```
TIM6_CLK = 84MHz（APB1=42MHz，APB1预分频≠1 → 定时器时钟×2）
PSC = 83  → 84MHz / 84 = 1MHz（第一级分频）
ARR = 999 → 1MHz / 1000 = 1kHz（第二级分频）
```

分两步的原因：从 84MHz 直接到 1kHz 需要除以 84000，超出 16bit 寄存器范围（最大 65535），所以分两步。

### 为什么选 1kHz

| 频率 | 问题 |
|------|------|
| 太低（如 10Hz） | 每 100ms 更新一次 PWM，电机负载变化来不及响应 |
| 太高（如 100kHz） | 编码器在 0.01ms 内脉冲太少，测速噪声极大；ISR 执行时间可能超过中断间隔 |
| 1kHz（1ms） | 比机械时间常数（50~200ms）快 50~200 倍，足够跟上机械变化；ISR 执行约 9μs，占周期 0.9% |

控制频率经验原则：**比被控对象机械时间常数快 10 倍以上**（从参考设计/博客获取起点，实测微调）。

> **注意**：JGA25-370 的 datasheet 只给了空载转速、空载电流、堵转扭矩等基本参数，**没有机械时间常数**（τ_m = J/B，需要转动惯量和阻尼系数，廉价电机 datasheet 通常不提供）。50~200ms 是直流减速电机的经验范围，精确值只能实测——串口打印 RPM，看启动曲线从 0 到稳定转速花了多少毫秒。

### 中断执行顺序

```
读TIM3（编码器→实际RPM）
    ↓
读ADC_IN0（电位器→目标RPM）
    ↓
算速度PID（目标RPM vs 实际RPM → 目标电流mA）
    ↓
读ADC_IN1（INA240→实际电流mA）
    ↓
算电流PID（目标电流 vs 实际电流 → duty 0~4095）
    ↓
发SPI2（duty → FPGA → PWM → 电机）
```

这个顺序对应代码里的 TIM6 中断：

```
Encoder_Update()
ADC1_Read_Filtered()
PID_Calc(&speed_pid, ...)
ADC1_ReadCurrent_Filtered_mA()
PID_Calc(&current_pid, ...)
SPI2_ReadWriteByte()
```

核心原则是：

```
先读本周期传感器，再用本周期数据算 PID，最后输出 duty
```

## 面试怎么说

> "这个项目用串级 PID 控速。外环是速度环，输入目标 RPM 和编码器反馈，输出目标电流；内环是电流环，输入目标电流和 INA240 反馈，输出 PWM 占空比。串级的好处是限流保护天然内置，内环响应比速度反馈快，能更早抑制扰动。
>

>
> 占空比是 12bit（0~4095），SPI 一次发 8bit，所以拆成高 4bit 和低 8bit 分两次发，FPGA 收到后拼回 12bit 驱动 PWM 计数器。FPGA 时钟 50MHz，12bit 计数器，PWM 频率 = 50MHz/4096 ≈ 12.207kHz，逻辑分析仪实测吻合。
>
> 从课程角度看，这就是闭环控制框架在电机上的应用：目标值和反馈值比较，PID 产生控制量，再通过 PWM 和功率级驱动负载。PWM 的平均电压近似 `Vmotor_avg = duty/4095 × 12V`，可以类比 Buck Converter；TB6612 是集成 H 桥，负责把 PWM 变成电机两端的功率输出，并提供续流路径保护电感负载。
>
> 和 ADA 课里的 DAC 相比，PWM 不是直接输出连续模拟电压，而是输出高速开关波形；电机线圈电感和机械惯量会把它平均成等效电压。这样比 DAC 加线性功放效率高得多，所以电机控制更常用 PWM + H 桥。
>
