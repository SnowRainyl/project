# 模块 2：ADC 信号采集

> 对应代码：`MOTOR_TEST/MDK-ARM/Src/adc_reg.c`
> 硬件：ADC1，PA0（电位器）/ PA1（INA240 电流输出），12bit，软件触发单次转换

---

## 2.1 ADC 在项目里的角色

**一句话：ADC 是模拟世界和数字世界之间的翻译器。**

电位器转动产生的是电压，0~3.3V 连续变化。STM32 是数字芯片，只能处理数字。ADC 把连续电压转成 0~4095 的整数，STM32 才能用它计算目标转速。

| 通道 | 引脚 | 信号来源 | 用途 |
|------|------|---------|------|
| IN0 | PA0 | 电位器 | 给定目标转速 |
| IN1 | PA1 | INA240 输出 | 测量实际电流，给电流内环用 |

两路都用 ADC1，软件切换通道。

**12bit 的含义：**
12bit = 2¹² = 4096 个等级，对应 0~3.3V，分辨率约 0.8mV，足够区分毫安级电流变化。

**STM32 的 ADC 是 SAR（逐次逼近寄存器）型：**
用二分法猜测输入电压，12bit 需要 12 次比较。SAR 在速度和精度之间平衡最好，适合嵌入式控制场景。

**面试怎么说：**
> "ADC 采两路：PA0 接电位器给定目标转速，PA1 接 INA240 输出测电流。两路都用 ADC1，软件切换通道，12bit 分辨率，采样结果再换算成实际物理量。"

---

## INA240 电流采样链路（补充背景）

ADC 读到的是电压，不是电流。完整链路：

```
电机电流流过采样电阻（0.1Ω）
        ↓
产生电压差（欧姆定律自动发生，无需计算）：2A × 0.1Ω = 0.2V
        ↓
INA240 差分放大（IN+ - IN-）× 50倍增益
        ↓
输出电压（分压后）送入 PA1
        ↓
ADC 读取，软件换算回电流
```

**为什么用差分放大：**
采样电阻在电机电路里，两端共模电压可能高达 12V。直接接 ADC 会烧芯片。INA240 只放大两端差值，共模部分自动消除，这就是 CMRR（共模抑制比）的作用。

**INA240 是 Current Sense Amplifier（电流采样放大器）**，专门用于高共模电压环境下的小信号差分放大。

## 2.2 ADC 时钟配置（ADCPRE）

**一句话：ADC 有自己的最高时钟限制，必须分频到范围内才能正常工作。**

时钟链路：
```
HSI 16MHz → PLL → SYSCLK 168MHz → APB2 84MHz → ADCPRE /4 → ADC 21MHz
```

STM32F407 的 ADC 最高时钟是 36MHz，APB2 是 84MHz，直接给 ADC 会超标，除以 4 得到 21MHz。

```c
ADC->CCR &= ~ADC_CCR_ADCPRE;   // 清除分频位
ADC->CCR |=  (1U << 16U);      // ADCPRE = 01 → /4
```

注意是 `ADC->CCR` 不是 `ADC1->CCR`——CCR 是三个 ADC 共用的公共寄存器，命名上没有数字就说明是公共的。

**所有外设的统一规律：**

```
系统时钟 → 总线分频 → APB1/APB2 → 外设内部再分频 → 实际工作频率
```

| 外设 | 分频旋钮在哪 |
|------|------------|
| UART | BRR（分频融合进波特率计算） |
| SPI | CR1 的 BR 位 |
| ADC | CCR 的 ADCPRE 位 |
| I2C | CR2 的 FREQ 位 + CCR 寄存器 |

I2C 需要两个参数是因为开漏总线上升沿受 RC 影响，协议对各段时序有独立要求，硬件需要知道输入时钟频率才能把纳秒换算成时钟周期数。

**面试怎么说：**
> "ADC 时钟最高 36MHz，APB2 是 84MHz 必须分频。用 CCR 寄存器设 /4 得到 21MHz。CCR 是三个 ADC 共用的公共寄存器，不是 ADC1 独有的。"

## 2.3 采样通道配置（SQR + SMPR）

**主线：ADC 是一个"把某一路模拟电压接进来，转换成数字，放到 DR 寄存器"的硬件。**

---

**Channel 是输入来源，不是存储区**

```
CH0  对应 PA0（电位器）
CH1  对应 PA1（电流采样）
```

Channel 只是告诉 ADC"这次测哪一路电压"，结果不会存在 channel 里，结果统一进入 `ADC_DR`。

---

**SQ 是测量顺序位置**

```
SQ1 = 第 1 步测哪个 channel
SQ2 = 第 2 步测哪个 channel
```

**SQR 是配置 SQ 队列的寄存器**

STM32F4 最多支持 16 步序列：

```
SQR3: SQ1  ~ SQ6   （每个 SQx 占 5bit，存 channel 号）
SQR2: SQ7  ~ SQ12
SQR1: SQ13 ~ SQ16，还有 L
```

**L 表示一轮测几步**

```
转换步数 = L + 1
L=0 → 1步，L=1 → 2步，以此类推
```

L=0 不是"只能用一个通道"，而是"每次启动 ADC，只执行 SQ1 这一步"。

---

**项目的方式：动态切换单通道**

```c
ADC1->SQR1 = 0U;          // L=0，每次只测 1 步
ADC1->SQR3 = ch;          // SQ1 = ch（每次读之前动态改）
```

调用两次，分别测两个通道：
```c
ADC1_ReadChannel(0);      // SQ1=CH0，只测 PA0 一次
ADC1_ReadChannel(1);      // SQ1=CH1，只测 PA1 一次
```

循环来自外层代码，不是 ADC 自己连续测。

---

**一次 ADC 读取的完整流程**

```c
ADC1->SQR3 = ch;               // 选这次测哪个 channel
ADC1->CR2 |= ADC_CR2_SWSTART;  // 软件触发，启动一次转换
while (!(ADC1->SR & ADC_SR_EOC)) {}  // 等 EOC 置位（转换完成）
raw = ADC1->DR & 0x0FFF;       // 读结果（同时清 EOC）
```

硬件自动完成：选择 channel → 采样电压 → 转换成数字 → 写入 ADC_DR → 置位 EOC。

---

**信号流总图**

```
GPIO 模拟引脚（PA0 / PA1）
        ↓
ADC channel（CH0 / CH1）
        ↓
SQ 队列决定第几步测哪个 channel
        ↓
SWSTART 启动
        ↓
ADC 转换（SAR 逐次逼近，12步）
        ↓
ADC_DR 存结果
```

---

**SMPR — 采样时间寄存器**

每个通道需要一段时间让内部电容充电到输入电压，信号源阻抗越高充电越慢，需要更长采样时间。

```c
ADC1->SMPR2 |= (6U << 0);   // CH0（电位器）：阻抗几kΩ，选较长采样时间
ADC1->SMPR2 |= (2U << 3);   // CH1（INA240）：输出阻抗低，短采样时间够
```

SMPR2 结构（每通道 3bit）：
```
bit[2:0] → CH0，bit[5:3] → CH1，bit[8:6] → CH2 ...
```

为什么是 SMPR**2** 不是 SMPR**1**：18 个通道 × 3bit = 54bit，一个寄存器装不下，按通道号拆成两个：
- SMPR2 → CH0~CH9
- SMPR1 → CH10~CH18

默认值 `000 = 3 周期`（最短），对高阻抗信号源不够，必须手动配置，否则读数偏低。

---

**如果要一次启动测多个通道（扩展知识）**

```c
ADC1->SQR1 = (1U << 20);        // L=1 → 2步
ADC1->SQR3 = (0U << 0) |        // SQ1=CH0
             (1U << 5);         // SQ2=CH1
```

启动后 ADC 自动依次测 CH0 → CH1。这种模式通常需要 DMA，否则 ADC_DR 可能被后一个结果覆盖。

---

**面试怎么说：**
> "SQR 寄存器定义转换序列，channel 是输入来源，SQ 是测量顺序，结果统一存在 ADC_DR。项目用单步模式，每次动态改 SQ1 来切换通道。SMPR 设置各通道采样时间，电位器阻抗高给更长时间，INA240 输出阻抗低只需短时间。"

---

## 2.4 12bit 结果换算成物理量

**一句话：ADC 读到的是 0~4095 的数字，需要用公式换算回实际电压、转速、电流。**

**第一步：数字 → 电压（所有通道一样）**
```
V_mV = raw × 3300 / 4095
```

**第二步（电位器）：电压 → 目标转速**
```
target_rpm = raw × 100 / 4095
```
raw=0 → 0 RPM，raw=4095 → 100 RPM，线性映射。

**第二步（电流）：电压 → 电流**
```c
V_out_mV = raw × 3300.0f / 4095
I_mA = (V_out_mV - 1773) × 1000 / (50 × 100)
```

参数说明：
- 增益 = 50（INA240 A2 档）
- 采样电阻 = 100mΩ（0.1Ω）
- V_ref = **1773mV**（实测零电流时的输出电压）

**零偏是什么：**

理想传感器零输入应该零输出，但 INA240 内部电路制造不对称，零电流时实际输出约 1773mV 而不是 0V。每次计算电流都要先减去这个值，就像体重秤空载显示 2kg，每次称重都要减去 2kg。

**为什么用实测值 1773mV 而不是理论值：**

每颗 INA240 零偏略有不同，数据手册给的是范围。实测一次得到的是这块板子专属的校准值，比理论值更准。这是调试过程中发现读数偏差后校准的（原来用 1650mV，实测不准，改为 1773mV）。

零偏会随温度漂移，本项目室温下使用没问题，工业级产品需要温度补偿。

**面试怎么说：**
> "ADC 读到 12bit 原始值，先换算成电压，电位器直接线性映射到转速，电流通道还要减去零偏校准值再除以增益和采样电阻。零偏是实测的 1773mV，不是理论值，因为每颗芯片略有不同。"

## 2.5 死区处理

**一句话：电位器归零时 ADC 不会精确读到 0，要人为设一个忽略区间。**

**问题发现过程（实测记录）：**

```
现象：电位器归零时，duty 和电流周期性爬升，电机偶发抖转

根本原因：adc ≈ 9（非零）→ PID 把它当成目标转速
         → 积分项每个控制周期持续累加
         → duty 慢慢爬升 → 电机抖一下
         → 转速短暂超目标，误差变负，积分回落
         → 周期性重复
```

**为什么积分会累积：**

```
积分项 += 误差 × 时间
```

误差 = 目标转速 - 实际转速 = 0.2 - 0 = 0.2 RPM，持续存在，每个周期都在加，最终推高 duty。

**解决方法：**

```c
if (adc < 50) {
    setpoint = 0;   // 强制目标转速为零
}
```

50 的来源：实测归零时 adc 最大约 9，选 50 留了足够余量，同时不会把真实低速目标误判为零。

**面试怎么说：**
> "调试时发现电位器归零后电机偶发抖转，串口打印发现 adc 归零时读数是 9 左右。这导致 PID 积分持续累积，duty 慢慢爬升。加了死区，adc < 50 强制 setpoint 为 0，50 是在实测值 9 的基础上留了余量。"

## 2.6 均值滤波

**一句话：ADC 读数每次都有噪声，把多次读数平均一下，噪声就抵消了。**

**为什么 ADC 读数会抖动：**

热噪声、电源纹波、数字电路干扰，同一个不变的输入电压，每次读到的值都有几个 LSB 的差异。

**滑动窗口均值滤波：**

```c
sum     -= buf[idx];            // 减去最旧的值
buf[idx] = ADC1_ReadChannel(0); // 读新值
sum     += buf[idx];            // 加入新值
idx      = (idx + 1) % 16;     // 移动指针
return sum / 16;                // 返回平均值
```

始终保留最新的 N 个读数，每次用新值替换最旧的值。每次只读一次 ADC，计算量极小，效果等同于 N 次平均。

**两路信号窗口大小不同：**

| 信号 | 窗口大小 | 原因 |
|------|---------|------|
| 电位器 | 16点 | 人手转动慢，大窗口滤波更平滑 |
| 电流 | 8点 | 电流变化快，窗口太大引入延迟影响内环响应 |

**诚实的说法（没有做对比测试）：**
16 和 8 是根据信号特性估算的经验值，没有做严格的对比测试。严格验证应该记录不同窗口大小下的阶跃响应曲线来确认最优值。

**窗口大小的 tradeoff：**
- 窗口越大：滤波越平滑，但响应越慢
- 16点 @ 1kHz = 16ms 延迟，对电位器没影响，对快速电流信号需要权衡

**面试怎么说：**
> "用滑动窗口均值滤波消除 ADC 噪声。电位器 16 点、电流 8 点，窗口大小不同是因为电流变化更快，窗口太大会引入延迟影响内环响应速度。这两个值是经验估算，没有做严格对比测试，验证方式应该是对比不同窗口下的阶跃响应曲线。"

## 2.7 和老师 PPT 的对应关系

这一节可以直接放到报告里，用来把 ADC 代码和 ADA、peripheral 里的知识连起来。

### 采集链：模拟世界进入 MCU 的路径

老师 ADA 课里给出的采集链可以概括为：

```
Protection → Gain → Anti-alias Filter → MUX → Sample/Hold → ADC
```

本项目两路 ADC 正好对应这个结构。

**PA0 电位器通道：**

```
电位器
    ↓
RC 低通滤波（模拟域滤波）
    ↓
PA0 / ADC_IN0
    ↓
ADC1 MUX 选中 CH0
    ↓
S/H 采样保持
    ↓
12bit SAR ADC
    ↓
软件 16 点均值滤波
    ↓
目标 RPM
```

**PA1 电流通道：**

```
电机电流
    ↓
0.1Ω 采样电阻
    ↓
INA240 差分放大，增益 50
    ↓
PA1 / ADC_IN1
    ↓
ADC1 MUX 选中 CH1
    ↓
S/H 采样保持
    ↓
12bit SAR ADC
    ↓
软件 8 点均值滤波
    ↓
实际电流反馈
```

这里的 MUX 就解释了为什么一个 ADC1 可以测两个引脚：ADC1 内部有模拟多路选择器，一次只把其中一路接到采样电容上。它不是两个通道同时转换，而是在 1kHz 控制循环里由软件依次切换。

### 为什么 STM32 用 SAR ADC

老师 ADA 课里比较了几类 ADC：

| ADC 类型 | 特点 | 是否适合本项目 |
|----------|------|----------------|
| Flash ADC | 极快，但比较器数量随 bit 指数增长，面积大 | 不适合 MCU |
| Sigma-Delta | 精度高，但延迟大 | 不适合 1kHz 实时控制 |
| SAR ADC | 面积小、速度够、精度中等 | 适合 MCU 片内 ADC |

本项目的 STM32F407 ADC1 就是 12bit SAR ADC。它的思路像二分查找：

```
先猜最高位
再猜下一位
...
12bit 就比较 12 次左右
```

项目里 ADC 时钟是 21MHz，一次转换约为：

```
采样周期 + 12 个左右转换周期
```

这个时间远小于 1ms 控制周期，所以 ADC 转换速度够用。

### 12bit 精度和系统分辨率

老师 ADA 里提到 N bit 量化会把模拟电压分成 `2^N` 级。本项目：

```
12bit = 4096 级 = 0~4095
```

电压分辨率约为：

```
3300mV / 4095 ≈ 0.806mV / LSB
```

这个 12bit 也和后面的 PWM duty 对齐：

| 模块 | 分辨率 |
|------|--------|
| ADC | 12bit，0~4095 |
| FPGA PWM | 12bit，0~4095 |

所以从输入给定到输出占空比，整个系统的数字量级是统一的。

### 量化误差：ADC 不可能无限精确

ADA full notes 里把量化噪声写得更完整：ADC 把连续电压切成很多台阶，每个台阶的宽度就是 1 LSB。

本项目：

```
1 LSB ≈ 3300mV / 4095 ≈ 0.806mV
```

ADC 读数天然有半个 LSB 左右的不确定性：

```
量化误差 ≈ ±0.5 LSB ≈ ±0.403mV
```

所以 `raw=2048` 不代表输入电压“精确等于某一个点”，而是代表输入电压落在某个小区间里。

对正弦满量程输入，老师笔记里给了常见近似：

```
SNRq(dB) ≈ 6n + 1.76
```

12bit 时：

```
SNRq ≈ 6 × 12 + 1.76 = 73.76dB
```

这个数字不是说项目真的能达到 73.76dB，而是说“只考虑理想量化噪声时，12bit ADC 的理论上限”。实际项目还会有电源噪声、PWM 纹波、传感器零偏、线路干扰，所以实际有效位数 ENOB 会低一些。

### S/H：为什么采样后还能慢慢转换

ADA full notes 里强调了 Sample & Hold：

```
Sample：开关闭合，内部电容跟随输入电压
Hold：开关断开，电容把刚才的电压保持住，ADC 开始转换
```

这解释了一个关键问题：SAR ADC 转换要比较很多次，输入电压如果一直变化怎么办？

答案是：

```
先采样，把电压存在内部电容上
再保持，让 SAR 对这个被冻结的电压做 12bit 转换
```

所以采样时间不能太短。采样时间太短时，内部电容还没充到真实输入电压，ADC 就开始转换，读数会偏低或不稳定。

这也解释了前面 SMPR 的设置：

| 信号 | 源阻抗/特点 | 采样时间选择 |
|------|-------------|--------------|
| 电位器 | 阻抗较高，内部采样电容充电慢 | 采样时间长一点 |
| INA240 | 输出阻抗低，驱动能力强 | 采样时间可以短一点 |

### ADC 动态时序：采样周期必须够长

ADA full notes 里有一个很重要的条件：

```
Ts > Tacq + Tconv
```

意思是：一次采样周期必须容纳两段时间：

| 阶段 | 含义 |
|------|------|
| `Tacq` | acquisition time，内部采样电容充到输入电压所需时间 |
| `Tconv` | conversion time，ADC 把保持电压转换成数字所需时间 |

本项目控制循环是 1kHz：

```
Ts = 1ms
```

ADC 时钟约 21MHz，一次转换是“采样周期 + 12 个左右转换周期”，远小于 1ms。因此从时间预算看，ADC 转换不会拖慢控制循环。

但这不代表采样时间可以随便设得很短。`Tconv` 是 ADC 自己能不能算完，`Tacq` 是输入电路能不能把采样电容充准；两者是两个问题。

### 多通道切换的额外注意点

ADA full notes 里还提到多通道系统：

```
Channel 1 -- 前端电路 --+
Channel 2 -- 前端电路 --+--> MUX --> S/H --> ADC
Channel N -- 前端电路 --+
```

本项目就是这种结构：

```
CH0 电位器
CH1 电流采样
    ↓
ADC1 内部 MUX
    ↓
同一个 S/H + SAR ADC
```

多通道切换时要注意：上一个通道的电压可能会通过寄生电容影响下一个通道，所以切换后仍然要给足 acquisition time。项目里每次只做单通道单次转换，并且采样时间不是最短值，就是为了让通道切换后的电压稳定下来。

### 采样频率和混叠风险

老师 ADA 课里讲 ADC 采样必须考虑带宽和抗混叠。本项目控制循环是 1kHz，也就是每 1ms 采样一次：

```
采样频率 fs = 1kHz
奈奎斯特频率 = 500Hz
```

但电机电流里会混入 FPGA PWM 的开关纹波：

```
PWM 频率 ≈ 12.2kHz
```

这个频率远高于 500Hz，直接采样会把高频纹波折叠成低频噪声，影响 PID 判断。

本项目的处理方式：

| 信号 | 处理 |
|------|------|
| 电位器 PA0 | 前端 RC 低通 + 软件 16 点均值 |
| 电流 PA1 | INA240 后软件 8 点均值 |

严格来说，软件均值不能完全替代模拟抗混叠滤波，因为高频已经进 ADC 之后才被平均；但对这个项目的 1kHz 控制和低成本硬件来说，它能明显压低 PWM 纹波对 PID 的影响。

### ADC1->DR 不是普通变量

老师 peripheral/memory 里讲外设寄存器不是普通 RAM。代码里的：

```c
ADC1->DR
ADC1->SQR3
ADC1->SMPR2
```

都是 memory-mapped 外设寄存器。

读取 `ADC1->DR` 的意义不是“读一个内存变量”，而是：

```
读出 ADC 硬件刚刚转换完成的结果
```

并且在 STM32 上，读 `DR` 还会影响硬件状态，例如清除 EOC 标志。所以外设寄存器访问必须按参考手册规定的顺序来。

**面试怎么说：**
> "从课程角度看，ADC 链路是模拟信号经过滤波/放大后进入 ADC1 MUX，再到采样保持和 12bit SAR 转换。12bit 把 0~3.3V 分成 4096 级，1 LSB 约 0.806mV，理想量化误差约 ±0.5 LSB。PA0 电位器和 PA1 电流共用同一个 ADC1，不是同时采样，而是在 1kHz 控制循环里软件切换 SQR3。切换后要给 S/H 电容足够 acquisition time，再进行 SAR 转换。项目还考虑了采样噪声和 PWM 纹波，所以电位器用 RC 加 16 点均值，电流用 8 点均值滤波。"
