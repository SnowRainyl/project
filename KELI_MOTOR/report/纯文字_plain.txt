[CHAPTER] Abstract This report introduces the design and implementation of a DC motor cascade closed-loop control system based on STM32F407 microcontroller and AX309 FPGA development board. The system adopts a cascade PI control structure composed of a speed outer loop and a current inner loop to achieve smooth speed adjustment in the range of 0 to 100 RPM. The initialization and data sending and receiving of the main peripherals of the system are implemented in register-level C language, including UART, ADC, SPI, I2C and TIM3 orthogonal encoder interfaces. FPGA uses VHDL to realize a 12-bit PWM generator with a PWM frequency of about 12.2 kHz, and receives duty cycle instructions sent by STM32 through SPI. The motor current is sampled by the INA240A2 bidirectional current shunt monitor and sent into the current inner loop, and the encoder speed feedback closes the speed outer loop. The experimental results show that the system can operate in a stable closed loop in the range of 0–100 RPM, and the actual measured PWM frequency is 12.207 kHz (completely consistent with the theoretical value of 50 MHz/4096); the output shaft is not connected to the external load, and the target speed is 100 RP. At M, the system measures that the motor current is about 30 mA.

Keywords: cascade PI, STM32F407, FPGA, DC motor control, current sampling, register-level programming, VHDL

The user gives the speed through the rotary potentiometer, and STM32F407 reads the potentiometer voltage and converts it into the target speed of 0–100 RPM; the encoder provides actual speed feedback, and the current sampling amplifier (INA240A2) provides motor current feedback. The controller calculates the PWM duty cycle according to these feedbacks and sends it to FPGA through SPI, and the FPGA outputs the PWM signal to drive the back-end motor drive module. Around this control link, the system needs to complete the following functions: - Speed setting and closed-loop speed adjustment: support the target speed setting of 0–100 RPM, and automatically adjust the PWM duty cycle according to the encoder feedback, so that the motor speed follows the given value. - Control accuracy target: in P When the ID parameters are determined and the load conditions are stable, the goal is to reduce the steady-state error between the actual speed and the target speed, and the specific error is evaluated through subsequent experimental data. - Operating status display: OLED displays the target speed, actual speed, PWM duty cycle and motor current in real time, which is convenient for Field observation system status. - Debugging information output: connect the PC through UART to output the speed, current, duty cycle and PID intermediate quantity, which is convenient for observing the operating status and adjusting PID parameters. - Parameter non-volatile storage: use SPI Flash (W25 Q64) Save PID parameters; when the system is powered on, it will check whether there are valid parameters in Flash, and if there are, they will be automatically read and used. In terms of hardware conditions, STM32F407 has provided the main interfaces required for this project: ADC can be used for potentiometer and current signal sampling, timer can be used for encoder speed measurement and cycle control, and USART, SPI and I2C are used for serial debugging, external Flash, FPGA communication and OLED display. The specific peripheral instance and the corresponding pin will be listed in the subsequent peripheral mapping chapter. The execution part generates a 12-bit PWM signal from FPGA, and the H-bridge motor drive module (TB6612FNG) converts the PWM signal into the driving voltage and current required by the motor; the INA240A2 current sampling module is connected in series between the H-bridge output and the motor, The R100 (0.1) sampling resistance on the module generates a voltage drop, which is amplified and sent to ADC. From the perspective of software implementation, the program can be divided into modules such as sampling, filtering, control, communication, display and parameter storage. The periodic control task is responsible for reading the input and feedback signals, and outputting the PWM control amount according to the calculation results of the cascade PI; serial command processing, OLED refresh and Flash parameter saving are completed in the main loop. In this way, closed-loop control, display, storage and other tasks can be realized separately, and the program structure is also clearer. In summary, this project has the conditions for implementation in terms of hardware interface and software task division. The results of steady-state error, current measurement and parameter preservation will be further verified in the experimental chapter.
[SECTION] System Architecture Design The system adopts a hierarchical architecture, as shown in Figure [REF]. [FIGURE CAPTION] DC motor cascade PI control system architecture diagram. The system is mainly composed of MCU control part, FPGA PWM generation module and motor execution part. The potentiometer output first passes through RC filtering, and then connects to the ADC channel 1 of the MCU as the target speed input; the INA240A2 module is connected in series between the H-bridge output and the motor, and the module output is connected to the ADC channel 2 as a current feedback; the encoder A/B The timer encoder interface connected to the MCU is used to calculate the actual speed. MCU completes the cascade PI operation according to the target speed, actual speed and current feedback, and sends the duty cycle instruction to the FPGA through SPI2. FPGA generates a PWM signal and drives the H-bridge motor drive module, and finally controls the operation of the DC motor. W25Q64 Flash, OLED and PC are connected to MCU through SPI1, I2C and UART respectively for PID parameter storage, status display and serial debugging. The main control link is as follows:

[MATH]
\text{Potentiometer} \xrightarrow{\text{RC + ADC}} \text{STM32 PID}
\xrightarrow{\text{SPI2}} \text{FPGA} \xrightarrow{\text{PWM}}
\text{TB6612} \rightarrow \text{Motor}
[/MATH]

The encoder speed and current sampling signals are fed back to STM32 to form a closed-loop control. [SECTION] Control strategy: If only single-loop speed PI is used, the control link can be expressed as:

[MATH]
\text{Target Speed}
\rightarrow \text{Speed PI}
\rightarrow \text{PWM}
\rightarrow \text{Motor}
[/MATH]

This structure can adjust the speed, but it only corrects the PWM according to the feedback of the encoder. The encoder reflects the result of mechanical movement, which is relatively slow due to the influence of rotor inertia and load; the motor current is the electrical amount, and the PWM will rise faster when it increases. Therefore, when starting or the load suddenly changes, the speed feedback may not change significantly. The current has risen first, and it is difficult for the single-loop speed PI to constrain the current in time. For this reason, this project adds a current loop between the speed loop and PWM to form a cascade PI:

[MATH]
\text{Target Speed}
\rightarrow \text{Speed PI}
\rightarrow \text{Target Current}
\rightarrow \text{Current PI}
\rightarrow \text{PWM}
\rightarrow \text{Motor}
[/MATH]

Among them, the encoder speed is fed back to the speed PI, and the current sampling result is fed back to the current PI. The speed outer loop gives the target current according to the speed error, indicating how much driving force is needed to approach the target speed at present; the current inner loop then calculates PWM according to the target current and actual current, and the duty cycle is no longer directly determined by the speed error. The division of labor of these two closed loops is: the speed outer loop is responsible for the speed target, and the current inner loop is responsible for the actual current. Because the current change is faster than the speed change, the current loop can perceive the current rise caused by start-up or load change earlier, and adjust the PWM according to the actual current; at the same time, the target current itself has an upper limit, so it can reduce the pressure caused by excessive current on the motor and drive circuit.

[SUBSECTION] Current Sensing: INA240A2 current sampling module This project uses the INA240A2 current sampling module with R100 sampling resistance. The R100 in the module is connected to the motor in series, and the connection relationship is

[MATH]
\text{AO1} \rightarrow \text{R100} \rightarrow \text{Motor} \rightarrow \text{AO2}.
[/MATH]

Therefore, all the motor current will flow through R100. The IN+ and IN- of INA240A2 are connected at both ends of R100 respectively to measure the voltage difference on the resistor; its input end is only responsible for measurement, and the main current of the motor will not flow into the INA240A2 chip. This connection method directly measures the motor current in the H-bridge output loop, which is not an ordinary power supply high edge or ground low edge sampling. The resistance of R100 is 0.1, and when the current flows, it will produce a small voltage drop proportional to the current. Estimated at a working current of 30–300 mA, the voltage drop is about 3–30 mV. INA240A2 amplifies the differential voltage between IN+ and IN- by 50 times, and then sends it to PA1 (ADC1\_IN1) of STM32 through the OUT pin, so that the current change can be measured stably.

[SUBSECTION] Speed sensing: encoder and TIM3 orthogonal decoding JGA25-370 motor has a built-in Hall effect orthogonal encoder, output A and B two-phase signals. The encoder is installed on the internal shaft of the motor, and the control object is the output shaft after deceleration. Therefore, the speed calculation needs to consider the number of pulses per turn of the encoder and the gear reduction ratio at the same time. The motor encoder of this project is 11 PPR, and the deceleration ratio is 34. The TIM3 encoder mode counts the four edges of the A/B phase, so the output shaft corresponds to each turn.

[MATH]
11 \times 34 \times 4 = 1496
[/MATH]

Count. If GPIO external interrupt processing is used, each edge will trigger the CPU interrupt, and when the motor speed increases, it will obviously occupy the control cycle time. TIM3 is configured as encoder mode 3 (SMS = 011), and the hardware state machine completes A/B phase decoding. The CPU only needs to read the CNT difference once in the control interruption to calculate the rotational speed, and the overhead is very small; at the same time, the hardware digital filter (IC1F = IC2F = 0001, 2 sampling) is used to suppress short pulse interference. The formula for calculating the speed is:

[MATH]
\text{RPM} = \frac{\Delta_{\text{count}} \times 60{,}000}
{N_{\text{PPR}}}
\label{eq:rpm}
[/MATH]
Among them, \Delta_count is the signed 16-bit counter difference (automatically handles overflow), and N_PPR is the number of pulses per rpm (including the deceleration ratio and \times4 mode). This project only uses ADC1 and selects two input channels: PA0 corresponds to ADC1\_IN0, which is used to collect potentiometer voltage; PA1 corresponds to ADC1\_IN1, which is used to collect current feedback. The program first selects the input channel through the SQR3 register of ADC1, and then starts the SWSTART position 1 to start the conversion. After the conversion is completed, the program waits for the EOC flag to be set to 1 and read the 12-bit result of 0–4095 from the DR register. The in-chip ADC of STM32F407 adopts a sequential approximative (SAR) structure. In the sampling stage, the internal sampling capacitor connects the input and saves the current voltage; in the conversion stage, the SAR logic gives the probe number from the highest bit, the internal DAC converts it into the probe voltage, and the comparator then compares the voltage with the sampling voltage. SAR retains or clears the current bit according to the comparison results, and continues to judge the next one. After 12 comparisons, the final 12-digit result is obtained. Its basic structure is shown in Figure [REF].

[FIGURE CAPTION] The basic structure of SAR ADC. The ADC clock is generated by the APB2 clock through the shared prescaler. The APB2 clock is 84 MHz, and the data manual stipulates that the ADC clock is up to 36 MHz, so 42 MHz cannot be obtained by 2 frequency division. This project configures the ADCPRE of ADC\_CCR to 4 frequency divisions, so that the ADC clock is

[MATH]
f_{\text{ADCCLK}}=\frac{84\,\text{MHz}}{4}=21\,\text{MHz},
[/MATH]

The corresponding single ADC clock cycle is about 1/21 MHz=47.6 ns. The sampling time indicates the time when the internal sampling capacitor of the ADC is connected to the input signal, and its unit is the ADC clock cycle. The higher the impedance of the input source, the longer it usually takes to fully charge the sampling capacitor. The potentiometer output is connected to ADC after passing through an RC low-pass filter composed of 10 k resistance and 100 nF capacitance, so it adopts a longer 144 cycle; the current sampling amplifier has a lower output impedance and 28 cycles. [SUBSUBSECTION] THE SPI1 PID PARAMETER IS SAVED IN SRAM WHEN THE PROGRAM IS RUNNING, BUT THE DATA WILL BE LOST AFTER THE SRAM IS POWERED OFF, AND THE ADJUSTED PARAMETERS CANNOT BE RETAINED AFTER POWER-ON. STM32 internal Flash is mainly used to store programs, so this project uses an independent W25Q64 to save PID parameters, so that parameter storage is separated from program storage. W25Q64 can still retain data after power outage and can be read and written through SPI1; after the user saves the parameters, the system can read and continue to use it the next time it is powered on. SPI is a synchronous full-duple serial protocol: the host (STM32) is responsible for generating clock SCK and chip selection CS, and the data is shifted according to the MSB priority (Mode 0) on the rising edge of SCK; MOSI carries the data from the host to the slave, and the MISO carries the slave to The data of the host, CS pull-down means that the slave is selected, and CS pull-up means that the transaction is over. W25Q64 as a SPI slave will not actively initiate communication, and all operations are actively initiated by STM32 in the full frame format of CS↓ + instruction byte + address + data + CS↑. The communication timing is: lower the chip selection pin (select the slave), send and receive data bytes, and pull up the chip selection pin (release the slave). W25Q64FV is a NOR Flash with a capacity of 8 MB. Its basic storage unit is a floating gate transistor. The floating gate is surrounded by an insulating layer and can retain electrons after power outage. The charge in the floating gate will change the threshold voltage of the transistor, and the reading circuit identifies 0 and 1 by judging whether the transistor is conductive at a given voltage. Figure [REF] shows the programming process of the NOR Flash array. The address decoder selects the target word line according to the input address, and applies programming voltage to the bit line that needs to be written as 0, so that the corresponding transistor can complete the programming through thermal electron injection. Multiple storage bits that need to be changed to 0 in the same line can be programmed at the same time. [FIGURE CAPTION] Word line selection and bit programming principle of NOR Flash array. Figure [REF] shows the erasing process of the floating gate transistor. When erasing, the electrons in the floating gate undergo Fowler–Nordheim tunneling through the thin oxidation layer under the action of a strong electric field. After the electrons leave the floating grid, the threshold voltage of the transistor decreases, and the storage bit is restored from 0 to 1. [FIGURE CAPTION] F-N tunneling and erasing process of FLOTOX floating gate transistor. Therefore, the programming operation of NOR Flash can only change the storage bit from 1 to 0; to restore 0 to 1, the corresponding sector must be erased first. [CHAPTER] CASCADE PI CONTROL ALGORITHM THIS CHAPTER EXPLAINS THE IMPLEMENTATION OF CASCADE CONTROL ALGORITHM. The program uses the general PID function, but the differential coefficients of the speed loop and the current loop are set to 0, so the actual cascade PI control is used. The differential term can suppress rapid changes in advance and reduce overshoot, but it will also amplify the encoder count fluctuations and current sampling ripples. In order to keep the control output stable, the differential sub-item is not enabled for the time being. The following introduces the discrete calculation method of the general PID, and then explains the connection relationship, parameter settings and 1 kHz control loop of the two PI loops. [SECTION] The control function in the PI mathematical model program retains the complete PID structure. The PID controller calculates the control output according to the error between the target value and the feedback value, and the error is defined as

[MATH]
e(t)=r(t)-y(t),
[/MATH]

Among them, r(t) is the target value, y(t) is the actual measured value, and u(t) is the controller output. The expression of continuous PID is:

[MATH]
u(t) = K_p\,e(t) + K_i\int_0^t e(\tau)\,d\tau + K_d\,\frac{de(t)}{dt}
[/MATH]

In the formula, the proportional term immediately adjusts the output according to the current error; the accumulated past error of the integral term is used to reduce the steady-state error; the differential term corrects the output according to the change of the error, which is used to suppress excessive changes. The program calculates PID every T=1 ms. After changing the integral to error accumulation and changing the differentiation to the difference of two adjacent errors, the discrete form used by the program is:

[MATH]
u[n] = K_p\,e[n]
+ K_i \sum_{k=0}^{n} e[k]
+ K_d\,\bigl(e[n] - e[n-1]\bigr)
\label{eq:pid_discrete}
[/MATH]

Among them, e[n] is the error of this time, e[n-1] is the error of the previous time, and u[n] is the output of this calculation. The integral coefficient in the code has been multiplied by the sampling cycle T, and the differential coefficient has been divided by T, so the sampling cycle is no longer multiplied separately in the program. K_i and K_d in the following parameter table both refer to the coefficients actually used by the program. This project sets the K_d of both loops to 0, so the PI control formula actually used is

[MATH]
u[n] = K_p\,e[n] + K_i \sum_{k=0}^{n} e[k].
\label{eq:pi_discrete}
[/MATH]

If the output has reached the upper limit, but the integral continues to increase, the control output will remain saturated for a long time. In order to reduce this impact, the program limits the accumulation of points to the following range:

[MATH]
-I_{\max}
\leq \sum_{k=0}^{n} e[k]
\leq I_{\max}
[/MATH]

The output is also limited to the range of [u_, u_]. The output range of the speed outer loop is 0–400 mA, and the output range of the current inner loop is 0–4095. When the output reaches the upper limit or lower limit, if continuous integration will further exceed the range of the output, the program will not retain the result of this integration step to avoid excessive integral accumulation. Symbol | Meaning

y | Measured (feedback) value
e = r − y | Error between target and measured value
u | Controller output
K_p | Proportional gain: effect of current error on output
K_i | Integral gain: effect of accumulated past error on output

SCK comes from STM32 and has no fixed phase relationship with the FPGA internal clock. If it is sampled directly, metastable states may be generated when the sampling moment falls near the SCK jump edge. The program uses two series triggers to synchronize the SCK and detect the rising edge according to the two-level sampling value. The first level receives asynchronous input, and the second level samples again in the next clock cycle, thus reducing the probability of metastable propagation to the post-stage logic. The core code is as follows: [CODE: SCK two-level synchronization chain.]
p_sync : process(clk)
begin
 if rising_edge(clk) then
 sck_d1 <= sck;
 sck_d2 <= sck_d1;
 end if;
end process;
sck_rise <= sck_d1 and (not sck_d2);  -- single-cycle rising-edge pulse
[/CODE]

[MATH]

[SECTION] Positional-form PID Implementation

[CODE: PID_Calc — positional-form PID with anti-windup]
float PID_Calc(PID_TypeDef *pid, float setpoint, float feedback)
{
 float err = setpoint - feedback;

 pid->integral += err;
 if (pid->integral > pid->integral_max)
 pid->integral = pid->integral_max;
 else if (pid->integral < -pid->integral_max)
 pid->integral = -pid->integral_max;

 float deriv = pid->kd * (err - pid->err_prev);
 pid->err_prev = err;

 float output = pid->kp * err + pid->ki * pid->integral + deriv;

 if (output > pid->out_max) {
 output = pid->out_max;
 if (err > 0.0f) pid->integral -= err;
 } else if (output < pid->out_min) {
 output = pid->out_min;
 if (err < 0.0f) pid->integral -= err;
 }
 return output;
}
[/CODE]
