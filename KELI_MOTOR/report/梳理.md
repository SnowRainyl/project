本项目使用了三种 interconnection（互连接口）：UART（通用异步收发器）、SPI（串行外设接口）、I2C（集成电路总线）。

---

## UART（通用异步收发器）

UART（通用异步收发器）作为连接 STM32 和 PC 的 interconnection（互连接口），用于在电脑上 debug（调试），查看 STM32 运行中的各种数据。

**为什么用 CH340G 而不是板载 USB：**

STM32F407G-DISC1 板上有一颗 ST-Link V2 芯片，它原本有两个功能：
1. SWD（串行线调试）烧录/调试（一直正常）
2. VCP（Virtual COM Port，虚拟串口）：板内走线把 PA2/PA3 接到 ST-Link 芯片，ST-Link 再通过板子的 USB 口模拟成一个 COM（串口）口，PC 就能收到 USART2 数据

这块板的 VCP（虚拟串口）功能损坏了（寄存器配置完全正确，PA2 引脚输出正常，但电脑端 COM（串口）口收不到任何数据，疑似 ST-Link 内部 UART 子模块硬件损坏）。

**CH340G 的作用：**

STM32 的 USART2 输出的是 TTL（晶体管-晶体管逻辑）电平的 UART 信号（0V=逻辑0，3.3V=逻辑1，按照起始位+数据位+停止位的时序发送）。CH340G 是一颗 USB-to-UART（USB转串口）桥接芯片：它一边用 USB 协议跟 PC 通信（PC 看到一个 COM（串口）口），另一边用 UART 电信号跟 STM32 的 PA2/PA3 通信。"转换"的含义就是把 UART 的 TTL（晶体管-晶体管逻辑）电信号翻译成 USB 总线协议，PC 才能用串口工具收到数据。

连线（TX（发送端）/RX（接收端）必须交叉）：
- CH340G TXD（发送脚）→ STM32 PA3（USART2_RX，接收引脚）
- CH340G RXD（接收脚）→ STM32 PA2（USART2_TX，发送引脚）
- CH340G GND（地）→ STM32 GND（必须共地）
- CH340G VCC（电源）→ 不接（STM32 自有供电）

波特率：115200，8N1，PC 端设备管理器中找 "USB-SERIAL CH340 (COMxx)"。

## SPI（串行外设接口）

SPI（串行外设接口）需要 4 根信号线：MOSI（主出从入）、MISO（主入从出）、CLK（时钟）、CS（片选），全双工（Master（主设备）发送的同时 Slave（从设备）也可以回传数据）。SPI 是高速协议，适合对传输速率有要求的外设。

本项目 SPI 连接了两个设备：

### 1）连接 FPGA

**信号流向（重要，方向不要搞反）：**

```
STM32 (SPI2)  →  FPGA  →  pwm_out (J3-31)  →  TB6612 PWMA  →  电机转动
                                                                    ↓
                                                编码器（反馈转速）→  STM32 TIM3 (PC6/PC7)
```

STM32 每 1ms 的控制中断里，把算好的 12-bit 占空比通过 SPI2 发给 FPGA（2 字节拼成 12bit）。FPGA 收到后驱动 PWM 发生器，把 PWM 信号输出给 **TB6612 电机驱动器的 PWMA 引脚**，TB6612 再控制电机转动。编码器是电机上的反馈传感器，信号走 TIM3，跟 FPGA 没关系。

**为什么用 SPI：** SPI（串行外设接口）速率高（本项目用几 MHz），推一帧 2 字节远小于 1ms 的控制周期，不会拖慢控制循环。FPGA 这边在 VHDL 里写一个 SPI Slave（从设备）状态机也简单直接。另外本项目 SPI2 是单向写（STM32→FPGA），FPGA 不需要回传数据，MISO（主入从出）线实际上可以不接。

### 2）连接 Memory（W25Q64 NOR Flash（NOR型闪存））

这里的 memory 是 NOR Flash（NOR型闪存），非易失性存储，断电后数据不丢失。用于保存 PID 参数，上电后自动加载。

**存储原理（浮栅晶体管）：**

NOR Flash 的基本存储单元是**浮栅 MOSFET（Floating Gate MOSFET，浮栅场效应管）**。浮栅是一层被 SiO₂ 绝缘层包裹的多晶硅，完全与外部电隔离。靠浮栅里困住的电子数量来记录数据：
- 浮栅里有大量电子 → 管子阈值电压高 → 读不通 → 逻辑 0
- 浮栅里没有电子 → 阈值电压低 → 读得通 → 逻辑 1（擦除后默认状态）

**三种操作：**

- **擦除（按块）**：施加高压，通过 **Fowler-Nordheim 隧穿（FN隧穿）** 使浮栅里的电子穿过薄氧化层隧穿出去，单元恢复到全 0xFF（全 1）状态。NOR Flash 按块（sector，扇区）擦除，不能单字节擦除。

- **写入（编程）**：写入前目标地址必须是 0xFF（全 1），因为写入只能把 1 改成 0（往浮栅注入电子），不能把 0 改回 1（那是擦除做的事）。机制是**热电子注入（Channel Hot Electron Injection，沟道热电子注入）**：漏-源电场把电子加速到高能量，飞过氧化层注入浮栅，阈值电压升高，该位变 0。

- **读取（随机读）**：字线（Wordline，行选择线）拉高选中行，灵敏放大器测量单元管子是否导通，根据电流大小判断 0 或 1。NOR Flash 支持随机字节读取，这是它和 NAND（NAND型闪存）的主要区别（NAND 只能按块/页读取）。

**为什么用 SPI：** W25Q64 本身就是标准 SPI 接口的芯片，SPI 的速率对断电保存 PID 参数这种低频操作绰绰有余。

## I2C（集成电路总线）

I2C（集成电路总线）连接 OLED 屏幕（SSD1306），传输运行中的数据（RPM（转速）/Duty（占空比）/Current（电流））到屏幕显示。

**为什么用 I2C：** OLED 是低速显示设备，不需要 SPI 的高速，而 I2C 只需要 **2 根信号线**，相比 SPI 的 4 根更省线。

**两根线的含义（常见误区）：**

I2C 的两根线是：
- **SCL（Serial Clock Line，串行时钟线）**：时钟线，由 Master（主设备，STM32）控制节拍
- **SDA（Serial Data Line，串行数据线）**：数据线，**地址也通过这根线传**

目标设备的选择不是靠"第二根线"实现的。Master（主设备）在每次通信开始时先通过 SDA（串行数据线）发送一个 **7-bit 从机地址**，总线上所有设备都能听到，地址匹配的设备回 ACK（应答信号），其余设备忽略。SCL（串行时钟线）只是时钟，不负责寻址。

**工作模式：** I2C 是**半双工**，不是单工。SDA（串行数据线）这根线可以双向传输：Master（主设备）发命令/数据给 Slave（从设备），Slave 也可以通过 SDA 回传数据给 Master。只是同一时刻只能一个方向传，不能同时收发。

**硬件特点：** SCL（串行时钟线）和 SDA（串行数据线）都是**开漏（Open-Drain）**输出，需要外部上拉电阻（本项目 PB6/PB7 配置了开漏+上拉）。这样多个设备挂在同一总线上不会短路。

**SSD1306：** 是 Solomon Systech 出的 OLED 显示控制器芯片，I2C 地址固定为 0x3C（由 SA0 引脚决定）。`OLED_Init()`、`OLED_ShowStr()` 本质上都是通过 I2C 向 SSD1306 发命令和数据，SSD1306 再去驱动对应像素点亮灭。
