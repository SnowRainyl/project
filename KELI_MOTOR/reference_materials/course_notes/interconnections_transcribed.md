## Page 1 - Delays

# Delays

## Skew

```text
t_k = t_max - t_min
```

- 图中标注：
  - `t_max` 处有 `t_2 - t_0`，旁边写有类似 `the V_IH`。
  - `t_min` 处有 `t_1 - t_0`，旁边写有类似 `the V_IL`。
- Skew 说明：
  - Greater with larger cables.
  - Affected by noise.

## Delay expressed as

```text
t_d = t_p ± t_k/2
```

- `t_p` 标注为 propagation AVG（平均传播延迟）。

## Parallel vs Serial

### Parallel

```text
word of n bits -> n // wires + 1 clock
```

### Serial

```text
single bits + clock on 1 wire
```

## Limitations on Frequency

- FF have `t_su + t_h` @ Rx.
- With no delays & perfect synch:

```text
t_CLK > t_su + t_h
f_CLK < 1 / (t_su + t_h)
```

## Worst Case for Setup

手写公式大意如下：

```text
t_d^clk  = t_pc - t_k/2
t_d^data = t_p[?] + t_k/2

t_1^Rx = t_1^Tx + t_d^clk - t_d^data
       = t_1^Tx - t_k

=> f_CLK < 1 / (t_su + t_h + 2t_k)   for Parallel
```

### 图示说明

右下角画了时序图：多条水平波形分别表示 `clkTx`、`dataTx`、`clkRx` 等信号，虚线竖线表示边沿到达时刻；数据区域用交叉阴影表示不确定/转换区；底部标注了 worst case for Rx 的采样窗口。图意是：由于 clock 和 data 传播延迟及 skew，接收端的有效采样窗口缩小，因此并行链路的最大时钟频率需要额外考虑 `2t_k`。

## Page 2 - Clock Generation / Synchronous Protocols

# Clock Generation

- @ Tx side -> transmitted to Rx with dedicated wire -> skew
- @ Rx side -> transmitted to Tx with dedicated wire -> skew & Tx delay
- Embedded, CDR, generated by Tx:
  - periodically
  - continuously
- Iso-frequential: Tx & Rx have separate free-running clocks, periodically synced.

# Asynchronous Protocol

```text
Asynchronous P. -> UART (later)
```

# Synchronous

- Char oriented (`k ~ n` bits):
  - char synch by special bit seq.
- Bit oriented protocols:
  - any length
  - start of msg identified by special sequence
  - synch by:
    - encoding violations
    - known sequences
- Clock Recovery:
  - use transition of the data signal:
    - in each bit (signal carrier)
    - periodically

# Synch Protocols

## NRZ

### NRZ-L

```text
1 : H
0 : L
```

### NRZ-M / Mark Inversion

```text
1 : transition
0 : no transition
```

### NRZ-S / Space Inversion

```text
1 : no change
0 : transition
```

- Does not guarantee transitions.
- Bandwidth:

```text
f_max = f_clk / 2
```

## RZ

### Unipolar

```text
1 : high pulse
0 : low state
```

旁边画了一个短高脉冲和一条低电平直线。

### Bipolar

```text
1 : high pulse
0 : low pulse
```

- Transitions guaranteed in Bipolar.
- `f_max` 标注接近 `f_clk`。

## Page 3 - Encoding Schemes / Forcing Transitions

## AMI RZ

Alternate Mark Inversion RZ:

```text
1 : alternate high/low pulse
0 : no pulse
```

- 旁边画了正负交替的脉冲。
- Transition not guaranteed.
- `f_max = f_clk / 2`
- `Ø DC avg`（无直流平均分量）。

## Dicode RZ

```text
each input transition generates output pulse with alternate polarity
no input transition -> stable output
```

## DUBIN / Dicode NRZ

```text
each input transition generates an output transition with alternate polarity
no input -> stable output
```

- Transitions not guaranteed.
- `f = f_clk / 4`（手写为类似该形式）。

## Multilevel Transmission Encoding - MLT

```text
0 : no change
1 : output transition with alternate polarity
```

- No transitions guaranteed.
- `f_max = f_clk / 4`
- 标注：Ethernet.

## Manchester

```text
1 : L to H
0 : H to L
```

- From NRZ-L:

```text
Data XOR Clock
```

- Guaranteed transitions.
- `f_max = f_clk`

## Frequency Modulation

```text
1 : transition @ beginning of bit, followed by transition in the middle
0 : transition in the middle
```

- ModFM:

```text
1 / 0 inverted
```

- ModModFM: 手写旁注类似 `Manchester` / `[不清]`。
- Transitions guaranteed.
- `f_max = f_clk / 2`

# Forcing Transitions

## nB/yB encoding

```text
n-bit block replaced by y-bit block
```

- deterministic
- fixed overhead

## Bit Stuffing

```text
Insert dummy bit after certain # of equal bits
```

- non-deterministic
- data-dependent

## Page 4 - nB/yB / Bit Stuffing / UART

## nB/yB

```text
Redundancy used for:
- transitions every n bits
- DC removal
- control codes
```

Example: `4b5b`

```text
4-bit input -> 5-bit output, LUT for Tx
5-bit input -> 4-bit output, LUT for Rx
```

## Bit Stuffing

```text
after n bits (usually 5-8) that don't change,
insert a bit that causes transition
```

- Rx and Tx re-synch @ transition.
- Don't always need to insert -> lower overhead.
- FSM @ Rx and Tx.

# Asynch Protocols

## UART

- Point to Point, Serial, Isofrequential independent clocks.
- Two serial wires:

```text
B1 -> B2 + GND
B1 <- B2
```

- Periodic synchronization of clock.
- Character based; each transmission / frame:

```text
start bit
n bits LSB first
parity
stop 1 or 2
```

右侧小图标注：

```text
low -> start bit
high -> idle
synch phase [?]
```

- Baud Rate / BR:

```text
BR = f_clk
```

常见值手写列举：

```text
300, 1200, 2400, 4800, 9600, 19200, 28800, ...
```

- `n = 6, 7, 8, 9` usually.
- Parity symbols:

```text
N : no parity
E : even
O : odd
M : mark
S : space
```

- NRZ encoding.
- BitRate:

```text
BitRate = n / (n + overhead) * f_clk
```

> **[本项目 — UART]**: 使用 USART2，PA2(TX) / PA3(RX)，配置 **115200 8N1**（8 bit数据、无奇偶、1位停止），对应课程的 n=8、N parity、stop=1。
> 板载 ST-Link VCP 链路损坏，改用外部 **CH340G USB-TTL 模块**接 PA2/PA3，属于典型的点对点异步串口。
> BRR 寄存器计算：APB1 = 42MHz，USARTDIV = 42MHz / (16 × 115200) = 22.786，BRR = 0x16D。
> 主循环每 200ms 轮询接收串口命令（save/load/show/set），符合课程"isofrequential independent clocks，periodic sync"的定义——双方各自用自己的时钟，靠 start bit 对齐。

- When `t_w = 0` -> no tx possible.
- With ideal rising/falling edges:

```text
f_clk < 1 / (t_su + t_h)
t_bit > t_su + t_h
```

### 图示说明

页下方画了一个接收窗口/眼图：纵轴标出 `V_OH`、`V_OH - NM`、`V_IH`、`V_IL`、`V_IL + NM`、`V_OL` 等电平；横向六边形窗口表示有效数据区，中间有 `t_w`，两侧标有 `t_su` 和 `t_h`，顶部/底部虚线表示噪声裕量和阈值。图意是：UART 接收端需在数据稳定窗口内采样，过大的边沿不确定性会使 `t_w` 变小。

## Page 5 - Synch Protocols: SPI & I²C / SPI

# Synch Protocols

## SPI & I²C

- Used to connect ICs on:
  - same board
  - different boards, short comm.
  - network of several nodes
- Masters & Slaves can be Tx or Rx.
- Serial Protocols: 1 wire for data.
- Synch: have separate wire -> skew.
- Multiple nodes can drive same wire.
- 100s of Kb to Mb/s.
- Communication always between M and S; M can initiate tx.
- Full Duplex or Half.
- Arbitration between Masters; Addressing for slaves.

# SPI

- 1 Master, Multiple slaves (up to 4, 5 usually).
- Full Duplex.

## Wires

```text
MOSI
MISO
SPICLK
[SPISS] : 0 or up to 1 per slave
```

- M and S always both Tx & Rx.
- Data discarded if not needed.

## Transmission

```text
NRZ
n bits
```

- `SPICLK` idle when no tx:

```text
CPOL = 0 -> low idle
CPOL = 1 -> high idle
```

- Slave Select active during all tx.
- Master generates `n` clock cycles.
- First clock edge -> beginning tx.
- MSB first data.
- Data changes on one clock edge and is sampled on the other.

```text
CPHA = 0 -> data on trailing
CPHA = 1 -> data on leading
```

- No need for arbitration since 1 master.
- Addressing not needed since SPISS selects and avoids conflicts.
- Slow slave cannot stop master.

> **[本项目 — SPI × 2]**: 项目使用了两条独立 SPI 总线，都是 1 Master（STM32）+ 1 Slave，Full Duplex：
>
> **SPI1 → W25Q64 Flash（PA4~PA7）**
> - CPOL=0, CPHA=0（Mode 0）：SCK 空闲低电平，数据在上升沿采样
> - CS 由 PA4 GPIO 软件控制（Software NSS）
> - 用途：存储 PID 参数，断电持久化
>
> **SPI2 → FPGA AX309（PB12~PB15）**
> - CPOL=0, CPHA=0（Mode 0）
> - CS 由 PB12 GPIO 软件控制
> - 单向写：STM32 每 1ms 发 2 字节，拼成 12-bit 占空比，FPGA 收到后驱动 PWM
> - MISO 线（PB14）可以不接，因为 FPGA spi_slave.vhd 硬编码 MISO=0，不回传数据
>
> 两路 SPI 的 SPISS（片选）都用独立 GPIO 实现，符合课程"SPISS selects slave, avoids conflicts"的描述。

## Page 6 - I²C

# I²C

- Multiple Masters.
- Up to 128 slaves (7 bits).
- 手写旁注：counts can extend with 10 bits.

## Wires

```text
2 wires + GND:
SCLK
SDATA
```

- Half duplex.
- Skew problem.
- Speed:

```text
100 ~ 4 Mbps
```

## Logic Levels / Open Drain

```text
Logic 0 : line to GND
1       : Toff -> float
          pull-up brings to Vcc
```

- Idle -> both high.

## Collision

```text
Node 1 produces 0
Node 2 produces 1
=> Node 2 notices and stops
```

- On `SCLK` -> clock stretching.
- On `SDATA` -> arbitration.

## Addresses

```text
only for slaves, often hardwired
```

右侧画了一个 I²C slave 芯片引脚示意，标注：

```text
GND, SDATA, SCL, NC
A0, A1, A2, VCC
```

## Transmission

```text
START config:
while clock high, Master drives data low
(violation) x 1 bit
```

```text
7 bits x Address, MSB first
Data changes only when clock low
```

```text
R/W bit
1 -> Read
```

```text
ACK:
ok -> Slave drives data low
```

```text
8 bits x data
1 bit x ACK
```

ACK 生成者：

```text
if write -> generated by Slave
if read  -> generated by Master
```

旁注：

```text
0 -> ok / ready for more data
1 -> no more data
```

Stop：

```text
SDATA low while SClock high
```

Re-Start：

```text
Need to address again
```

## Arbitration

```text
first master to send 0 wins
```

- Open drain avoids damages.

> **[本项目 — I2C]**: 使用 I2C1，PB6(SCL) / PB7(SDA)，驱动 **SSD1306 OLED 屏**（0.96寸，128×64）。
> - 从机地址 **0x3C**（7-bit，硬件固定），符合课程"addresses often hardwired"
> - PB6/PB7 配置为开漏输出 + 上拉（AF4），对应课程 Open Drain 结构：输出 0 时拉低，输出 1 时释放由上拉电阻拉高
> - 项目只向 OLED 写数据（发命令/像素），不需要读，属于 Half Duplex 单向写
> - 每次写操作：START → 地址(0x3C)+W → ACK → 控制字节(0x00命令/0x40数据) → ACK → 数据字节 → ACK → STOP，完整匹配课程帧格式
> - 踩过一个坑：I2C 事务后不能关闭 PE（外设使能），否则 AF 标志残留，下次 START 无法发出，导致 OLED 卡死——修复方式是保持 PE=1，事务结束后只清除错误标志（AF/BERR/ARLO/OVR）

### 图示说明

页中右侧画了 I²C 总线开漏结构：两条总线通过上拉电阻连接到 `Vcc`，节点内部有读/写控制、collision detect 以及下拉晶体管；节点将时钟线和数据线拉低表示 `0`，释放线路后由上拉电阻拉高表示 `1`。该图同时说明了总线冲突检测和开漏避免损坏的原理。

# CAN

Controller Area Network.

- Encode info as voltage difference between line 1 and 2 with respect to GND.
- Twisted pair cables -> less noise.

## Wires

```text
2 wires + GND:
CANH
CANL
```

## Clock / Encoding

- Embedded Clock, CDR.
- NRZ encoding.
