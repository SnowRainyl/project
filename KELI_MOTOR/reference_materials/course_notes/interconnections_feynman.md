# 互连接口全解——费曼教学法

> 一句话定位：把数字信号从芯片A送到芯片B，路上会出什么问题、怎么解决、不同协议各用了什么方案。

---

## 一、传信号路上会出什么问题：延迟与偏斜

**大局观**：电信号在导线里传播不是瞬间的，有速度，有"到达时间差"。数字系统里所有的时序问题，根源都在这里。

### 传播延迟（Propagation Delay）

想象你在高速公路上同时出发了两辆车：时钟信号和数据信号。它们走的路不一样长，到达目的地的时间就不同。这个"晚到的那个到达时刻"就是传播延迟 t_p。

实际用的是平均值：

```
t_d = t_p ± t_k/2
```

t_p 是平均传播延迟，t_k 是下面要说的偏斜。

### 偏斜（Skew）

**一句话**：同时出发的多条信号线，因为物理路径长度不同，到达时间不一样，这个"最晚到"和"最早到"之间的差就叫偏斜。

```
t_k = t_max - t_min
```

类比：你发了8封信给8个朋友（8位并行数据），同时寄出，但因为每个人住的距离不同，收到的时间不一样。接收方必须等最晚的那封到了才能把8封信当成一个完整的字读出来。

两个加剧偏斜的因素：
- 导线越长，t_k 越大（所以板间并行通信很难做快）
- 噪声干扰也会影响信号边沿的到达时刻

### 偏斜如何限制时钟频率

这是真正的重点，也是为什么并行总线被串行总线替代的核心原因。

**理想情况（没有延迟，完美同步）**：  
接收端的触发器（FF）需要在数据稳定后留出建立时间（t_su）和保持时间（t_h），所以：

```
t_CLK > t_su + t_h
f_CLK < 1 / (t_su + t_h)
```

**实际情况（有偏斜）**：  
时钟线也有偏斜，数据线也有偏斜。最坏情况下，时钟"提前到"但数据"晚到"，有效采样窗口被两边压缩了。推导结果：

```
f_CLK < 1 / (t_su + t_h + 2·t_k)   ← 并行总线的实际上限
```

**用更直白的话说**：

没有偏斜时，时钟周期只需要留够建立时间+保持时间的余量：
```
T_min = t_su + t_h
```
有偏斜时，时钟可能提前 t_k 到，数据可能推迟 t_k 才稳定，所以必须把周期再延长 2t_k 才能保证最坏情况下数据也来得及稳定：
```
T_min = t_su + t_h + 2t_k
```
线越长 → t_k 越大 → 2t_k 越大 → 频率上限越低。

**结论**：偏斜越大，频率上限越低。并行总线要做高速，必须让每条线等长布线，工程上极难，于是大家转向串行总线（1根数据线没有偏斜问题）。

### 并行 vs 串行

| | 并行 | 串行 |
|---|---|---|
| 数据线 | n根（一次传n bit） | 1根（一次传1 bit） |
| 时钟线 | 1根 | 1根（或嵌入） |
| 速度瓶颈 | 偏斜限制频率 | 无偏斜，频率可以很高 |
| 典型场景 | 短距板内总线（老式） | 现代高速通信（SPI/I2C/USB/PCIe） |

## 二、时钟从哪里来：同步问题的根源

**大局观**：接收端要正确采样数据，必须知道"什么时刻采"。这个"节拍"就是时钟。时钟可以有四种来源，不同协议选了不同方案，各有代价。

### 四种时钟方案

#### 方案1：发送端生成，专用时钟线传到接收端
发送方自己有晶振，生成时钟，用一根专线把时钟也送过去。  
**问题**：时钟线和数据线走不同路径，到达时间不同——又是偏斜。SPI、I²C 都用这种方案，所以它们是"同步协议"，但也有偏斜问题。

#### 方案2：接收端生成，传回发送端
接收方有自己的时钟，反向送给发送方让它同步。  
**问题**：往返传输引入了额外延迟，而且发送方要等接收方的时钟才能开始发。

#### 方案3：嵌入式时钟，时钟恢复（CDR，Clock and Data Recovery）
时钟不单独传，而是"藏在"数据信号的跳变里。接收端通过检测数据的跳变边沿来恢复时钟。  
**好处**：省掉时钟线，没有时钟偏斜。  
**代价**：必须保证数据足够频繁地跳变，否则接收端失去同步——这正是为什么需要"编码方案"（下一节）。CAN 协议用这种方式。

#### 方案4：等频独立时钟（Isofrequential），周期性同步
发送方和接收方各自有独立时钟，标称频率相同，但有误差（比如都是 115200 Hz 但有百万分之几的偏差）。双方靠"特殊序列"周期性地对齐时钟。  
**UART 就是这种**：双方约定好波特率，靠 start bit 的下降沿对齐，每帧重新同步一次。

### 同步协议 vs 异步协议

| | 同步（Synchronous） | 异步（Asynchronous） |
|---|---|---|
| 时钟 | 发送方显式提供时钟线 | 双方约定好频率，靠特殊位对齐 |
| 代表 | SPI、I²C | UART |
| 速度 | 更快（时钟线随时可读） | 较慢（频率容忍度有限） |

## 三、数据怎么编码：线路编码方案

**大局观**：如果直接把0/1对应低/高电平发出去，连续发很多个0或很多个1时，信号一直不变，接收端就失去了时钟同步（对于嵌入式时钟系统）或者产生直流偏移（影响电容耦合的系统）。所以需要编码，**目的只有一个：保证足够频繁的跳变**。

### NRZ（Non-Return-to-Zero，不归零码）

信号在一个比特周期内保持电平，不"回到0"。

#### NRZ-L（电平编码）
最直白的方案：
```
1 → 高电平
0 → 低电平
```
**问题**：连续 0 或连续 1 没有跳变，接收端失去同步。  
**带宽**：f_max = f_clk / 2（每两个时钟周期最多一次跳变）

#### NRZ-M（Mark 反转）和 NRZ-S（Space 反转）
```
NRZ-M：遇到1就翻转，遇到0不变
NRZ-S：遇到0就翻转，遇到1不变
```
**问题**：连续 0（对NRZ-M）或连续 1（对NRZ-S）还是没有跳变，仍然不保证跳变。

### RZ（Return-to-Zero，归零码）

每个比特周期内，信号会回到0（低电平）。

#### 单极性（Unipolar RZ）
```
1 → 高脉冲（半个周期高，半个周期归零）
0 → 全低
```
**问题**：连续 0 没有跳变。

#### 双极性（Bipolar RZ）
```
1 → 正脉冲
0 → 负脉冲
```
**优点**：每个比特都有跳变（归零时必然经过零）。**保证跳变。**  
**代价**：需要双极性电源，硬件复杂，带宽 f_max ≈ f_clk。

### AMI RZ（交替标志反转）

```
1 → 交替出现正脉冲/负脉冲（奇数个1用正，偶数个1用负）
0 → 无脉冲（零电平）
```
**优点**：无直流分量（正负平衡）。  
**问题**：连续 0 没有跳变。  
**带宽**：f_max = f_clk / 2

### Manchester 编码（最重要，嵌入式时钟的标准答案）

**核心思想**：每个比特周期中间强制一次跳变，把时钟"藏在"数据里。

```
1 → 低到高（↑）
0 → 高到低（↓）
```

等价于：`编码输出 = 原始数据 XOR 时钟`

**优点**：每个比特周期中间都有跳变，接收端永远不会失去同步。**保证跳变。**  
**代价**：带宽翻倍——f_max = f_clk（因为每个比特要表示两个电平状态，频率加倍）。  
**应用**：以太网（10Base-T）、CAN 的内部某些层。

### 强制产生跳变的两种补充方法

前面的编码方案是从信号波形层面保证跳变。还有两种从"数据流"层面强制跳变的方法：

#### nB/yB 块编码
```
把 n 位原始数据替换成 y 位编码输出（y > n）
```
查表（LUT）实现，发送端用一张表把输入映射到输出，接收端用逆表还原。

**例：4b5b**（USB、100Base-TX 使用）
```
4-bit 输入 → 5-bit 输出（发送端查表）
5-bit 输入 → 4-bit 输出（接收端查表）
```
多出的 1 bit 用于保证编码后的序列足够频繁地跳变，同时可以插入控制码（比如帧起始/结束标记）。  
**特点**：开销固定（4:5 = 20% 开销），确定性的。

#### 位填充（Bit Stuffing）
```
连续出现 n 个（通常5~8个）相同的位后，强制插入一个相反的位
```
发送端和接收端都运行一个状态机，接收端收到后把填充位剔除还原原始数据。

**类比**：写代码时约定"如果连续5个分号，就在第6位插一个逗号，防止解析器误判"。

**特点**：开销不固定（数据模式决定要不要填充），适合数据内容不固定的场景。CAN 使用 5-bit 位填充。

## 四、UART——最简单的异步协议

**大局观**：两台设备之间，约定好波特率，靠 start bit 对齐时钟，逐帧传字符。没有时钟线，没有主从关系，是最简单的点对点通信。

### 帧结构（每次传一个字符）

```
[空闲=高] → [start bit=低] → [数据位 n 个，LSB先] → [奇偶校验，可选] → [stop bit=高]
```

关键细节：
- **start bit 就是一个 0（低电平）**，接收端检测到高→低跳变就知道一帧开始了，用这个边沿对齐时钟
- 数据位通常 8 位（8N1 = 8位数据、无校验、1位停止）
- stop bit 是高电平，确保下一帧的 start bit 有跳变可以被检测到

### 波特率与采样

双方约定同一个波特率（比如 115200）。接收端收到 start bit 后，以波特率为节拍，在每个位周期的中间采样，而不是边沿采样——这样对时钟漂移最有容忍性。

```
BitRate = n / (n + 帧开销) × f_clk
```

常见值：9600、19200、115200、921600……  
**本项目**：115200 8N1，APB1=42MHz，BRR=0x16D。

### 关键约束

```
t_bit > t_su + t_h
```

即每个位持续时间必须大于触发器的建立+保持时间，这限制了最高波特率。

## 五、SPI——同步主从全双工

**大局观**：1个主设备（Master）控制通信节拍，最多4~5个从设备（Slave），主从同时收发（全双工）。4根线，简单直接，速度快（几十 MHz）。

### 四根线的分工

```
MOSI（主出从入）：Master → Slave 的数据线
MISO（主入从出）：Slave → Master 的数据线
SPICLK（时钟）：由 Master 产生
SPISS（片选）：Master 拉低激活对应的 Slave
```

Master 和 Slave **同时**发送和接收数据，就像两个人互换礼物——A 把礼物给 B 的同时，B 也把礼物给 A，不管有没有用，每次通信都是双向的。用不上的数据直接丢掉。

### CPOL 和 CPHA：时钟的"性格"

CPOL（时钟空闲极性）：
```
CPOL=0 → 空闲时 SCK 是低电平
CPOL=1 → 空闲时 SCK 是高电平
```

CPHA（数据采样沿）：
```
CPHA=0 → 在后沿（trailing edge）采样
CPHA=1 → 在前沿（leading edge）采样
```

两两组合得到 Mode 0~3。**本项目两路 SPI 都用 Mode 0（CPOL=0, CPHA=0）**：SCK 空闲低，数据在上升沿采样。

### 为什么不需要仲裁和寻址

- **不需要仲裁**：只有1个 Master，不存在两个 Master 同时抢总线的情况
- **不需要地址**：每个 Slave 有独立的 SPISS（片选）线，Master 拉低哪根就跟哪个通信，不用在数据里写地址

**代价**：从设备多了就要多根片选线（4个从设备就要4根 SPISS + MOSI + MISO + CLK = 7根线）。

## 六、I²C——同步多主多从，两根线走天下

**大局观**：只有 SDA（数据）和 SCL（时钟）两根线，却可以挂最多 128 个从设备（7-bit 地址）。靠**开漏电路**实现多设备共享总线而不短路，靠**地址帧**选中目标设备。

### 开漏（Open-Drain）：多设备共享一根线的物理基础

这是 I²C 能实现多设备的关键，必须理解。

每个设备的输出是这样的：
- 想输出 **0（低电平）**：内部晶体管导通，把线直接拉到 GND
- 想输出 **1（高电平）**：内部晶体管关闭，**什么都不驱动**，线"浮起来"，由外部上拉电阻拉到 VCC

**为什么这样能防短路**：如果一个设备输出 0（拉到 GND），另一个设备输出 1（不驱动），线上的电压由拉低的那个设备决定 → 结果是 0。没有两个设备硬碰硬的情况，不会短路。

这是"线与（Wired-AND）"逻辑：任何一个设备拉低，总线就是 0；所有设备都释放，总线才是 1。

### 总线仲裁：谁先发 0 谁赢

当多个 Master 同时想发数据（多主场景），这样判断谁优先：  
每个 Master 在发出每个 bit 后，立刻读回总线电平。如果我发了 1（释放总线）但总线读回来是 0，说明有另一个 Master 在拉低总线——我输了，立刻停止发送。**第一个发 0 的赢**（因为 0 压制 1）。

类比：两个人同时对着麦克风说话，谁先说"静音"，声音就被压下去了。

### 一次完整的通信帧

```
START → [7位从机地址] → [R/W位] → [ACK] → [8位数据] → [ACK] → … → STOP
```

逐步拆解：

**START 条件**：SCL 高时，SDA 从高变低。这是一个"违规"——正常传输时数据只在 SCL 低时才能变化，所以这个违规被当作起始信号。

**地址阶段**：Master 发出 7 位从机地址 + 1 位 R/W（0=写，1=读），MSB 先。所有 Slave 都听到了，地址匹配的那个回 ACK。

**ACK（应答）**：接收方拉低 SDA 一个 SCL 周期，表示"收到了，准备好了"。没有 ACK（SDA 保持高）= NACK，表示出错或数据接收完毕。

- 写数据时：ACK 由 Slave 发
- 读数据时：ACK 由 Master 发（告诉 Slave"继续发"），NACK 表示"停了，够了"

**STOP 条件**：SCL 高时，SDA 从低变高。同样是违规，作为结束信号。

**本项目**：I2C1，PB6(SCL)/PB7(SDA)，驱动 SSD1306 OLED（地址 0x3C）。每次写：START → 0x3C+W → ACK → 控制字节 → ACK → 数据字节 → ACK → STOP。

## 七、CAN——差分总线，广播式，工业级抗噪

**大局观**：两根线（CANH、CANL），靠两者的**电压差**传数据，而不是靠单根线的绝对电平。这样外部噪声会同时加在两根线上，相减之后抵消了，抗噪能力极强。

### 差分信号：噪声的克星

普通信号：用线上绝对电压（0V=0，3.3V=1）  
差分信号：用两根线的电压差（CANH - CANL > 阈值 = 1，< 阈值 = 0）

类比：两个人手拉手测温度，测的不是各自体温，而是两人体温的**差值**。如果外部环境温度变化（噪声），两人同时受影响，差值不变。

```
Dominant（显性，逻辑0）：CANH ≈ 3.5V，CANL ≈ 1.5V，差值 ≈ 2V
Recessive（隐性，逻辑1）：CANH = CANL ≈ 2.5V，差值 ≈ 0V（浮空）
```

和 I²C 一样：**Dominant（0）压制 Recessive（1）**，谁先发 0 谁赢仲裁。

### 时钟：嵌入式，靠跳变恢复

CAN 没有时钟线，时钟嵌在数据跳变里（CDR）。但如果数据长时间不变，就没有跳变可以恢复时钟——所以 CAN 用**位填充**：连续 5 个相同的位后插入 1 个相反的位，强制产生跳变。

同步：每次检测到从 Recessive→Dominant 的跳变，所有设备重新同步时钟。

### 寻址：发的是消息 ID，不是目标地址

CAN 和 I²C/SPI 的寻址方式完全不同：
- I²C/SPI：地址是"我要和谁说话"
- CAN：ID 是"这条消息是什么类型"，**所有设备都会收到**，每个设备自己判断要不要处理

```
11-bit ID（标准帧）或 29-bit ID（扩展帧）
ID 越小优先级越高（仲裁时先发 0 的赢）
```

### CAN 帧结构

```
SOF（帧起始，1个显性位）
→ ID（11位）
→ RTR（远程传输请求位）
→ IDE（帧类型位）
→ DLC（数据长度，4位，0~8）
→ Data（0~8字节）
→ CRC（15位校验）
→ CRC delimiter（1个隐性位）
→ ACK（Tx发隐性，Rx收到后拉显性确认）
→ ACK delimiter（1个隐性位）
→ EOF（帧结束，7个隐性位——这7个连续隐性位违反了位填充规则，专门用来标记帧结束）
```

## 总结对比

| 特性 | UART | SPI | I²C | CAN |
|------|------|-----|-----|-----|
| 时钟来源 | 等频独立（Isofrequential） | Master 提供 | Master 提供 | 嵌入式（CDR） |
| 时钟线 | 无 | 有（SPICLK） | 有（SCL） | 无 |
| 数据线数 | 2（TX+RX） | 2（MOSI+MISO） | 1（SDA，半双工） | 2（差分） |
| 全/半双工 | 全双工 | 全双工 | 半双工 | 半双工 |
| 主设备数 | 无主从（点对点） | 1个Master | 多个Master | 无主从（广播） |
| 从设备数 | 无主从 | ~4个（每个需1根SS线） | 128个（7-bit地址） | 多节点（ID区分） |
| 寻址方式 | 无（点对点） | SS线选择 | 地址字节 | 消息ID |
| 编码 | NRZ | NRZ | NRZ+开漏 | NRZ+位填充 |
| 典型速率 | ~1 Mbps | ~几十 Mbps | 100k~4 Mbps | ~1 Mbps |
| 典型用途 | 调试串口 | Flash、FPGA | OLED、传感器 | 汽车、工业总线 |
