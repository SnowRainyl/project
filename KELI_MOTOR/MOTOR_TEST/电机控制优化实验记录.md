# 电机控制优化实验记录

## 1. 文档目的

本文记录 `MOTOR_TEST` 工程从“电机可以转动”到“零位可靠停机、转速基本稳定、支持在线调参”的完整优化过程。

每个阶段按照以下顺序记录：

1. 实验现象
2. 原因分析
3. 下一步解决方案
4. 代码修改
5. 修改后的实验结果
6. 阶段结论

本文只选取有代表性的串口数据。完整实验数据保留在调试聊天和串口日志中。

---

## 2. 控制系统结构

当前系统采用串级 PID：

```text
电位器 ADC
    |
    v
目标转速 rpm_set
    |
    v
速度外环 PID
    |
    v
目标电流 iset
    |
    v
电流内环 PID
    |
    v
PWM duty
    |
    v
FPGA PWM -> 电机
```

反馈信号：

```text
编码器 -> 实际 RPM -> 速度外环
INA240 -> 实际电流 curr -> 电流内环
```

主要运行频率：

| 功能 | 当前频率 |
|---|---:|
| TIM6 控制中断 | 1 kHz |
| 电流采样及电流内环 | 1 kHz |
| 编码器测速及速度外环 | 100 Hz |
| 串口/OLED 刷新 | 约 5 Hz |
| FPGA PWM | 约 12.2 kHz |

## 3. 阶段一：零位仍有转速、占空比和电流

### 3.1 实验现象

电位器已经转到零位，但 OLED 和串口仍出现：

```text
RPM 在 0、5、10 附近交替
duty 在 2%～10% 波动
curr 可能为负值，也可能跳到几十 mA
电机时而转动、时而停止
```

代表性数据：

```text
RPM=5.0   duty=180 (4.4%)  adc=126  curr_raw=2337  curr=8.3mA
RPM=12.0  duty=408 (10.0%) adc=138  curr_raw=2251  curr=-3.3mA
RPM=1.5   duty=449 (11.0%) adc=128  curr_raw=2855  curr=70.5mA
```

### 3.2 原因分析

最初仅使用很小的 ADC 阈值判断电位器零位，而实际电位器零点会受噪声和偏置影响。

当系统仍运行串级 PID 时：

1. 电位器噪声产生非零目标转速。
2. 编码器低速量化产生跳变。
3. 电流零点噪声进入电流 PID。
4. PID 输出小占空比，电机被反复启动。

### 3.3 下一步解决方案

设计独立的启停状态，而不是只使用单一阈值：

- `ADC >= 350`：允许启动。
- `ADC <= 250`：进入停机。
- 250～350：保持之前状态，形成滞回。

停机时同时：

- 清空速度 PID。
- 清空电流 PID。
- 将目标电流设为 0。
- 将 duty 平滑降到 0。

### 3.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

增加参数：

```c
#define MOTOR_MIN_RUN_RPM       15.0f
#define MOTOR_STOP_ADC_MAX      250U
#define MOTOR_START_ADC_MIN     350U
#define DUTY_STOP_SLEW_PER_MS   4U
```

增加启停状态：

```c
static uint8_t motor_enabled = 0U;
```

停机处理：

```c
PID_Reset(&speed_pid);
PID_Reset(&current_pid);
g_current_setpoint_mA = 0.0f;

if (duty_applied > DUTY_STOP_SLEW_PER_MS) {
    duty_applied -= DUTY_STOP_SLEW_PER_MS;
} else {
    duty_applied = 0U;
}
```

### 3.5 修改后的实验结果

零位数据稳定为：

```text
RPM=0.0  duty=0 (0.0%)  adc=14  curr_raw=2047  iset=0.0mA  curr=0.0mA
RPM=0.0  duty=0 (0.0%)  adc=14  curr_raw=2048  iset=0.0mA  curr=0.0mA
```

`curr_raw` 仅在 2047～2048 之间变化，说明静止零点稳定。

### 3.6 阶段结论

零位误启动问题已基本解决。滞回避免了电位器在临界点附近反复启停，停机时清空 PID 避免了积分残留。

## 4. 阶段二：进入死区时电机骤停、机械卡顿

### 4.1 实验现象

加入死区后，电位器进入停止区域时 duty 立即变为 0，电机突然失去扭矩，体感上有明显卡顿。

### 4.2 原因分析

“可靠停机”和“平滑停机”是两个不同要求：

- 直接清零 duty 可以保证停机。
- 但 duty 瞬间从较大值跳到 0，会造成明显的机械冲击。

### 4.3 下一步解决方案

停机时不再立刻清零实际输出，而是：

1. 目标电流立即清零。
2. PID 状态立即复位。
3. 实际 duty 每 1 ms 最多下降 4 个计数。
4. duty 最终必须到达 0，不在死区内持续驱动。

### 4.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
#define DUTY_STOP_SLEW_PER_MS 4U
```

使用 `duty_applied` 保存当前实际输出，并逐步下降。

### 4.5 修改后的实验结果

进入死区后 duty 不再瞬间归零，机械冲击减小；最终串口仍能稳定显示：

```text
RPM=0.0  duty=0 (0.0%)  iset=0.0mA  curr=0.0mA
```

### 4.6 阶段结论

当前停机逻辑兼顾了平滑性和可靠性。后续若希望停机更快或更慢，只需调整 `DUTY_STOP_SLEW_PER_MS`。

## 5. 阶段三：电流值随机跳动

### 5.1 实验现象

电位器保持不动时，电流仍出现大幅变化：

```text
curr_raw=1966～3080
curr=3mA～108mA
```

而 RPM、ADC 和 duty 的变化没有与电流跳动形成稳定关系。

### 5.2 原因分析

FPGA PWM 频率约为 12.2 kHz，一个周期约 82 us。

如果每次只读取一个 ADC 点，采样可能随机落在：

- PWM 导通阶段
- 续流阶段
- 关断阶段

因此单点值不是稳定的平均电流，而是 PWM 波形某个随机相位的瞬时值。这属于异步采样混叠。

另一个问题是 PA0 电位器和 PA1 电流共用 ADC1。切换 ADC 通道后，内部采样电容可能保留上一个通道的电压。

### 5.3 下一步解决方案

分两步处理：

1. ADC 通道切换后，先做一次转换并丢弃。
2. 每次电流测量连续采样 192 点并取平均，使采样覆盖多个 PWM 周期。

### 5.4 代码修改

文件：`MDK-ARM/Src/adc_reg.c`

通道切换后丢弃第一次转换：

```c
if (ch != last_ch) {
    ADC1->CR2 |= ADC_CR2_SWSTART;
    while ((ADC1->SR & ADC_SR_EOC) == 0U) {
    }
    (void)ADC1->DR;
    last_ch = ch;
}
```

电流突发采样：

```c
#define ADC_CURR_BURST_SAMPLES 192U

for (i = 0U; i < ADC_CURR_BURST_SAMPLES; i++) {
    raw_sum += ADC1_ReadChannel(1U);
}
raw_avg = (float)raw_sum / ADC_CURR_BURST_SAMPLES;
```

192 点约覆盖 4.5 个 PWM 周期。

### 5.5 修改后的实验结果

中高速运行时 `curr` 仍存在纹波，但变化开始有范围，不再完全随机。例如稳定高速时：

```text
RPM=98.8～99.8
duty=60.7%～61.6%
curr 约 49mA～62mA
```

### 5.6 阶段结论

突发平均显著改善了电流显示，但它仍不是严格的 PWM 同步电流采样。

后续更好的方案是由 PWM 定时点触发 ADC，在固定 PWM 相位采样。

## 6. 阶段四：电流零点不准和自动校零

### 6.1 实验现象

最初使用固定零点电压换算电流，不同上电过程可能出现：

```text
duty=0，curr=27mA
duty=0，curr=73mA
```

### 6.2 原因分析

INA240 的 REF、电源误差、ADC 参考电压和器件偏置都会使实际零点偏离理论值。

固定使用 `1650mV` 或某次人工测得的值，无法适应每次上电的真实偏置。

### 6.3 下一步解决方案

上电时先确保 FPGA duty 为 0，等待模拟电路稳定，再采集 64 个零电流样本作为本次启动的零点。

### 6.4 代码修改

文件：`Core/Src/main.c`

```c
FPGA_CS_LOW();
SPI2_ReadWriteByte(0U);
SPI2_ReadWriteByte(0U);
FPGA_CS_HIGH();
HAL_Delay(100);
ADC1_CalibrateCurrentZero();
```

文件：`MDK-ARM/Src/adc_reg.c`

```c
for (i = 0U; i < ADC_CURR_ZERO_SAMPLES; i++) {
    zero_sum += ADC1_ReadChannel(1U);
}
s_current_zero_raw = (float)zero_sum / ADC_CURR_ZERO_SAMPLES;
```

### 6.5 曾尝试但撤销的方案

曾尝试在运行过程中检测 duty 为 0 后自动重新校零。

该方案被撤销，原因是：

- duty 已经为 0 时，电机可能仍在惯性旋转。
- 电机反电动势或续流电流仍可能存在。
- 此时校准会把非零电流误当作零点。
- 后续可能出现虚假的 100mA 以上偏置。

因此当前只在确认停机的上电初始化阶段校零。

### 6.6 修改后的实验结果

稳定静止时：

```text
curr_raw=2047～2048
curr=0.0mA
```

### 6.7 阶段结论

静态零点已经稳定。当前高速电流纹波主要不是零点漂移，而是 PWM 电流波形、采样相位和电流换算标定共同造成。

## 7. 阶段五：低速 RPM 跳变和电机一顿一顿

### 7.1 实验现象

最初每 1 ms 计算一次编码器速度，低速时 RPM 以较大台阶变化，速度 PID 输出随之快速变化，电机出现类似周期性加速和减速的顿挫。

### 7.2 原因分析

编码器输出轴每转计数：

```text
11 PPR * 4 倍频 * 34 减速比 = 1496 counts/rev
```

1 ms 内的计数太少。低速时常见情况是：

```text
本次 delta=0
下一次 delta=1
```

使用 1 ms 窗口换算后，一个计数对应很大的 RPM 台阶，速度反馈量化严重。

### 7.3 下一步解决方案

保持 TIM6 为 1 kHz，但把：

- 编码器测速降到 100 Hz。
- 速度外环降到 100 Hz。
- 电流内环继续保持 1 kHz。

这样速度统计窗口从 1 ms 增加到 10 ms。

### 7.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
#define SPEED_LOOP_DIVIDER 10U
```

每 10 次 TIM6 中断调用一次：

```c
Encoder_Update();
g_current_setpoint_mA =
    PID_Calc(&speed_pid, setpoint_rpm, g_encoder_rpm);
```

文件：`MDK-ARM/Src/encoder_reg.h`

```c
#define ENCODER_UPDATE_HZ 100U
```

文件：`MDK-ARM/Src/encoder_reg.c`

```c
raw_rpm = (float)g_encoder_delta
        * (60.0f * ENCODER_UPDATE_HZ)
        / ENCODER_COUNTS_PER_REV;
```

### 7.5 修改后的实验结果

RPM 最小变化约为 0.5 RPM，常见稳定数据为：

```text
98.8, 99.3, 99.8
```

而不是原先的 5 RPM 级跳变。

### 7.6 阶段结论

降低速度环频率是本次稳定性提升的重要基础。速度环不需要与电流环一样快，分层设置频率更符合串级控制结构。

## 8. 阶段六：限制 duty 变化速度

### 8.1 实验现象

电流采样纹波和速度误差会直接反映到 PID 输出，duty 快速变化，使电机产生扭矩冲击。

### 8.2 原因分析

即使 PID 输出瞬间变化很大，实际电机和机械系统也不需要在 1 ms 内完成同样大的占空比变化。

### 8.3 下一步解决方案

在 PID 目标输出与 FPGA 实际输出之间加入斜率限制：

```text
运行时每 1 ms 最多变化 2 个 duty 计数
停机时每 1 ms 最多下降 4 个 duty 计数
```

### 8.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
#define DUTY_SLEW_PER_MS      2U
#define DUTY_STOP_SLEW_PER_MS 4U
```

```c
if (duty_target > duty_applied + DUTY_SLEW_PER_MS) {
    duty_applied += DUTY_SLEW_PER_MS;
} else if (duty_target + DUTY_SLEW_PER_MS < duty_applied) {
    duty_applied -= DUTY_SLEW_PER_MS;
} else {
    duty_applied = duty_target;
}
```

### 8.5 修改后的实验结果

电机加减速过程明显平滑，duty 在高速稳态通常只在约 59%～61% 范围内缓慢变化。

### 8.6 阶段结论

duty 斜率限制有效降低了机械顿挫，但也会增加到达目标转速所需时间。后续调响应速度时，需要同时考虑速度 PID 和 duty 斜率限制。

---

## 9. 阶段七：`iset=0` 时 duty 仍保持旧值

### 9.1 实验现象

曾观察到：

```text
RPM=62.7  duty=1600  iset=0.0mA  curr=0.0mA
```

目标电流已经是 0，但 duty 长时间卡在 1600。

### 9.2 原因分析

电流 PID 使用位置式 PID。

电流负值被限制为 0 后，当：

```text
iset=0
curr=0
```

误差也是 0。此时电流 PID 中以前积累的积分不会自动消退，因此输出仍保持旧 duty。

### 9.3 下一步解决方案

当目标电流小于等于 0 时：

1. 复位电流 PID。
2. 直接令 duty 目标为 0。
3. 实际 duty 仍通过斜率限制平滑下降。

### 9.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
if (g_current_setpoint_mA <= 0.0f) {
    PID_Reset(&current_pid);
    duty_target = 0U;
} else {
    duty_target = (uint16_t)PID_Calc(
        &current_pid,
        g_current_setpoint_mA,
        measured_current);
}
```

### 9.5 修改后的实验结果

目标电流变为 0 后，duty 不再永久保持旧值，而会逐步下降。

### 9.6 阶段结论

该问题属于 PID 状态管理问题，不是 PID 参数问题。切换运行状态时必须明确处理积分状态。

---

## 10. 阶段八：增加可观测量

### 10.1 实验现象

最初串口只显示：

```text
RPM、duty、adc、curr_raw、curr
```

只能看到实测电流，无法判断电流内环到底在追踪什么目标。

### 10.2 原因分析

串级 PID 调试至少需要同时观察：

```text
目标转速
实际转速
目标电流 iset
实际电流 curr
duty
```

没有 `iset` 时，无法区分：

- 速度外环输出本身在跳。
- 电流内环没有跟随目标。

### 10.3 下一步解决方案

将速度 PID 输出导出为全局监控变量，并加入串口日志。

### 10.4 代码修改

文件：`Core/Inc/stm32f4xx_it.h`

```c
extern volatile float g_current_setpoint_mA;
```

文件：`Core/Src/stm32f4xx_it.c`

```c
volatile float g_current_setpoint_mA = 0.0f;
```

文件：`Core/Src/main.c`

```text
RPM=... duty=... adc=... curr_raw=... iset=...mA curr=...mA
```

同时主循环不再直接读取 ADC1 电流通道，而是读取中断已经采集好的 `g_motor_current_raw`，避免主循环与控制中断竞争 ADC。

### 10.5 修改后的实验结果

加入 `iset` 后，很快发现速度外环输出曾在：

```text
0mA～292mA
```

之间周期变化，从而确认主要振荡来源是速度外环，而不是电位器。

### 10.6 阶段结论

增加监控量是本次排障的关键步骤。控制系统调试不能只看最终 duty，必须观察每一层控制器的输入和输出。

---

## 11. 阶段九：速度外环严重振荡

### 11.1 实验现象

电位器固定在中档，ADC 基本稳定：

```text
adc=1886～1892
```

但实际数据为：

```text
RPM=46～58
iset=0～277mA
duty=29%～39%
```

电机转速在目标值两侧周期性来回变化。

### 11.2 原因分析

串口 `show` 最终发现实际运行参数为：

```text
speed kp=33.0
speed ki=0.1
```

Flash 中保存的旧参数覆盖了代码默认值。

`kp=33` 会把很小的 RPM 误差放大成很大的电流目标变化，使 `iset` 快速到达 0 或 400mA，形成明显振荡。

### 11.3 下一步解决方案

分阶段降低速度环参数：

| 阶段 | Kp | Ki | 结果 |
|---|---:|---:|---|
| Flash 旧参数 | 33.0 | 0.1 | 严重振荡 |
| 第一次保守调整 | 0.8 | 0.02 | 仍有低频摆动 |
| 第二次保守调整 | 0.4 | 0.005 | 稳定，但到达目标较慢 |
| 当前折中参数 | 0.8 | 0.01 | 响应较快且无明显振荡 |

### 11.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

当前默认值：

```c
PID_Init(&speed_pid,
         0.8f, 0.01f, 0.0f,
         0.0f, MOTOR_MAX_CURRENT_MA,
         40000.0f);
```

串口在线调参命令：

```text
set sp 0.8
set si 0.01
show
save
```

### 11.5 `0.4 / 0.005` 的实验结果

优点：

- 转速单调、平滑地接近目标。
- 没有周期振荡。

缺点：

- 从约 86 RPM 上升到 99 RPM 用时较长。
- `iset` 积分上升较慢。

最终稳定数据：

```text
RPM=98.8～99.8
duty≈61%
```

### 11.6 `0.8 / 0.01` 的实验结果

代表性数据：

```text
RPM=96.3  duty=59.6%  iset=222.8mA
RPM=97.3  duty=60.0%  iset=229.1mA
RPM=98.3  duty=60.7%  iset=231.1mA
RPM=99.3  duty=60.7%  iset=235.4mA
```

结果：

- RPM 平稳接近 100。
- 没有重新出现明显周期振荡。
- duty 稳定在约 59.5%～60.9%。
- 比 `0.4 / 0.005` 更快。

### 11.7 阶段结论

当前推荐速度 PID：

```text
Kp = 0.8
Ki = 0.01
Kd = 0
```

需要通过 `save` 写入 Flash，并在重新上电后使用 `show` 确认加载值。

## 12. 阶段十：串口在线调参失败

### 12.1 实验现象

发送：

```text
set sp 0.4
set si 0.005
show
```

系统反复返回：

```text
[PID] unknown cmd
```

但 `show` 可以识别。

### 12.2 第一层原因：浮点解析

原代码使用：

```c
sscanf(cmd, "set sp %f", &val);
```

Keil 当前 C 库配置可能没有启用 `scanf` 浮点支持，因此整数命令可以工作，带浮点参数的命令解析失败。

### 12.3 第一层解决方案

在 `Core/Src/main.c` 中增加轻量小数解析函数 `parse_float_arg()`，不再依赖 `sscanf("%f")`。

修改参数后同时调用：

```c
PID_Reset(&speed_pid);
```

避免新参数继续继承旧参数留下的积分。

### 12.4 第二层原因：接收字符丢失

加入失败回显后，发送：

```text
set sp 0.4
```

MCU 实际收到：

```text
s 0.4
```

说明命令前面的字符丢失。

原 UART 只轮询 USART2 的单字节接收寄存器。主循环发送长日志或 TIM6 执行较长 ADC 采样时，新的串口字符来不及读取，产生 ORE 溢出。

### 12.5 第二层解决方案

文件：`MDK-ARM/Src/uart.c`

增加 64 字节环形缓冲区：

```c
#define UART_RX_BUFFER_SIZE 64U
```

开启 USART2 RXNE 中断：

```c
USART2->CR1 =
    USART_CR1_TE |
    USART_CR1_RE |
    USART_CR1_RXNEIE |
    USART_CR1_UE;
```

USART2 ISR 将字节放入缓冲区，主循环通过 `UART_RecvChar()` 取出。

### 12.6 第三层原因：中断优先级

最初 USART2 中断优先级为 3，TIM6 为 2。

TIM6 可以阻塞 USART2，而 TIM6 内包含 192 点 ADC 采样，执行时间较长，仍可能造成串口接收丢字符。

### 12.7 第三层解决方案

提高 USART2 中断优先级：

```c
NVIC_SetPriority(USART2_IRQn, 1U);
```

当前优先级：

```text
USART2 = 1
TIM6   = 2
```

USART2 可以抢占 TIM6，及时保存收到的字节。

### 12.8 修改后的实验结果

命令成功执行：

```text
speed:   kp=0.4000 ki=0.0050 kd=0.0000
current: kp=5.0000 ki=0.2000 kd=0.0000
```

随后可以继续在线切换到：

```text
speed: kp=0.8000 ki=0.0100 kd=0.0000
```

### 12.9 阶段结论

串口命令问题由多个因素叠加造成：

1. `%f` 浮点解析不可靠。
2. 轮询接收容易丢字节。
3. USART2 中断优先级低于长时间控制中断。

当前三项均已处理。

## 15. 当前尚未解决的问题

### 15.1 `iset` 与 `curr` 数值差距较大

高速稳态时：

```text
iset≈240mA
curr≈55mA
```

二者没有在数值上接近。

这说明速度稳定并不代表电流内环已经完成标定。可能原因包括：

1. INA240 增益型号或分流电阻阻值配置不准确。
2. 电流换算单位或比例存在误差。
3. ADC 突发平均仍受 PWM 相位影响。
4. `iset` 的量程设计与实际电流量程不匹配。
5. 电流 PID 的积分、输出和 duty 斜率限制共同影响跟踪。

### 15.2 `curr_raw` 仍有明显瞬时波动

虽然滤波后的 `curr` 已有稳定范围，但 `curr_raw` 偶尔出现较大峰值。这符合 PWM 电流纹波特征，但仍需要同步采样验证。

### 15.3 目标转速尚未打印

目前已经打印实际 RPM 和 `iset`，但尚未打印 `rpm_set`。

调速度环时最好同时观察：

```text
rpm_set, RPM, iset, curr, duty
```

## 16. 下一轮实验计划

### 16.1 第一步：保存并验证速度 PID

串口输入：

```text
set sp 0.8
set si 0.01
show
save
```

重新上电后再次输入：

```text
show
```

确认 Flash 中保存的是 `0.8 / 0.01`。

### 16.2 第二步：增加目标转速打印

将 `rpm_set` 导出并加入日志：

```text
rpm_set=... RPM=... iset=... curr=... duty=...
```

目的：精确计算速度超调量、稳态误差和响应时间。

### 16.3 第三步：记录阶跃响应

不要连续缓慢转动电位器，而是进行固定档位阶跃：

1. 0 -> 中档
2. 中档保持 10 秒
3. 中档 -> 最高档
4. 最高档保持 10 秒
5. 最高档 -> 0

记录：

- 到达目标 90% 所需时间
- 最大超调量
- 稳态 RPM 波动
- duty 变化范围
- `iset` 变化范围
- `curr` 变化范围

### 16.4 第四步：校准实际电流

使用万用表或已知负载测量真实电流，与串口 `curr` 对比。

根据：

- INA240 实际型号和增益
- 分流电阻实际阻值
- ADC 实际参考电压

重新校准换算系数。

### 16.5 第五步：改为 PWM 同步采样

理想方案：

1. FPGA 或 MCU 提供固定 PWM 相位触发。
2. ADC 在每个 PWM 周期相同位置采样。
3. 再对多个周期做平均。

这会比当前“连续采 192 点”更准确，也能减少中断执行时间。

### 16.6 第六步：单独整定电流内环

在电流标定完成后，再调整：

```text
current kp
current ki
```

判断标准不是 RPM，而是：

```text
curr 是否快速、稳定地跟随 iset
```

速度环和电流环不要同时修改，否则无法判断效果来自哪一层。

## 18. 总结

本轮优化不是单纯“调 PID 参数”，而是依次处理了控制系统的基础问题：

```text
零位状态管理
-> 平滑启停
-> ADC 通道串扰
-> PWM 电流采样混叠
-> 上电电流零点校准
-> 编码器低速量化
-> 速度环与电流环分频
-> PID 积分状态管理
-> 关键变量可观测性
-> 速度 PID 整定
-> UART 在线调参可靠性
```

目前速度控制已经从明显振荡改善到最高档约 99 RPM 稳定运行。下一阶段的重点应从速度环转向电流测量标定和电流内环验证。
