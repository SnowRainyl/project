# 电机控制优化实验记录

## 1. 文档目的

本文记录 `MOTOR_TEST` 工程从“电机可以转动”到“零位可靠停机、转速基本稳定、支持在线调参”的完整优化过程。

每个阶段按照以下顺序记录：

1. 实验现象
2. 原因分析
3. 下一步解决方案
4. 代码修改
5. 修改后的实验结果
6. 阶段结论

本文只选取有代表性的串口数据。完整实验数据保留在调试聊天和串口日志中。

---

## 2. 控制系统结构

当前系统采用串级 PID：

```text
电位器 ADC
    |
    v
目标转速 rpm_set
    |
    v
速度外环 PID
    |
    v
目标电流 iset
    |
    v
电流内环 PID
    |
    v
PWM duty
    |
    v
FPGA PWM -> 电机
```

反馈信号：

```text
编码器 -> 实际 RPM -> 速度外环
INA240 -> 实际电流 curr -> 电流内环
```

主要运行频率：

| 功能 | 当前频率 |
|---|---:|
| TIM6 控制中断 | 1 kHz |
| 电流采样及电流内环 | 1 kHz |
| 编码器测速及速度外环 | 100 Hz |
| 串口/OLED 刷新 | 约 5 Hz |
| FPGA PWM | 约 12.2 kHz |

## 3. 阶段一：零位仍有转速、占空比和电流

### 3.1 实验现象

电位器已经转到零位，但 OLED 和串口仍出现：

```text
RPM 在 0、5、10 附近交替
duty 在 2%～10% 波动
curr 可能为负值，也可能跳到几十 mA
电机时而转动、时而停止
```

代表性数据：

```text
RPM=5.0   duty=180 (4.4%)  adc=126  curr_raw=2337  curr=8.3mA
RPM=12.0  duty=408 (10.0%) adc=138  curr_raw=2251  curr=-3.3mA
RPM=1.5   duty=449 (11.0%) adc=128  curr_raw=2855  curr=70.5mA
```

### 3.2 原因分析

最初仅使用很小的 ADC 阈值判断电位器零位，而实际电位器零点会受噪声和偏置影响。

当系统仍运行串级 PID 时：

1. 电位器噪声产生非零目标转速。
2. 编码器低速量化产生跳变。
3. 电流零点噪声进入电流 PID。
4. PID 输出小占空比，电机被反复启动。

### 3.3 下一步解决方案

设计独立的启停状态，而不是只使用单一阈值：

- `ADC >= 350`：允许启动。
- `ADC <= 250`：进入停机。
- 250～350：保持之前状态，形成滞回。

停机时同时：

- 清空速度 PID。
- 清空电流 PID。
- 将目标电流设为 0。
- 将 duty 平滑降到 0。

### 3.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

增加参数：

```c
#define MOTOR_MIN_RUN_RPM       15.0f
#define MOTOR_STOP_ADC_MAX      250U
#define MOTOR_START_ADC_MIN     350U
#define DUTY_STOP_SLEW_PER_MS   4U
```

增加启停状态：

```c
static uint8_t motor_enabled = 0U;
```

停机处理：

```c
PID_Reset(&speed_pid);
PID_Reset(&current_pid);
g_current_setpoint_mA = 0.0f;

if (duty_applied > DUTY_STOP_SLEW_PER_MS) {
    duty_applied -= DUTY_STOP_SLEW_PER_MS;
} else {
    duty_applied = 0U;
}
```

### 3.5 修改后的实验结果

零位数据稳定为：

```text
RPM=0.0  duty=0 (0.0%)  adc=14  curr_raw=2047  iset=0.0mA  curr=0.0mA
RPM=0.0  duty=0 (0.0%)  adc=14  curr_raw=2048  iset=0.0mA  curr=0.0mA
```

`curr_raw` 仅在 2047～2048 之间变化，说明静止零点稳定。

### 3.6 阶段结论

零位误启动问题已基本解决。滞回避免了电位器在临界点附近反复启停，停机时清空 PID 避免了积分残留。

## 4. 阶段二：进入死区时电机骤停、机械卡顿

### 4.1 实验现象

加入死区后，电位器进入停止区域时 duty 立即变为 0，电机突然失去扭矩，体感上有明显卡顿。

### 4.2 原因分析

“可靠停机”和“平滑停机”是两个不同要求：

- 直接清零 duty 可以保证停机。
- 但 duty 瞬间从较大值跳到 0，会造成明显的机械冲击。

### 4.3 下一步解决方案

停机时不再立刻清零实际输出，而是：

1. 目标电流立即清零。
2. PID 状态立即复位。
3. 实际 duty 每 1 ms 最多下降 4 个计数。
4. duty 最终必须到达 0，不在死区内持续驱动。

### 4.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
#define DUTY_STOP_SLEW_PER_MS 4U
```

使用 `duty_applied` 保存当前实际输出，并逐步下降。

### 4.5 修改后的实验结果

进入死区后 duty 不再瞬间归零，机械冲击减小；最终串口仍能稳定显示：

```text
RPM=0.0  duty=0 (0.0%)  iset=0.0mA  curr=0.0mA
```

### 4.6 阶段结论

当前停机逻辑兼顾了平滑性和可靠性。后续若希望停机更快或更慢，只需调整 `DUTY_STOP_SLEW_PER_MS`。

## 5. 阶段三：电流值随机跳动

### 5.1 实验现象

电位器保持不动时，电流仍出现大幅变化：

```text
curr_raw=1966～3080
curr=3mA～108mA
```

而 RPM、ADC 和 duty 的变化没有与电流跳动形成稳定关系。

### 5.2 原因分析

FPGA PWM 频率约为 12.2 kHz，一个周期约 82 us。

如果每次只读取一个 ADC 点，采样可能随机落在：

- PWM 导通阶段
- 续流阶段
- 关断阶段

因此单点值不是稳定的平均电流，而是 PWM 波形某个随机相位的瞬时值。这属于异步采样混叠。

另一个问题是 PA0 电位器和 PA1 电流共用 ADC1。切换 ADC 通道后，内部采样电容可能保留上一个通道的电压。

### 5.3 下一步解决方案

分两步处理：

1. ADC 通道切换后，先做一次转换并丢弃。
2. 每次电流测量连续采样 192 点并取平均，使采样覆盖多个 PWM 周期。

### 5.4 代码修改

文件：`MDK-ARM/Src/adc_reg.c`

通道切换后丢弃第一次转换：

```c
if (ch != last_ch) {
    ADC1->CR2 |= ADC_CR2_SWSTART;
    while ((ADC1->SR & ADC_SR_EOC) == 0U) {
    }
    (void)ADC1->DR;
    last_ch = ch;
}
```

电流突发采样：

```c
#define ADC_CURR_BURST_SAMPLES 192U

for (i = 0U; i < ADC_CURR_BURST_SAMPLES; i++) {
    raw_sum += ADC1_ReadChannel(1U);
}
raw_avg = (float)raw_sum / ADC_CURR_BURST_SAMPLES;
```

192 点约覆盖 4.5 个 PWM 周期。

### 5.5 修改后的实验结果

中高速运行时 `curr` 仍存在纹波，但变化开始有范围，不再完全随机。例如稳定高速时：

```text
RPM=98.8～99.8
duty=60.7%～61.6%
curr 约 49mA～62mA
```

### 5.6 阶段结论

突发平均显著改善了电流显示，但它仍不是严格的 PWM 同步电流采样。

后续更好的方案是由 PWM 定时点触发 ADC，在固定 PWM 相位采样。

## 6. 阶段四：电流零点不准和自动校零

### 6.1 实验现象

最初使用固定零点电压换算电流，不同上电过程可能出现：

```text
duty=0，curr=27mA
duty=0，curr=73mA
```

### 6.2 原因分析

INA240 的 REF、电源误差、ADC 参考电压和器件偏置都会使实际零点偏离理论值。

固定使用 `1650mV` 或某次人工测得的值，无法适应每次上电的真实偏置。

### 6.3 下一步解决方案

上电时先确保 FPGA duty 为 0，等待模拟电路稳定，再采集 64 个零电流样本作为本次启动的零点。

### 6.4 代码修改

文件：`Core/Src/main.c`

```c
FPGA_CS_LOW();
SPI2_ReadWriteByte(0U);
SPI2_ReadWriteByte(0U);
FPGA_CS_HIGH();
HAL_Delay(100);
ADC1_CalibrateCurrentZero();
```

文件：`MDK-ARM/Src/adc_reg.c`

```c
for (i = 0U; i < ADC_CURR_ZERO_SAMPLES; i++) {
    zero_sum += ADC1_ReadChannel(1U);
}
s_current_zero_raw = (float)zero_sum / ADC_CURR_ZERO_SAMPLES;
```

### 6.5 曾尝试但撤销的方案

曾尝试在运行过程中检测 duty 为 0 后自动重新校零。

该方案被撤销，原因是：

- duty 已经为 0 时，电机可能仍在惯性旋转。
- 电机反电动势或续流电流仍可能存在。
- 此时校准会把非零电流误当作零点。
- 后续可能出现虚假的 100mA 以上偏置。

因此当前只在确认停机的上电初始化阶段校零。

### 6.6 修改后的实验结果

稳定静止时：

```text
curr_raw=2047～2048
curr=0.0mA
```

### 6.7 阶段结论

静态零点已经稳定。当前高速电流纹波主要不是零点漂移，而是 PWM 电流波形、采样相位和电流换算标定共同造成。

## 7. 阶段五：低速 RPM 跳变和电机一顿一顿

### 7.1 实验现象

最初每 1 ms 计算一次编码器速度，低速时 RPM 以较大台阶变化，速度 PID 输出随之快速变化，电机出现类似周期性加速和减速的顿挫。

### 7.2 原因分析

编码器输出轴每转计数：

```text
11 PPR * 4 倍频 * 34 减速比 = 1496 counts/rev
```

1 ms 内的计数太少。低速时常见情况是：

```text
本次 delta=0
下一次 delta=1
```

使用 1 ms 窗口换算后，一个计数对应很大的 RPM 台阶，速度反馈量化严重。

### 7.3 下一步解决方案

保持 TIM6 为 1 kHz，但把：

- 编码器测速降到 100 Hz。
- 速度外环降到 100 Hz。
- 电流内环继续保持 1 kHz。

这样速度统计窗口从 1 ms 增加到 10 ms。

### 7.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
#define SPEED_LOOP_DIVIDER 10U
```

每 10 次 TIM6 中断调用一次：

```c
Encoder_Update();
g_current_setpoint_mA =
    PID_Calc(&speed_pid, setpoint_rpm, g_encoder_rpm);
```

文件：`MDK-ARM/Src/encoder_reg.h`

```c
#define ENCODER_UPDATE_HZ 100U
```

文件：`MDK-ARM/Src/encoder_reg.c`

```c
raw_rpm = (float)g_encoder_delta
        * (60.0f * ENCODER_UPDATE_HZ)
        / ENCODER_COUNTS_PER_REV;
```

### 7.5 修改后的实验结果

RPM 最小变化约为 0.5 RPM，常见稳定数据为：

```text
98.8, 99.3, 99.8
```

而不是原先的 5 RPM 级跳变。

### 7.6 阶段结论

降低速度环频率是本次稳定性提升的重要基础。速度环不需要与电流环一样快，分层设置频率更符合串级控制结构。

## 8. 阶段六：限制 duty 变化速度

### 8.1 实验现象

电流采样纹波和速度误差会直接反映到 PID 输出，duty 快速变化，使电机产生扭矩冲击。

### 8.2 原因分析

即使 PID 输出瞬间变化很大，实际电机和机械系统也不需要在 1 ms 内完成同样大的占空比变化。

### 8.3 下一步解决方案

在 PID 目标输出与 FPGA 实际输出之间加入斜率限制：

```text
运行时每 1 ms 最多变化 2 个 duty 计数
停机时每 1 ms 最多下降 4 个 duty 计数
```

### 8.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
#define DUTY_SLEW_PER_MS      2U
#define DUTY_STOP_SLEW_PER_MS 4U
```

```c
if (duty_target > duty_applied + DUTY_SLEW_PER_MS) {
    duty_applied += DUTY_SLEW_PER_MS;
} else if (duty_target + DUTY_SLEW_PER_MS < duty_applied) {
    duty_applied -= DUTY_SLEW_PER_MS;
} else {
    duty_applied = duty_target;
}
```

### 8.5 修改后的实验结果

电机加减速过程明显平滑，duty 在高速稳态通常只在约 59%～61% 范围内缓慢变化。

### 8.6 阶段结论

duty 斜率限制有效降低了机械顿挫，但也会增加到达目标转速所需时间。后续调响应速度时，需要同时考虑速度 PID 和 duty 斜率限制。

---

## 9. 阶段七：`iset=0` 时 duty 仍保持旧值

### 9.1 实验现象

曾观察到：

```text
RPM=62.7  duty=1600  iset=0.0mA  curr=0.0mA
```

目标电流已经是 0，但 duty 长时间卡在 1600。

### 9.2 原因分析

电流 PID 使用位置式 PID。

电流负值被限制为 0 后，当：

```text
iset=0
curr=0
```

误差也是 0。此时电流 PID 中以前积累的积分不会自动消退，因此输出仍保持旧 duty。

### 9.3 下一步解决方案

当目标电流小于等于 0 时：

1. 复位电流 PID。
2. 直接令 duty 目标为 0。
3. 实际 duty 仍通过斜率限制平滑下降。

### 9.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

```c
if (g_current_setpoint_mA <= 0.0f) {
    PID_Reset(&current_pid);
    duty_target = 0U;
} else {
    duty_target = (uint16_t)PID_Calc(
        &current_pid,
        g_current_setpoint_mA,
        measured_current);
}
```

### 9.5 修改后的实验结果

目标电流变为 0 后，duty 不再永久保持旧值，而会逐步下降。

### 9.6 阶段结论

该问题属于 PID 状态管理问题，不是 PID 参数问题。切换运行状态时必须明确处理积分状态。

---

## 10. 阶段八：增加可观测量

### 10.1 实验现象

最初串口只显示：

```text
RPM、duty、adc、curr_raw、curr
```

只能看到实测电流，无法判断电流内环到底在追踪什么目标。

### 10.2 原因分析

串级 PID 调试至少需要同时观察：

```text
目标转速
实际转速
目标电流 iset
实际电流 curr
duty
```

没有 `iset` 时，无法区分：

- 速度外环输出本身在跳。
- 电流内环没有跟随目标。

### 10.3 下一步解决方案

将速度 PID 输出导出为全局监控变量，并加入串口日志。

### 10.4 代码修改

文件：`Core/Inc/stm32f4xx_it.h`

```c
extern volatile float g_current_setpoint_mA;
```

文件：`Core/Src/stm32f4xx_it.c`

```c
volatile float g_current_setpoint_mA = 0.0f;
```

文件：`Core/Src/main.c`

```text
RPM=... duty=... adc=... curr_raw=... iset=...mA curr=...mA
```

同时主循环不再直接读取 ADC1 电流通道，而是读取中断已经采集好的 `g_motor_current_raw`，避免主循环与控制中断竞争 ADC。

### 10.5 修改后的实验结果

加入 `iset` 后，很快发现速度外环输出曾在：

```text
0mA～292mA
```

之间周期变化，从而确认主要振荡来源是速度外环，而不是电位器。

### 10.6 阶段结论

增加监控量是本次排障的关键步骤。控制系统调试不能只看最终 duty，必须观察每一层控制器的输入和输出。

---

## 11. 阶段九：速度外环严重振荡

### 11.1 实验现象

电位器固定在中档，ADC 基本稳定：

```text
adc=1886～1892
```

但实际数据为：

```text
RPM=46～58
iset=0～277mA
duty=29%～39%
```

电机转速在目标值两侧周期性来回变化。

### 11.2 原因分析

串口 `show` 最终发现实际运行参数为：

```text
speed kp=33.0
speed ki=0.1
```

Flash 中保存的旧参数覆盖了代码默认值。

`kp=33` 会把很小的 RPM 误差放大成很大的电流目标变化，使 `iset` 快速到达 0 或 400mA，形成明显振荡。

### 11.3 下一步解决方案

分阶段降低速度环参数：

| 阶段 | Kp | Ki | 结果 |
|---|---:|---:|---|
| Flash 旧参数 | 33.0 | 0.1 | 严重振荡 |
| 第一次保守调整 | 0.8 | 0.02 | 仍有低频摆动 |
| 第二次保守调整 | 0.4 | 0.005 | 稳定，但到达目标较慢 |
| 当前折中参数 | 0.8 | 0.01 | 响应较快且无明显振荡 |

### 11.4 代码修改

文件：`Core/Src/stm32f4xx_it.c`

当前默认值：

```c
PID_Init(&speed_pid,
         0.8f, 0.01f, 0.0f,
         0.0f, MOTOR_MAX_CURRENT_MA,
         40000.0f);
```

串口在线调参命令：

```text
set sp 0.8
set si 0.01
show
save
```

### 11.5 `0.4 / 0.005` 的实验结果

优点：

- 转速单调、平滑地接近目标。
- 没有周期振荡。

缺点：

- 从约 86 RPM 上升到 99 RPM 用时较长。
- `iset` 积分上升较慢。

最终稳定数据：

```text
RPM=98.8～99.8
duty≈61%
```

### 11.6 `0.8 / 0.01` 的实验结果

代表性数据：

```text
RPM=96.3  duty=59.6%  iset=222.8mA
RPM=97.3  duty=60.0%  iset=229.1mA
RPM=98.3  duty=60.7%  iset=231.1mA
RPM=99.3  duty=60.7%  iset=235.4mA
```

结果：

- RPM 平稳接近 100。
- 没有重新出现明显周期振荡。
- duty 稳定在约 59.5%～60.9%。
- 比 `0.4 / 0.005` 更快。

### 11.7 阶段结论

当前推荐速度 PID：

```text
Kp = 0.8
Ki = 0.01
Kd = 0
```

需要通过 `save` 写入 Flash，并在重新上电后使用 `show` 确认加载值。

## 12. 阶段十：串口在线调参失败

### 12.1 实验现象

发送：

```text
set sp 0.4
set si 0.005
show
```

系统反复返回：

```text
[PID] unknown cmd
```

但 `show` 可以识别。

### 12.2 第一层原因：浮点解析

原代码使用：

```c
sscanf(cmd, "set sp %f", &val);
```

Keil 当前 C 库配置可能没有启用 `scanf` 浮点支持，因此整数命令可以工作，带浮点参数的命令解析失败。

### 12.3 第一层解决方案

在 `Core/Src/main.c` 中增加轻量小数解析函数 `parse_float_arg()`，不再依赖 `sscanf("%f")`。

修改参数后同时调用：

```c
PID_Reset(&speed_pid);
```

避免新参数继续继承旧参数留下的积分。

### 12.4 第二层原因：接收字符丢失

加入失败回显后，发送：

```text
set sp 0.4
```

MCU 实际收到：

```text
s 0.4
```

说明命令前面的字符丢失。

原 UART 只轮询 USART2 的单字节接收寄存器。主循环发送长日志或 TIM6 执行较长 ADC 采样时，新的串口字符来不及读取，产生 ORE 溢出。

### 12.5 第二层解决方案

文件：`MDK-ARM/Src/uart.c`

增加 64 字节环形缓冲区：

```c
#define UART_RX_BUFFER_SIZE 64U
```

开启 USART2 RXNE 中断：

```c
USART2->CR1 =
    USART_CR1_TE |
    USART_CR1_RE |
    USART_CR1_RXNEIE |
    USART_CR1_UE;
```

USART2 ISR 将字节放入缓冲区，主循环通过 `UART_RecvChar()` 取出。

### 12.6 第三层原因：中断优先级

最初 USART2 中断优先级为 3，TIM6 为 2。

TIM6 可以阻塞 USART2，而 TIM6 内包含 192 点 ADC 采样，执行时间较长，仍可能造成串口接收丢字符。

### 12.7 第三层解决方案

提高 USART2 中断优先级：

```c
NVIC_SetPriority(USART2_IRQn, 1U);
```

当前优先级：

```text
USART2 = 1
TIM6   = 2
```

USART2 可以抢占 TIM6，及时保存收到的字节。

### 12.8 修改后的实验结果

命令成功执行：

```text
speed:   kp=0.4000 ki=0.0050 kd=0.0000
current: kp=5.0000 ki=0.2000 kd=0.0000
```

随后可以继续在线切换到：

```text
speed: kp=0.8000 ki=0.0100 kd=0.0000
```

### 12.9 阶段结论

串口命令问题由多个因素叠加造成：

1. `%f` 浮点解析不可靠。
2. 轮询接收容易丢字节。
3. USART2 中断优先级低于长时间控制中断。

当前三项均已处理。

## 19. 工程化改造（第一阶段）：显式状态机 + 统一遥测快照

> 参考生产级电机固件（ODrive / SimpleFOC / MESC）的工程结构，对控制环做不改变行为的结构化重构。本阶段不调任何 PID 参数，目标是把散落的隐含状态收敛成可维护、可观测、可扩展的形态，为后续故障锁存、参数校验打基础。

### 19.1 改造动机

1kHz 控制环（`TIM6_DAC_IRQHandler`）原本用一个 `motor_enabled` 标志加多处 `if` 表达"零位 / 启动 / 运行 / 平滑停止"等隐含状态，存在两个问题：

- **状态散落**：启停滞回、PID 复位时机、duty 升降、iset=0 处理分布在不同分支，新增"故障停机"这类状态时无清晰落点。
- **监控字段不同步**：主循环分别读取 `g_pid_duty`、`g_encoder_rpm`、`g_motor_current_mA`、`g_adc_val`、`g_current_setpoint_mA`，这些量来自不同控制周期，打印出来的一行可能是几个时刻的拼凑，调试时容易误判。

### 19.2 解决方案

新增头文件 `MDK-ARM/Src/motor_fsm.h`（纯头文件，不新增 .c，无需改 Keil 工程文件）：

- 定义 6 态枚举 `MotorState`：`INIT / IDLE / STARTING / RUNNING / STOPPING / FAULT`
- 定义统一遥测结构 `MotorTelemetry`（state / rpm_set / rpm / current_set_mA / current_mA / duty / pot_adc / current_raw / faults）；其中 `current_raw` 为电流通道原始 ADC，纳入快照以保证整行字段同周期一致
- 预留故障位 `MOTOR_FAULT_OVERCURRENT / STALL / ENCODER`（本阶段恒为 0，第三阶段填触发条件）
- 提供 `Motor_GetTelemetry()`：拷贝期间临时关闭 TIM6 中断、原子读取整组快照杜绝"撕裂"；并**保存/恢复 TIM6 原使能状态**，避免在 TIM6 本就关闭时被本函数意外打开

状态迁移图：

```text
INIT ──▶ IDLE ──▶ STARTING ──▶ RUNNING
           ▲          │             │
           │          ▼             ▼
           └──────── STOPPING ◀─────┘

任意状态 ──▶ FAULT （第三阶段实现）
```

### 19.3 代码修改

ISR 改成 **Mealy 结构**：先按输入做状态迁移，再按当前状态执行动作。迁移规则严格映射原有逻辑，行为完全等价：

| 原隐含逻辑 | 对应状态/迁移 |
|------------|---------------|
| `motor_enabled` 0→1（adc≥350） | `IDLE → STARTING` |
| `motor_enabled` 1→0（adc≤250） | `RUNNING/STARTING → STOPPING` |
| 禁用分支 duty 平滑降到 0 | `STOPPING` 动作，降到 0 且转轴停稳后 `→ IDLE` |
| 使能分支串级 PID + 升斜率 | `STARTING / RUNNING` 动作（两态动作相同） |
| 转速达到 `MIN_RUN_RPM` | `STARTING → RUNNING`（单向，不回退，避免标签抖动） |

为保证"无额外死拍"，`MOTOR_INIT → IDLE` 不在 ISR 首拍完成，而是在 `Motor_Control_Init()` 末尾显式置位：`MOTOR_INIT` 仅代表 TIM6 启动前的上电态，TIM6 一旦运行，第一拍即可根据 adc 直接进入 `STARTING`，与改造前完全一致。

ISR 末尾一次性写入 `g_motor_telemetry`（含 `current_raw`），保证整组字段同周期一致。主循环改用 `Motor_GetTelemetry()` 取快照，串口打印 `set / RPM / duty / adc / raw / iset / curr` 全部来自同一周期，并显示状态名。

涉及文件：

| 文件 | 改动 |
|------|------|
| `MDK-ARM/Src/motor_fsm.h` | 新增：状态枚举、遥测结构、状态名、原子读取 |
| `Core/Src/stm32f4xx_it.c` | ISR 重构为双 switch 状态机，末尾写遥测快照 |
| `Core/Src/main.c` | 监控打印改用遥测快照，串口/OLED 加状态名 |

### 19.4 预期实验结果（待硬件验证）

- 行为应与改造前**完全一致**（启停阈值、duty 斜率、停机清零、上电首拍响应均未变），作为无回归基线
- 串口每行带状态标签，例如：`[RUN  ] set=99.0 RPM=99.0 duty=2480 (60.6%) adc=4000 raw=... iset=... curr=...`；旋钮归零时应看到 `[STOP ] → [IDLE ]` 的迁移
- 同一行内 set / RPM / duty / adc / raw / 电流来自同一控制周期，不再出现跨周期拼凑

### 19.5 阶段结论

控制行为保持不变，但状态表达从"标志 + 散落 if"升级为显式状态机，监控数据从"多变量拼凑"升级为"原子快照"。后续三个阶段（故障锁存 → 参数 CRC → PWM 同步采样）都可在此结构上独立增量实现、独立测试、独立提交。

## 20. 低速启动超调与启动防超调（START 阶段积分管理）

> 本节是状态机改造（§19）后第一个利用 `STARTING` 状态做的实质控制改进。借助遥测快照逐拍数据，定位并修复了低速启动的大幅超调。

### 20.1 实验现象

测试数据 `report/测试数据/t2.md`：电位器固定在 adc≈895（对应目标 ≈27.4 RPM）启动，逐拍记录如下要点：

```text
START 阶段（RPM 恒为 0）：iset 从 1.4mA 逐步累加到 96.3mA，curr 紧随 iset
击穿瞬间：RPM 1.5 → 35.6 → 63.7 → 66.2（冲过头）
回落：66.2 → 13.5（跌破目标）
再回升并逐步收敛到 ~27.4
```

超调率：`(66.2 − 27.4) / 27.4 ≈ 142%`。该测试证明超调是真实控制行为，而非电位器移动造成的假象（adc 全程稳定在 ~895）。

### 20.2 原因分析

- START 阶段电机受静摩擦长时间堵转，RPM=0，速度外环每 10ms 累加误差 27.4。
- 此时 iset（峰值 ~96mA）**远未达到速度环 out_max=400mA**，PID 自带的"输出饱和 anti-windup"不触发，积分自由膨胀至约 7400（由 `ki·integral = 96 − 0.8×27.4` 反推）。
- 电机靠这份高 iset 才挣脱静摩擦；一旦转动，巨大残余积分继续维持高 iset，叠加机械惯性 → RPM 冲过目标，需负误差缓慢泄积分才回落。
- 在电机尚未转动的堵转蓄能阶段，curr 基本紧随 iset，主要矛盾是**速度环启动阶段的积分蓄能**；电机转动后的电流动态仍需单独验证。

### 20.3 解决方案

利用状态机已区分的 `STARTING` 状态，对启动阶段施加三道针对性限制（其余状态不受影响）：

| 措施 | 参数 | 默认值 | 作用 |
|------|------|--------|------|
| ①限 START 最大 iset | `SPEED_START_ISET_MAX` | 110 mA | **主限制**（单位 mA，与 ki 无关）：限制击穿静摩擦时注入的能量（>实测击穿所需 ~96mA 留裕量） |
| ②未达运行转速时夹住速度积分 | `SPEED_START_INTEGRAL_MAX` | 8000 → **11000** | **第二层安全闸**：防积分无限膨胀。注意其实际 mA 效果 = ki×积分钳，会随在线调 ki 漂移，故须足够高让 ① 成为主闸（见 20.5b） |
| ③START→RUN 交接泄积分 | `SPEED_HANDOFF_KEEP` | 0.4 | 击穿瞬间泄掉 60% 启动蓄能，避免整体带入 RUN 冲过头 |

### 20.4 代码修改

| 文件 | 改动 |
|------|------|
| `Core/Src/stm32f4xx_it.c` PD 段 | 新增三个启动防超调参数定义 |
| `Core/Src/stm32f4xx_it.c` 迁移 switch | `STARTING→RUNNING` 时 `speed_pid.integral *= SPEED_HANDOFF_KEEP` |
| `Core/Src/stm32f4xx_it.c` 动作 switch | 仅 `MOTOR_STARTING` 态：夹住 `speed_pid.integral`、限制 `g_current_setpoint_mA` 上限 |

构建：Keil armclang V6.24，`0 Error(s), 0 Warning(s)`，Code 19060→19148B。

### 20.4b 后续踩坑：积分钳把高档位启动卡死（8000 → 11000）

更高目标（45 RPM，adc≈1680）从静止启动时出现**堵转停机**：iset/curr 稳定卡在 ~84mA、duty ~7%、RPM=0，电机始终挣脱不了静摩擦。

排查关键：误以为 `out_max=84` 或固件版本错。实际原因——速度环 **kp/ki 是上电从 Flash 加载的运行值**，`show` 打印为 `kp=0.08、ki=0.01`（kp 已被在线调小，非源码的 0.8）。代入：

```text
iset = kp×err + ki×SPEED_START_INTEGRAL_MAX
     = 0.08×45.2 + 0.01×8000 ≈ 83.6mA   ← 与实测 84.1 吻合
```

即 iset 被**积分钳(8000)**摁死在 84mA（< 挣脱所需 ~96mA），而 `SPEED_START_ISET_MAX=110` 因 84<110 **从未触发**。教训：

- 启动电流的实际上限由「积分钳×ki」与「ISET_MAX」中**先到者**决定；积分钳的 mA 效果随 ki 漂移，单位含糊。
- 应让积分钳足够高，使**单位明确的 ISET_MAX 成为主闸**，积分钳只兜底防膨胀。

修复：`SPEED_START_INTEGRAL_MAX` 8000 → **11000**。此时 45RPM 堵转 iset = 0.08×45.2+0.01×11000 ≈ 113.6 → 由 ISET_MAX(110) 接管。构建 `0 Error/0 Warning`。

> 待办：START 堵转超时保护——若 START 持续 >3s 且 RPM≈0，进 `FAULT` 锁存、停止通电（接 §19 留空的 FAULT 入口）。

### 20.5 第一次上板结果（t21）

测试数据：`report/测试数据/t21.md`。

本次从零位逐步调到约 21.7 RPM，最终 adc≈645。电机在 `STARTING` 阶段可靠启动，未触发 110mA 电流给定上限：

```text
START 末段：RPM=2.0，iset=73.8mA，duty=338
进入 RUN：RPM=32.6，iset=28.1mA，duty=1029
峰值：RPM=36.1
随后：30.1 → 23.6 → 18.5 → 16.0 → 16.5 → 18.0 → 20.1 → 22.6
```

`STARTING→RUNNING` 后 iset 从 73.8mA 降至 28.1mA，说明 `SPEED_HANDOFF_KEEP=0.4` 的交接泄积分已经生效。按最终目标 21.7 RPM 粗略计算，本次峰值超调率为：

```text
(36.1 - 21.7) / 21.7 ≈ 66%
```

相较 t2 的约 142% 超调，峰值明显下降，且启动可靠。但进入 RUN 后仍出现 36.1→16.0 RPM 的一次欠调，说明启动能量和交接后的控制量仍需继续平衡。

需要注意：本次并非严格的 t2 对照实验。t2 固定在 adc≈895、目标约 27.4 RPM，而 t21 启动过程中 adc 从 380 增加到约 645、最终目标约 21.7 RPM。因此只能确认改动方向有效，不能把 142%→66% 作为严格的同工况改善比例。

## 21. 启动防超调（第二步）：电流环 + 执行器交接

> §20 只处理了速度环积分。t22/t23 进一步实测表明：超调严重程度与"击穿时的蓄能"强相关，而蓄能不止存在速度环，还困在电流环积分与已蓄 duty 里。本节补上这部分交接。

### 21.1 实测规律：超调 ∝ 击穿蓄能

三组实测把规律坐实（注意三者工况不同，仅用于看趋势，非严格对照）：

| 测试 | 击穿时 iset | 给定方式 | 峰值/目标 | 粗略超调 |
|------|-----------|----------|-----------|----------|
| t2   | ~96 mA    | 快速到位并保持 | 66.2 / 27.4 | ~142% |
| t23  | ~82 mA    | 较快拧高（目标 ~30） | 44.1 / 30 | ~47% |
| t21  | ~74 mA    | 半渐进（目标 ~21.7） | 36.1 / 21.7 | ~66% |
| t22  | ~54 mA    | 全程渐进拧高 | 28.6 / 28.1 | ~1.8% |

渐进拧旋钮本身相当于"人肉 setpoint ramp"，使误差小、击穿轻柔（t22 仅 54mA 即挣脱）→ 几乎无超调；而静摩擦较大、卡到高 iset 才挣脱时（t23 的 82mA），超调显著回升。

### 21.2 原因分析：残余超调在 duty/电流环

t23 交接前后关键数据：

```text
行26 [START] iset=82.4 duty= 273   ← 卡到 82mA 才挣脱
行27 [RUN  ] iset=33.2 duty= 766   ← ③已把 iset 砍低(82.4×0.4≈33)，但 duty 已蹿高
行28 [RUN  ] iset=28.7 duty=1182   ← iset 仅 28，duty 却冲到 1182 → RPM 顶到 44.1
```

iset 已被 ③ 砍到 28mA，duty 却仍冲到 1182。原因：`duty_target = kp·(iset−curr) + ki·current_pid.integral`，电流环积分在击穿那几十毫秒（curr 因反电动势骤降、curr<iset）被顶高，即便 iset 砍低，积分项仍维持高 duty_target；叠加 duty 只能按 2/ms 下行斜率回落 → 启动能量被困在电流环积分与已蓄 duty 里。速度环的 ③ 管不到这部分。

### 21.3 解决方案

在 `STARTING→RUNNING` 交接同一拍，除 ③ 外再泄掉电流环侧能量：

| 措施 | 参数 | 默认值 | 作用 |
|------|------|--------|------|
| ④泄电流环积分 | `CURRENT_HANDOFF_KEEP` | 0.4 | 砍掉击穿期间冲起的电流环积分 |
| ⑤泄已蓄 duty | `DUTY_HANDOFF_KEEP` | 0.6 | 释放被 2/ms 下行斜率困住的执行器能量，让 RUN 从更低基线起步 |

### 21.4 代码修改

| 文件 | 改动 |
|------|------|
| `Core/Src/stm32f4xx_it.c` PD 段 | 新增 `CURRENT_HANDOFF_KEEP` / `DUTY_HANDOFF_KEEP` |
| `Core/Src/stm32f4xx_it.c` 迁移 switch | `STARTING→RUNNING` 时追加 `current_pid.integral *= CURRENT_HANDOFF_KEEP`、`duty_applied *= DUTY_HANDOFF_KEEP` |

构建：Keil armclang V6.24，`0 Error(s), 0 Warning(s)`。

### 21.5 预期实验结果（待硬件验证）

- 对 t23 类强力击穿工况，交接后 duty 不应再冲到 ~1182，峰值 RPM 应明显下降。
- 风险：若 ④⑤ 泄得过猛，击穿后可能瞬时掉扭矩、出现欠调或转速回坠。判读规则：
  - 仍超调 → 同时下调 `CURRENT_HANDOFF_KEEP`、`DUTY_HANDOFF_KEEP`
  - 击穿后掉速/卡顿 → 上调二者（保留更多能量）
- 仍需 §20.6 的固定 adc≈895 / 27.4 RPM 阶跃工况做正式对照。

## 22. 给定斜率限幅（setpoint ramp）

> §20/§21 的 ①~⑤ 都是在"击穿那一刻/那一拍"做能量管理，属于事后补救。本节从源头入手：把电位器的阶跃目标整形为平缓爬坡，让任何快速旋钮动作都接近 t22 的"缓慢拧"工况。

### 22.1 动机

`INTEGRAL_MAX` 抬到 11000 后高档位能可靠启动，但快速拧旋钮到高档时观察到剧烈摆动（RPM 在 0 与 60+ 间反复、中途一度 RPM=0）。注意该组数据 `set` 仍在移动（26.9→34.6 RPM），**尚不能确认是稳定极限环**，需固定电位器后复测确认。

机理上，t22"缓慢拧旋钮"几乎零过冲，本质是目标渐进上升、误差小、挣脱轻柔。因此对 `setpoint_rpm` 加软件斜率限幅，可把快速旋钮动作整形为平缓爬坡，从源头减小给定突变。

### 22.2 实现要点

| 项 | 说明 |
|----|------|
| 速率 | `SETPOINT_SLEW_RPM_PER_STEP = 0.1 RPM/速度环周期`，速度环 100Hz → ~10 RPM/s |
| 升降 | 升、降均限速 |
| 位置 | **必须在 `MOTOR_MIN_RUN_RPM` 钳位之后**对"钳位后的目标"爬坡；喂给 PID 的是 `setpoint_ramped`，不再二次钳位，否则会被 MIN_RUN 直接跳到 ~15 RPM |
| 复位 | IDLE/STOPPING 时 `setpoint_ramped = max(0, 实测RPM)`，使减速途中再启动从当前转速续接 |
| 日志 | 新增 `set`（钳位后电位器目标=爬坡终点）与 `setR`（实际喂 PID 的爬坡值）两列，区分二者 |

③④⑤ 与 `iset<=0 → 复位电流环并降 duty` 的安全逻辑**本轮均保留不动**，以便单独验证 ramp 的独立效果。

### 22.3 代码修改

| 文件 | 改动 |
|------|------|
| `Core/Src/stm32f4xx_it.c` PD 段 | 新增 `SETPOINT_SLEW_RPM_PER_STEP` |
| `Core/Src/stm32f4xx_it.c` ISR | 新增 `static float setpoint_ramped`；MIN_RUN 钳位后做斜率限幅；IDLE/STOPPING 复位为实测 RPM；遥测加 `rpm_set_ramped` |
| `MDK-ARM/Src/motor_fsm.h` | `MotorTelemetry` 加 `rpm_set_ramped` |
| `Core/Src/main.c` | 串口打印加 `setR` 列 |

构建：Keil armclang V6.24，`0 Error(s), 0 Warning(s)`。

### 22.4 验证方法

- **快速**把电位器拧到固定位置后**完全不动**，观察日志：`set` 应立即到位，`setR` 应以 ~10 RPM/s 平缓追上。
- 若 `set` 固定后 `RPM` 仍反复 `60→0→60`，才能确认存在真正的极限环（届时再考虑是否需要处理 RUN 内的二次膨胀）。
- 对比有/无 ramp 的启动峰值 RPM 与是否还会中途停转。
- 调参：先用 0.1（10 RPM/s）；过冲仍大可调小（更缓），启动太慢可调大。

### 22.5 首次上板观察

> 注意措辞：以下为有限次、5Hz 采样下的**观察**，非定论；5Hz 日志相邻点间隔约 200ms，不足以刻画 200ms 内的转速细节。

**功能验证通过：**
- `setR` 确实按约 10 RPM/s 变化；升、降均限速（实测电位器从 42 快速拧回时 `setR` 仍按速率缓降：`set=25→setR=38.7`、`set=17→setR=29.3`）。
- IDLE/STOPPING 的 `setR` 复位、再启动从低值续接均正常。

**固定低档（adc≈554，target≈19.6）：**
- 未观察到持续的 `60→0→60` 摆动；跳到 ~22 后在 19.6 附近收敛（17~26）。因此**此前"边拧边测"时的乱象不能认定为固定目标下的极限环**。
- 静摩擦挣脱伴随明显速度跃升（日志上 `RPM=0 → 22.6`）。但受 5Hz 采样限制，**不能断言瞬间从 0 跳到 22**，电机可能在 200ms 内经过 5/10/15 RPM 未被采到；也**不能断言该电机绝对无法运行在 5~10 RPM**。可严谨表述为：**在当前负载与控制参数下，15 RPM 以下难以稳定运行**。

**观察到的副作用——低档启动偏慢：**
- 低目标误差小、积分增长慢，挣脱所需时间约 `8000/(19.6×100Hz) ≈ 4.1s`；实测低档 START 持续约 5s 才挣脱。高目标误差大、挣脱明显更快。即**启动时间强依赖目标 RPM**。

### 22.5b 重复启动量化（report/测试数据/196and45.md）

8 次启动尝试（7 次有效 + 1 次中途人为拧回 0 的中止），5Hz 采样下估读：

| 目标档 | 挣脱 iset | 峰值 RPM | 过冲 | 收敛 |
|--------|-----------|----------|------|------|
| ~20（固定） | 94 mA | 30.1 | ~47% | →20 ✓ |
| ~20（固定） | 80 mA | 22.6 | ~9%  | →21 ✓ |
| ~20（固定） | 89 mA | 25.1 | ~22% | →20 ✓ |
| ~46（上拧） | 83 mA | 55.6 | ~18% | →47 ✓ |
| ~46（上拧） | 83 mA | 56.7 | ~21% | →47 ✓ |
| ~46（上拧） | 62 mA | 55.6 | ~21% | →46 ✓ |
| ~47（上拧） | 90 mA | 57.7 | ~23% | →47 ✓ |

观察：
- 有效启动全部成功，固定目标后无持续极限环、无中途停转。
- 挣脱电流离散明显（62~94mA），静摩擦逐次不同 → 20 档过冲离散（9~47%），45 档较一致（18~23%）。
- 两个残留同根：堵转期间速度积分要慢慢 winds 到"挣脱电流"，这份蓄能既使低档启动慢、又在释放时造成过冲；③④⑤ 只在交接泄一次（×0.4），压不到 0。

**结论：ramp 显著提高了启动重复性与稳定性**（消除了边拧边测时的乱象），但**未彻底解决**挣脱过冲（~20%）与低档启动慢（~4-5s）。

### 22.6 下一阶段方案：START 启动电流斜坡 + 早挣脱检测 + 无扰交接

> 关键认识（数据修正）：iset 斜坡只让启动**与目标解耦、可预测**，不会自动同时更快且过冲更小——升流越快、挣脱越猛、过冲风险越高，是取舍。真正治过冲的另一半是**更早地判定挣脱并立即交给 RUN**（当前 `RPM≥15` 才交接，③④⑤ 释放偏晚）。

设计（待实现）：

1. **START 电流斜坡**：进入 START 后 `iset` 按固定速率上升，初始 **30mA/s**（非 20mA/s），上限保留 `SPEED_START_ISET_MAX=110mA`。启动过程与目标 RPM 解耦、可预测。
2. **独立挣脱检测**：`RPM > 3` 连续 3 个速度周期 → 立即 `STARTING→RUNNING`（不再等 15 RPM），使 RUN 更早介入、更早回收能量。
3. **无扰交接（反算速度积分）**：交接时令 `speed_pid.integral = (当前iset − kp×当前速度误差) / ki`，使 RUN 接管瞬间速度环输出 ≈ 交接前电流，无跳变。此项**取代** ③（及 ④⑤）的"泄能"式交接。
4. 保留 `110mA` 启动电流上限。
5. 增加约 **6s 启动超时 → FAULT**（堵转保护，阈值 > 斜坡到 110mA 的 ~3.7s + 余量；旋钮回零清故障）；接 §19 留空的 `FAULT` 入口。
